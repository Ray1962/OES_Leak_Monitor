6. 判定策略:Golden Run 為主,step 為輔

6.1 為什麼不能只靠 step 判定

滾動基準的歷史在每次電漿熄滅時會清空(閒置寬限只有 1.5 s,而兩段之間有約 10 s 無電漿)。所以:

  • 它只看得到「在同一段製程中途才開始」的漏氣。開段前就存在的漏氣,會被算進參考值裡,永遠看不到。 生產中的漏氣通常從上一片就已經存在。
  • 短段(約 35 s 的電漿)扣掉 warm-up 之後幾乎沒有可判定的時間。

所以 step 判定只能補抓「段內突然開始漏」的情況。主判必須是 Golden Run,它比較的是跨 run 的絕對比值。

6.2 Golden Run 怎麼抓

  1. 先不要現在就抓一個長期使用的 GR。含氮指標還在下降(§4.3)。用現在的 GR,之後讀值會一路低於基準, 要漏到把這段差距補回來才會報警,靈敏度會打折。
  2. 腔體穩定前,用單筆最新的長段 run 建臨時 GR(Baseline Builder,流程 A 單檔, baseline-builder-sop-zh-TW.md §7)。好讓 Alarm 路徑有東西可比,也讓 % 顯示有意義。
    • 不能跨檔合併。 Baseline Builder 會拒收 mean/σ 低於 10 的比值。App 實測(2026-11-24): 4 次長段合併時,一致性檢查先擱置了 2 筆(含最新的 P_OES1_1123155536),剩下 2 筆裡 N₂ 337 / Ar 750 仍然被拒(0.0063 ± 0.00069),CN 388 / Ar 750 只以 14.3 勉強通過。 原因是含氮指標在 run 之間一路下降,把合併後的 σ 拉大了。 單筆最新 run 則是 N₂ 337 / Ar 750 18.1、CN 388 / Ar 750 27.2(各 62 幀),都能通過。
    • 視窗:點火後約 5 s 到結束前約 14 s(避開最後碳源關掉的過渡段)。 一筆長段約 63 幀,剛好過 60 幀的門檻,不要再縮短。
    • 只建 P1_Ar。 短段一筆只有約 25 幀,不夠 60 幀;P2_NoAr 的比值全是 TrendOnly, 沒有基準不影響警報(結果面板列在 No baseline for: 是正常的)。
    • 單筆 GR 的 σ 只有幀間雜訊,比 run 間差異窄。 能擋住 run 間差異造成誤報的是 §5.2 的倍率門檻 1.20 / 1.30,不要因為 σ 很小就把倍率調緊。
    • 量測步驟與預期結果見 remeasure-sop-20261123-zh-TW.md A6。
  3. 用 Batch Trend 追 NO / Ar、N₂ / Ar 的批次值。連續 5 批以上不再下降(批次間差 < 5 %), 就可以改用跨檔合併重建 GR(合併後兩個 Alarm 比值都要過 mean/σ 10), 並依實際 run 間 CV 重定 §5.2 的門檻。在那之前,每週用當時最新的單筆 run 重建一次臨時 GR。
  4. 之後每次 PM 或破真空回機,都重複 2–3。

批次層取樣點固定在「每類第一段完整製程的閘門開啟後 10–30 s」(batch-layer.md)。 這兩段的穩態從點火後約 5 s 開始,10–30 s 落在穩態內,不用改。

7. 回問客戶清單

  1. 製程 2 的氣體:光譜顯示有大量氧(O 777、O 844、CO、OH),不可能只有 C₂H₂。 實際上還通了什麼(O₂、CO₂、N₂O)?流量多少?
  2. 製程 1 的 Ar:光譜上 Ar 是最亮的線,但氣體清單沒有列 Ar。請確認 Ar 流量。

  4. 每段的總流量與腔壓(sccm、Torr)。漏進來的空氣會被製程氣體稀釋, 可偵測漏率要用總流量換算;總流量是幾百 sccm 還是幾十 slm,結論可能完全相反。
  5. 規格漏率(mTorr/min 或 mbar·L/s),以及腔體容積。
  6. 兩段的關係:短段 → 長段是同一片晶圓的兩個步驟,還是兩個不同的配方? 短段是不是清潔或前處理步驟?

  8. 製程中有沒有用 N₂(例如 purge、稀釋、背面冷卻)?會直接影響氮背景。

8. 建議的驗證:DV 加量

在流量資料到手、以 §7 第 4 項算出預期值之前,這套設定只能證明「會看」,不能證明「看得到」。驗證步驟:

  1. 先把 §5 的設定上機,跑幾批正常生產,確認兩類都分對,Guard 和 TrendOnly 的值與 §4 一致。
  2. 用洩漏閥(DV)在兩段製程各加 3 個劑量(含 0),每個劑量至少 3 次 run。 劑量換算見 dosing-valve-reference-zh-TW.md。
  3. 對每一個候選 Ratio(包括 TrendOnly 的),算劑量-響應斜率和 響應 / run 間 σ。 反應最大、最穩的兩個留做 Alarm;若製程 2 有達到 3σ 的指標,再把它升成 Alarm。
