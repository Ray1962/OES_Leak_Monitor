OES Leak Monitor × EAP 整合規格（PM3）

對象： 廠內 EAP 平台的開發與維運人員。 目的： 說明 EAP 要如何連上 PM3 的 OES Leak Monitor、讀哪些資料、怎麼判讀，以及怎麼和主機台的製程事件接起來。 第一階段範圍： 只記錄與通知，不扣貨、不 Hold 腔體、不對設備下命令。 依據： Satellite_SECS_Specification_v2.md（欄位語意）、secs-integration.md（設備端實作）、EAP ceid-events.md（主機台 CEID 表）。三者與本文衝突時，以前兩份為準，並回頭修正本文。

3. 連線後的初始化順序

每次建立通訊（包括斷線重連）都要完整跑一次。下表每一項都已確認設備端支援。

步驟訊息目的

2S1F1 → S1F2確認型號與軟體版本
2aS1F17 → S1F18依平台慣例要求 ON-LINE（設備端支援；ONLACK 0 = 接受、2 = 已在線上，兩者皆可）
3S2F31 → S2F32對時（見下方注意）
4S1F11 → S1F12讀 SVID 名單，和第 4.1 節比對；缺項要告警，不要默默略過
5S5F5 → S5F6讀警報清單，應有 5 條，ALID 為 ASCII
6S5F3 → S5F4啟用全部警報
7S2F43 → S2F44開啟 S5、S6 的暫存（spooling），斷線期間的警報與事件才不會遺失
8S2F33 → S2F35 → S2F37定義報告、連到 CEID、啟用事件（第 4.3 節）
9S2F23 → S2F24訂閱 Trace（第 4.1 節）
10S6F23 → S6F24取回斷線期間暫存的訊息

對時的注意事項： S2F31 只會設定 OES 回報給 Host 的 SECS 時鐘，不會改 OES PC 的系統時間。OES 寫的 CSV 與日誌用的是 PC 時鐘，所以 OES PC 要另外接廠內 NTP，否則事後拿 CSV 和 EAP 的紀錄對時會對不上。

5. 判讀規則（必須實作）

以下行為都已對照設備端程式碼確認。EAP 的語意層必須處理，否則會產生假警報或漏報。

#規則寫錯的後果
R1VID 001 必須搭配 004 讀。 004 = 0 時 001 送 0，存成 NULL，不是「漏率 0」趨勢圖上出現大量假的「零漏」
R2VID 016 = 1 的資料一律標成「非量測」，不可進 SPC、報表或通知測試或回放的警報被當成真的
R3VID 015 = 1 時，另發一則「OES 需重抓基準」給設備工程師曝光參數改了，所有判定都在比錯的東西
R4007 = 3（Alarm）是鎖存的。 漏氣停止也不會自己回落，警報持續時間要算到 CEID 502把「沒人處理」算成「漏了很久」
R5ALID 是成對的。 以 (ALID, set)／(ALID, clear) 維護「有效警報表」。Warning 升 Alarm 時，OES 先 clear 001、再 set 002警報表殘留已結束的警報
R6重連後用 S1F3 讀 007 校正警報表，即使已開啟 spooling 也要做斷線期間的轉態遺失，警報表與實際不符
R7VID 008 和 009 不可相加或相減。 008 只排除停用的比值；009 只算 Warning（Alarm 算在 010）。要判斷「有沒有異常」，看 007鎖存 Alarm 時讀到 009 = 0，誤判為正常
R8讀 027 前先看 028。 027 空字串有三種原因，只有 028 分得出來（0 未設分類器、1 無電漿步驟、2 尚未判定、3 已分類、4 無法分類）把「還沒判定」當成「不是製程 A」

6. 與主機台製程事件的關聯

6.1 使用的主機台事件（PM3）

主機台 CEID事件說明欄EAP 用途
3100439529／3100439530PM3 ProcessStart／EndChamber Process／Chamber precoat製程 A 視窗：OES 判定有效
3099591660／3099591661PM3 ProcessStart／EndChamber Clean清潔視窗：OES 判定不適用
3100167145／3100167146PM3 ProcessStart／EndAuto Leak check主機台升壓測漏：OES 的對照組

Chamber Process 與 Chamber precoat 的 CEID 相同。 兩者是同一個製程，差別只在 precoat 沒有放晶圓。從 CEID 分不出來，OES 從光譜也分不出來（兩者都會判為製程 A）。處理方式見 6.3。

6.2 視窗定義

EAP 依主機台事件維護 PM3 的「目前視窗」：

視窗開始結束OES 警報的意義
PROCESS_A31004395293100439530有效：製程 A 電漿中偵測到漏氣
CLEAN30995916603099591661不適用：OES 的比值組不是為清潔製程設計的
LEAK_CHECK31001671453100167146主機台測漏中，通常沒有電漿
IDLE以上皆非OES 判定為 Idle 或 NoPlasma，警報不應出現；若出現，視為異常並記錄

關聯規則：

  • OES 的每一筆 ALID 和每一筆 Trace 樣本，都標記收到當下 PM3 所在的視窗與視窗開始時間。
  • 時間基準用 EAP 收到訊息的時間。OES 的 S6F11 與 S5F1 不帶設備時間戳；暫存（spooled）訊息到達較晚，以 S6F23 取回時要另外標記「延遲到達」。
  • 警報跨視窗（例如 PROCESS_A 期間 set，結束後才 clear）時，以 set 時的視窗為準。

6.3 有沒有晶圓（Chamber Process vs. precoat）

EAP 目前不知道 ProcessStart 時 PM3 裡有沒有晶圓（列為待補需求，見第 10 節）。第一階段：

  • 兩者用同一條規則：OES 判定在兩者期間都有效。precoat 時漏氣一樣是漏氣，而且是在第一片晶圓進腔之前發現，處理價值最高。
  • 完整保存每個 PROCESS_A 視窗的開始與結束時間。 之後平台補上晶圓資訊時，可以用時間戳回頭判斷每一筆 OES 警報當時有沒有晶圓、影響哪些 Lot。

6.4 交叉驗證

檢查條件不符時代表
OES 製程類別PROCESS_A 視窗內，028 = 3 時 027 應為 A對時錯誤、腔體對應錯誤，或 OES 分類規則需要重調
電漿有無PROCESS_A 視窗內，021 應為 1OES 的電漿門檻設太高，該製程完全沒被判定
主機台測漏對照每次 LEAK_CHECK 的結果與前後 OES 讀值並排保存累積起來就是 OES 漏報、誤報的實地證據

第一項僅在 OES 開啟製程分類器時適用（028 ≠ 0）。

7. 第一階段動作：記錄與通知

不扣貨、不 Hold 腔體、不對任何設備下命令。 原因：OES 在這台機台的偵測能力尚未經實地驗證（leak-monitor-plan-zh-TW.md §16.1 的結論為 NO-GO），且 2026-09 曾因基準擷取錯誤整天顯示 Alarm。先累積誤報率，再決定是否放權。

觸發條件通知對象內容
ALID 10327002 setVID 016 = 0設備工程師時間、PM3 視窗、ALTX、當下 VID 001／004／013
ALID 10327012～014 set不論 016設備工程師時間、ALTX；註明「OES 已停止量測」
VID 015 由 0 變 1VID 016 = 0設備工程師「OES 基準已不適用，需重抓 Golden Run」
CEID 10327502—不通知，只記錄解除時間、警報持續時間
ALID 10327001 set—不通知，只記錄Warning 次數納入月報

通知範例：

[OES PM3] 洩漏警報 (Alarm)
時間：2026-10-22 14:03:11
PM3 視窗：PROCESS_A（開始於 14:01:40）
OES：CH3 OES LEAK ALARM composite=3, 2 alarm / 0 warning of 3 ratios
漏率：2.4E-3 mbar·L/s（有效）　基準：Recipe 1
處理：請至 OES 畫面確認並由操作者按 Acknowledge

8. 資料保存

資料建議結構保存期限（建議）
OES 警報一筆一列：ALID、set 時間、clear 時間、ALTX、set 時的 PM3 視窗、是否測試資料（016）、是否延遲到達永久
OES 事件一筆一列：CEID、時間、報告內容永久
OES Trace時序資料：時間、各 VID 值、PM3 視窗1 年
PM3 視窗一筆一列：類型、開始、結束、主機台 CEID永久（之後補晶圓資訊要用）
主機台測漏對照每次 LEAK_CHECK：開始、結束、主機台結果、前後 10 分鐘 OES 007／001 摘要永久

OES PC 本身也保存 SECS 收送日誌（Log\secs_YYYYMMDD.log）與 Ratio CSV，雙方有爭議時可以互相對照。

月報建議：Alarm 次數（依視窗分類）、每次 Alarm 的處理結果（真漏／基準問題／不明）、OES 斷線時數、與主機台測漏結果的一致率。這份統計是第二階段「是否放權」的依據。

9. 驗收方式

不需要真的漏氣。OES 的 Replay 分頁可以播放一段記錄過的漏氣錄檔（Normal → Warning → Alarm）。

#步驟預期
1EAP 連線，跑完第 3 節初始化每一步回覆碼為 0；S1F11 名單與第 4.1 節一致
2OES SECS 分頁勾選 Report test / replay data too，播放漏氣錄檔EAP 依序收到 10327001 set → 10327001 clear + 10327002 set
3檢查步驟 2 的資料全部標記為「非量測」（VID 016 = 1），且沒有發出通知（驗證 R2）
4操作者在 OES 按 Acknowledge收到 10327002 clear 與 CEID 10327502
5Alarm 期間拔掉網路線 30 秒再接回重連後警報表正確；暫存訊息取回且標記延遲（驗證 R6）
6取消勾選 Report test / replay data too 後再播一次收不到 ALID；但 S1F3 讀 007 仍會變化
7在主機台跑一次 PM3 Chamber ProcessEAP 建立 PROCESS_A 視窗；若 OES 已開分類器，視窗內 027 = A

10. 待補需求與已知限制

10.1 待補需求

#項目負責影響
N1ProcessStart 時 PM3 有沒有晶圓（區分 Chamber Process 與 precoat）EAP 平台補上前無法判斷警報影響哪些 Lot；6.3 的時間戳保存是為此準備
N2確認 OES SECS 分頁的機台號 cc = 03設備工程師不是 03 時，第 4 節所有編號的第 2～3 碼要跟著改
N3主機台 Auto Leak check 的結果變數（漏率或通過／失敗的 VID）主機台／EAP 平台沒有結果值，6.4 的對照只能記時間
N4驗證有晶圓與沒有晶圓的製程 A 光譜是否有差設備工程師（用 N1 的資料）若有差，OES 的基準只能從有晶圓的步驟建立

10.2 OES 設備端的已知限制

項目狀態EAP 的因應
CEID 501（洩漏狀態改變）未實作狀態變化靠 ALID 與 Trace 的 007 推得
比值槽位 VID 101～400未實作只有整機結論，看不到逐比值細節
遠端命令 S2F41不提供（需求方決定）EAP 不能遠端解除警報；一律由操作者在 OES 畫面按 Acknowledge
設備端時間戳S6F11／S5F1 不帶用 EAP 收到的時間；OES PC 要接 NTP
一個 OES App 對一個 cc設計如此將來 PM2 也加裝時，是另一條連線、另一組編號（cc = 02）
