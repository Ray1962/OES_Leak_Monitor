修改報告：2026-11-19 ～ 2026-11-20

這份報告整理 11/19–11/20 兩天對 OES Leak Monitor 的所有修改，說明改了什麼、為什麼要改。 期間共合併 9 個 PR（#98、#99、#100、#109、#110、#111、#118、#124、#131），全部以 squash 合併進 master，最後一個 commit 是 0517649。 11/20 晚上已用 SelfContained-win-x64 重新發布交付資料夾。

0. 起因：11/19 實驗機漏氣測試

11/19 在實驗機做了洩漏閥（DV）0/200/300/400 的漏空氣測試（各點位的流量見洩漏閥點位與漏氣流量，DV=300 ≈ 0.2 mbar·L/s ≈ 12 sccm），錄檔在 C:\DualOES\202611\19。 這次測試暴露出幾個問題，後面所有的修改都是從這裡來的：

  1. 取線錯誤。 兩組 OH 比值的基準窗落在 OH 帶上，讀值為負，被 Golden Run 丟掉。只剩 NO/Ar 一組，加上 requireTwoForAlarm，Alarm 永遠不會觸發。當晚已在實驗機用修正後的取線（NO 235.6、OH 308.8 Integral）解決，並用 Replay 驗證。
  2. 基準漂移比漏氣訊號還大。 開電漿後 NO/OH 會持續衰減，40 分鐘內漂移約 10–40%。DV=300 的訊號只有 NO +30%、OH +7–9%。固定的 Golden Run 基準因此一開頭就誤報，後段又漏報。
  3. Ratio Setup 存檔會重設取線窗。 中心不在譜線目錄的取線區，存檔時會被改回預設窗（#88）。
  4. 趨勢圖畫的不是判定依據。 圖上固定畫 100/120/150 的「% of baseline」線，看不出滾動基準判定的上升量。
  5. 預設取線窗太窄。 光譜儀像素間距約 0.6 nm，預設 ±0.5 nm 的訊號窗只涵蓋 1 個像素。

1. Step judging：滾動基準判定（PR #98，issue #90–#97）

改了什麼

  • 每個比值除了 Golden Run 判定以外，可以再開「滾動基準（step）」判定。
  • 參考值是 [t − 180 s, t − 20 s] 這段時間原始比值的中位數。
  • 上升量（rise）超過 Warn rise / Alarm rise，並經過確認時間後就會 latch。上升量超過 Warn 時參考值會凍結，避免基準被漏氣本身拉高。
  • 判定前要先累積資料（warm-up），期間顯示 "Warming up"，不列入綜合判定。
  • 程式結構：
    • 原本 RatioMonitor 的確認／latch 狀態機抽成 JudgingPath。Golden Run 和 step 是同一種 path 的兩個實例。
    • 狀態取兩條 path 中較嚴重的那個。Acknowledge 會同時清掉兩條 path 的 latch。
  • Leak Monitor 面板：
    • 新增 step (vs rolling) 欄。
    • 狀態文字標出是哪條 path 觸發的，例如 "ALARM · Step"、"WARNING · GR"。
  • Ratio Setup：
    • 新增 Judging 區塊。
    • 存檔會拒絕三種設定：兩條 path 都關、Warn rise ≤ 0、Alarm rise 小於 Warn rise。
  • Ratio CSV：step 判定的比值多一欄 _stepRise，放在 LeakRateSigma 後面，所以舊的讀取程式不受影響。
  • RawMean（pedestal）讀值不能做 step 判定。
  • SECS 的資料格式不變。

為什麼

固定基準對付不了開電漿後的衰減漂移。用滾動基準在 11 個錄檔做模擬：DV=300/400 六次全部抓到，DV=0/200 沒有誤報，而且比 Golden Run 判定更早發出警報。

判定不用 σ，是因為即時 σ 在漏氣那一步會被放大，反而讓警報變遲鈍。

新增的錄檔測試把 11 個錄檔送進引擎跑一遍，C# 結果和 Python 模擬的差距在 1 ms 以內。

附帶修正

  • PR #99：「% of Golden Run (not judged)」在 120 px 寬的欄位被截斷，改成「% of GR (not judged)」。
  • PR #100：重拍使用手冊圖 4、5，新增 step judging 的圖 6。

2. 趨勢圖改為「% vs reference」（PR #109–#111，issue #101–#108）

改了什麼

  • Leak Monitor 趨勢圖改成畫「實際被判定的量」，所有線共用一條以 0 為中心的「% vs reference」軸：
    • step 判定的比值畫上升量；
    • Golden Run 判定的比值畫 % of GR − 100。比值同時有 step 判定時，這條線用虛線，名稱加上 " (GR)"。
  • 移除固定的 120／150 線。
    • 點一列就畫出該比值自己的 Warn/Alarm 線，並淡化其他線。
    • 再點一次或按 Esc 取消選取。
  • warm-up 期間畫灰色的「warming up」帶。
  • Ratio Review 改成用同一套投影（TrendProjection / RecordedTrendProjection）。
    • 每段錄檔的判定方式和門檻，取自錄檔旁的 _config_*.json：選「不晚於錄檔最後一列」的最新一份。
    • 新增 Thresholds 選單。
    • 沒有 config snapshot 的舊錄檔照樣可以畫，只是不畫門檻線。
  • 修正：選取一列之後立刻用最新一幀畫門檻線。以前沒有新幀進來（例如 Replay 結束）時，選了也畫不出來。
  • 文件：CONTEXT 新增「% vs reference」名詞；使用手冊 §6.3.6、§6.10 改寫；圖 4、6、10 重拍。

為什麼

有了 step 判定以後，舊圖的「% of baseline」和固定 120／150 線已經對應不到實際的判定依據。操作員看圖時無法判斷離警報還有多遠。

config snapshot 採用「不晚於最後一列」的規則，是因為 11/19 的 snapshot 比 ratio CSV 的第一列晚 2–68 s 才寫入。如果用「不晚於第一列」，多半會選到錯的設定。

3. 取線窗存檔不再被重設，並記錄在 Golden Run 上（PR #118，issue #88、#114–#117）

改了什麼

  • Ratio Setup 每一側只保留一份正在編輯的 LineRegion。它一開始是載入區段的原樣複本，只有操作員改了線、模式或窗寬時才會變。
  • 訊號半寬、基準間隙、基準寬、峰搜尋四個欄位可以直接編輯：
    • 換線時重設為預設值；
    • 只換模式時保留原值；
    • 存檔時檢查 0–20 nm 的範圍，超出就指出是哪個欄位。
  • Golden Run 基準會記錄擷取時的取線窗（WindowKey，不含中心）。
    • 取線窗不符時清除基準，並寫入 LeakMonitorBaselineMismatch 日誌。
    • 波長校正改變不會讓基準失效。
    • #88 之前建的舊基準照舊接受。
  • 存檔時會列出這次修改讓哪些比值的 Golden Run 失效。

為什麼

11/19 調好的 NO 235.6、OH 308.8 中心不在譜線目錄裡，一存檔就被改回預設窗，等於默默推翻了取線修正。當時只能用使用者譜線繞過去。

基準記錄取線窗之後，換了窗就不會再拿舊基準來比，避免誤判。

4. 不對稱基準窗與 Line preview（PR #124，issue #112、#120–#123）

改了什麼

  • 左右基準窗可以分別設定間隙和寬度（右側 gap / width）。
  • Ratio Setup 新增 Line preview，可以顯示即時光譜、Freeze 畫面，或錄檔中的某一幀。
    • 預覽圖上依實際量到的位置畫出訊號窗、基準窗，和引擎算出的讀值。
    • 基準窗和鄰近譜線重疊、窗內沒有峰等狀況，會顯示警告。
  • 使用手冊新增圖 5a。

為什麼

  • OH 308.8 坐在 N₂ 315.9 的斜坡上，乾淨的背景只有 298.6–305 和 317–320 nm 兩段。對稱的基準窗一定會踩到其他譜帶。
  • 11/19 的取線錯誤要到看了光譜才發現。在設定畫面直接看到窗落在光譜的哪裡，才能在現場當下發現問題。

5. 像素數取線窗預設、過窄警告與 Apply suggested widths（PR #131，issue #125–#130）

改了什麼

  • 新增 LineWindowAdvice。預設窗改以像素數訂定：訊號 5、基準 3、間隙 2、峰搜尋 2。再用當下光譜的像素間距換算成 nm；沒有光譜時以 0.6 nm 計算。
  • Ratio Setup：
    • 每一側顯示各窗涵蓋幾個像素；
    • 低於最低值時顯示 "Too narrow" 警告；
    • 新增 Apply suggested widths 按鈕，只把過窄的窗拉寬，可以用 Revert 還原。
  • 出廠比值和參考線 preset 改成符合最低值。N₂ 337.1 用不對稱間隙避開 Zn 334.5。
  • 既有設定不自動遷移。
  • Integral 訊號窗不設像素下限；峰搜尋設為 0 時視為刻意固定，不做檢查。

為什麼

  • 0.6 nm/px 下，原本的預設窗只有 1–2 個像素：峰稍微漂移就跑出窗外，基準也不穩。
  • 用 11/19 錄檔驗證的結果：
    • Ar RawMean 從 1 px 加寬到 5 px，表現持平或更好；
    • 已調好的 NO、OH Integral 帶加寬到 7 px，step SNR 反而下降 25–35%。多出來的像素不回應漏氣，而且雜訊主要來自電漿閃爍，不是像素雜訊。

所以 Integral 不設下限。

  • 不自動遷移，是因為改了窗之後 Golden Run 就會失效，應該由工程師自己決定什麼時候改、改完重新驗證。

細節見 docs/worklog-20261120.md。

7. 對現場的注意事項

  1. 新功能在舊設定檔下預設都是關的：step 判定預設關閉，取線窗也不會自動加寬。舊設定的行為和以前完全一樣。
  2. 要用 step 判定，在 Ratio Setup 的 Judging 區塊勾選即可。11/19 的建議設定是：
    • NO 235.6/Ar：+10% / +15%；
    • OH 308.8/Ar：+2% / +3%；
    • 關閉 Golden Run 判定，並開啟 RequireTwoForAlarm。

這組參數是用同一批資料挑出來的，還需要 DV=0→300 的實測確認。

  1. step 判定要先 warm-up 約 40 s，開閥的 SOP 要配合這段時間。
  2. 改了取線窗之後，相關比值的 Golden Run 基準會失效，要重新擷取。
  3. 本機 SECS 驗收用的 settings.json 這兩天都沒有被修改。
