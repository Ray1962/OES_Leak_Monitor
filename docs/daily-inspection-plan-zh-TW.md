## 1. 目的與適用範圍

### 1.1 監控目的

在製程腔體上以光纖取電漿自身的發光，用**比值法（actinometry）**即時判斷是否有**空氣（氮、氧、水氣）漏入製程腔**。

空氣漏入的光譜特徵是：**O、OH、NO（以及 N₂⁺）等物種的譜線同時上升**，而製程本身供應的參考譜線（N₂ 337.1 nm、Ar 750.4 nm 等）維持不變。用比值而非絕對強度，是為了消掉功率、壓力、觀察窗汙染這類**與洩漏無關**的漂移。

漏氣在半導體製程上的後果是實質的：膜質劣化（含氧、含氮）、顆粒增加、腔體與泵浦腐蝕、真空件壽命縮短，嚴重時整批 WIP 報廢。**這套系統的價值在於「在製程結果變壞之前就看到趨勢」**，所以巡檢的重點不是「有沒有跳警報」，而是**「趨勢有沒有在慢慢變」**。

### 1.2 兩階段巡檢的分工

| 階段 | 名稱 | 目的 | 需要的能力 |
|---|---|---|---|
| **第一階段（L1）** | 一般性簡易巡檢 | **只問一句話：現在跟平常一不一樣？** 不調參數、不改設定，發現異常就記錄並上報 | 會操作介面即可（Operator 權限） |
| **第二階段（L2）** | 深入巡檢 | 確認**偵測策略本身還有效**：基準線、譜線選擇、門檻、SNR、波長、洩漏率校正 | 需懂製程氣體與光譜（Engineer 權限） |

> ⚠️ **L1 人員不得更改任何設定。** 調整門檻、換譜線、重錄 Golden Run 一律屬於 L2。
> L1 若「因為一直跳警報就把門檻調高」，等於關掉這套系統。

### 1.3 不在本計畫範圍內

- 光譜儀硬體本身的計量校正（送校）。
- 腔體的實體檢漏（氦質譜檢漏、升壓率測試）——本系統是**線上早期指標**，確認漏點仍需實體檢漏。
- 機台的製程參數調整。

## 2. 巡檢層級、頻率與責任分工

| 項目 | L1 每日巡檢 | L2 深入巡檢 |
|---|---|---|
| 頻率 | **每班次一次**（建議交接時），至少每日一次 | **每週一次**；另加事件驅動（見 §9） |
| 每台耗時 | 約 5–10 分鐘 | 約 30–60 分鐘 |
| 執行者 | 設備技術員／製程操作員 | 設備工程師／製程工程師 |
| 軟體權限 | Operator | Engineer 或 Admin |
| 產出 | L1 巡檢表（§10.1） | L2 巡檢表（§10.2）＋設定變更記錄 |
| 可否改設定 | **否** | 是（須記錄變更原因與前後值） |
| 異常處理 | 記錄 → 通報工程師 | 判定 → 處置 → 驗證 → 結案 |

**建議排程**：L2 安排在**機台已知穩定、且剛跑完良品批**的時段做，因為 L2 的許多項目（重錄 Golden Run、驗證校正）需要一個「確定沒有洩漏」的基準狀態。剛做完 PM 但尚未驗證的機台不適合做 L2 定基準。

## 3. 巡檢前準備

巡檢開始前先確認以下四件事，缺一則巡檢結果不可信：

| 項目 | 確認方式 | 不符合時 |
|---|---|---|
| 帳號權限 | 右上角角色徽章顯示 `Operator` 以上 | 先 **Sign In**；閒置 5 分鐘會自動鎖回 Guest |
| 硬體連線 | Monitor 分頁狀態列 **Test Mode = False** | **立刻停止巡檢並上報** ——`True` 代表現在畫面上全是模擬資料，判讀完全無效 |
| 電漿狀態 | 機台正在跑製程（有電漿） | 沒電漿時只能做「介面存活」檢查，比值判讀無效（會顯示 `No Plasma`） |
| 對照基準 | 手邊有**同配方、同機台**的前次巡檢記錄 | L1 的判定全部是「跟上次比」，沒有對照就只能記錄不能判定 |

> 💡 **關於 Test Mode**：`Test Mode = True` 而硬體確實有接，最常見原因是程式資料夾裡少了
> `UserApplication.dll` / `SiUSBXp.dll` / `libsodium.dll`（見手冊 §9.1）。這是本系統最危險的失效模式
> ——畫面看起來一切正常、數字會動、卻完全沒在監控真實腔體。**每次巡檢第一件事就是確認這一格。**

## 4. 第一階段（L1）每日巡檢

**原則**：由「光」到「數」——先看光譜長相（§4.1），再看時間趨勢（§4.2），最後才看系統給的結論（§4.3）。反過來只看警報燈，會漏掉「還沒到門檻但已經在爬」的緩漏。

### 4.0 步驟 0 — 連線與擷取狀態（30 秒）

在 **Monitor** 分頁確認：

- ☐ `Test Mode` = **False**
- ☐ `Frame` 每幀點數與平常一致（例如 2048），沒有變成 1000（測試模式的點數）
- ☐ `Last`（最後一幀時間）在**數秒內**持續更新——停住代表擷取已中斷
- ☐ `Serial`（序號）與該機台配掛的光譜儀相符

任一項不符 → **停止判讀，直接進入 §8 升級流程**。

### 4.1 步驟 1 — 檢查電漿強度光譜【重點一】

畫面：**Monitor** 分頁上半部的全譜圖（DevicePanel）。操作：滑鼠滾輪縮放、右鍵 → **Zoom All**（快捷鍵 `A`）回到全譜。

看五件事，**由粗到細**：

#### (1) 整體強度水準

- 全譜最高峰的計數值與前次巡檢相比，變化應在 **±20% 以內**。
- **明顯偏低**（例如掉到 70% 以下）→ 觀察窗汙染、光纖鬆脫或彎折、電漿功率下降。
- **明顯偏高** → 有人改過積分時間，或製程條件改變。

> ⚠️ 強度絕對值的變化**本身不是洩漏**。洩漏看的是比值（§4.3）。但強度大幅下降會讓譜線掉進雜訊底，
> 使系統進入 `Low Signal` 而**失去偵測能力**——這才是要抓的。

#### (2) 訊號飽和（削頂）

- ☐ 沒有任何峰的頂端呈現**平頂／被切平**的形狀。
- 飽和代表該波長已超出偵測器量程，強度讀值不再正確，比值必然失真。
- 發現飽和 → 記錄並上報（L2 需縮短 Integration Time 後重錄 Golden Run）。

#### (3) 基線（暗背景）水準

- 譜線之間的「谷底」應接近平坦且貼近零；若整條基線被整體抬高，通常是雜散光、外部漏光（機台門開著、維修燈照到觀察窗）或偵測器溫度異常。
- ☐ 巡檢時確認**腔體觀察窗附近沒有外部光源照入**。

#### (4) 關鍵譜線是否都在、形狀是否正常

對照該機台的**標準光譜照片**（L2 於策略定案時拍存，見 §7.1 步驟 7），逐一確認下列譜線存在且峰形對稱：

| 譜線 | 波長 | 角色 |
|---|---|---|
| N₂ (SPS) | 337.1 nm | 常用參考線／電漿存在判定 |
| OH | 308.9 nm | 洩漏指標（水氣） |
| NO | 237.0 nm | 洩漏指標（N+O 反應產物） |
| O | 777.2 nm | 洩漏指標（氧原子） |
| Ar | 750.4 / 811.5 nm | 參考線（若製程有通 Ar） |
| N₂⁺ | 391.4 nm | 空氣漏入的高敏感指標（若策略有納入） |

- ☐ **峰形對稱、無分裂、無明顯變寬** ——變寬或偏移見手冊 §9.3（多為硬體平均模式問題）。
- ☐ **沒有新出現的、平常不存在的峰**。新峰的常見來源：金屬（Fe 372 / Cr 425 / Al 396 → 腔體或載具被濺射）、CN 388（有機物或 O-ring 被侵蝕）、H 656（水氣或有機物）。**新峰一律記錄並上報**。

#### (5) 幀完整性

- ☐ 光譜沒有出現**斷裂／撕裂**（波形中間出現不連續的階梯或錯位段）。
- 這是 Z5／乙太網路機種在長積分時間下的已知現象，處置是 L2 把 Acquire Mode 改為 `Oneshot`（手冊 §9.2）。

### 4.2 步驟 2 — 檢查電漿強度趨勢【重點二】

畫面：**Monitor** 分頁下半部的 **Wavelength Trend**（時間 vs 強度，保留 30 分鐘）。

這張圖畫的是**每幀原始計數**（刻意不濾波），最多 6 條線：Trigger 波長 ＋ Monitored Wavelengths 前 5 個。

**建議巡檢操作順序**：

1. 先按 **Zoom All** 看完整 30 分鐘。
2. 勾 **Smooth**（τ ≈ 3 s EMA）——雜訊被壓下去後，**緩慢的趨勢**才看得出來。切換時歷史也會一起重算。
3. 再勾 **Normalize**——所有線以「勾選當下」為 1.0，這時看的是**各線之間有沒有分歧**。
   洩漏的特徵就是「洩漏指標線往上跑、參考線持平」，正規化後一眼可辨。
4. 判讀完**取消 Normalize**，把畫面留在原始狀態給下一班。

檢查四件事：

| # | 檢查項 | 正常 | 異常樣態 |
|---|---|---|---|
| 1 | **平穩度** | 各線在 30 分鐘內圍繞水平帶波動 | 有線單調上升／下降 |
| 2 | **同步性** | 所有線一起動（功率、壓力波動的正常表現） | **只有部分線在動** → 化學組成真的變了 |
| 3 | **階梯跳動** | 無 | 出現方波狀突跳 → 有人改參數、或幀撕裂 |
| 4 | **訊號中斷** | 曲線連續 | 出現斷點／歸零 → 擷取中斷或電漿熄滅 |

**判讀的關鍵是「同步 vs 分歧」**：

- **全部線同步緩降**（正規化後仍重疊）→ 光路問題（觀察窗汙染、光纖），**不是洩漏**。
- **O／OH／NO 上升而 N₂ 或 Ar 持平**（正規化後明顯分岔）→ **高度懷疑空氣洩漏**，即使 Leak Monitor 尚未跳警報，也要立即記錄並上報。這是本系統最有價值的一個判讀，也是把「巡檢」做成「預警」的關鍵。

> 💡 每條趨勢線取的是該波長 **±0.5 nm 內的峰值**（吸收波長漂移用的峰值定位，不是濾波），
> 所以小幅波長漂移不會讓線掉下去；若某線**莫名掉到接近零**，多半是漂移已超過 ±0.5 nm，或該峰真的消失了。

### 4.3 步驟 3 — Leak Monitor 狀態與比值列

畫面：**Leak Monitor** 分頁。這一步是看「系統的結論」，但要**用前兩步的觀察去驗證它**。

- ☐ **狀態橫幅**：應為綠色 `OK — within baseline`。
  - 灰色 `Idle` → 沒電漿或沒基準線（若製程正在跑卻顯示 Idle，屬異常，上報）。
  - 橘 `WARNING` / 紅 `ALARM` → 進入 §8 處置流程。
- ☐ **沒有「LOW SIGNAL」警示**。出現代表有比值的譜線太靠近雜訊底，**該比值已被排除在警報判定之外**——系統的偵測能力已經缺一角，必須上報（處置見手冊 §9.4，屬 L2）。
- ☐ **沒有「測試模式」註記**。
- ☐ **Baseline 下拉選的是今天這支配方對應的基準線**。選錯基準線 = 拿別的配方當標準，全部判讀作廢。這是實務上最常見的人為錯誤，**每次巡檢都要確認**。
- ☐ **逐條比值列**，記錄下列數值到巡檢表：

| 欄位 | L1 判定 |
|---|---|
| 狀態 | 應為 `Normal`（綠） |
| **% of baseline** | **100 ± 10%** 視為正常；**110–120%** 記為「觀察」；**> 120%** 為異常（已達預設 Warn factor） |
| 斜率 | 應接近 0；**持續為正**即使百分比還低，也記為「觀察」 |
| SNR | 應 **> 10**；**5–10** 記為「觀察」（逼近預設下限 5）；**< 5** 該比值已被停用 |
| baseline (mean ± σ) | 與前次巡檢應完全相同——**數值變了代表基準線被重錄過**，須確認是誰、為什麼 |

- ☐ **趨勢圖（% of baseline，30 分鐘）**：所有比值曲線應在 100% 附近水平擺動。**任何一條呈現持續上升**，即使還在門檻以下，都要記錄。
- ☐ **洩漏率讀值**（若已做校正）：記錄數值與 confidence。
  - 顯示 `calibration "X" needs its baseline …` → 校正與目前基準線不配對，**估算已暫停**，上報。

### 4.4 步驟 4 — 資料記錄器與儲存空間

畫面：**Monitor** 分頁的 **Recorder 狀態列**（Reset Run 下方那條，唯讀，不需權限即可檢視）。

- ☐ **徽章不是紅色 `OFF`** —— `OFF` 代表**全光譜記錄器**沒武裝，不會產生強度 CSV（比值 CSV 不受影響，仍照常寫）。有電漿時應為 `SAVING`；沒電漿時 `ARMED` 為正常。
- ☐ **沒有橘色「not saved」小字** —— 出現代表武裝狀態沒寫進 `settings.json`，**下次重開就會失效**（需工程師補按 Configuration 的 Save）。
- ☐ `SAVING` 時右側有檔名，且滑鼠停留可看到完整路徑。
- ☐ 當日的 `Data\YYYYMM\DD\` 資料夾內有今天的 CSV，且檔案大小持續成長。
- ☐ 資料碟剩餘空間 **> 20%**。程式**不會刪除**任何量測資料；餘量低於 10% 時它會在開／關程式時跳出警告（手冊 §7.4）。若該機台已啟用自動壓縮，過期資料會變成 `DD.zip` —— **壓縮不是刪除，回放也不受影響**：Recordings / Ratio Review 會直接讀壓縮檔，清單上標示 `zip`。

> **兩份檔案的產生條件不同**（手冊 §7.3）：
> - **強度 CSV**（`_OES1_`）只在記錄器武裝**且**強度高於觸發門檻時才寫 —— 當班沒跑電漿就沒有檔案，屬正常。
> - **比值 CSV**（`_Ratio_`）只要 OES 在擷取就一直寫，跨午夜會自動換日換檔。**擷取中卻沒有今天的比值檔 = 異常**（手冊 §9.8），因為這代表洩漏監控的歷史沒有被留下來，每週 L2 的回放審查（§6.6）會沒有資料可看。
>
> ⚠️ 武裝／解除武裝在 Engineer 權限的 Configuration 分頁，**L1 人員無法也不需要操作** —— 只負責看狀態列並回報。這是一次性設定，不是每日動作。

### 4.5 步驟 5 — 系統日誌快掃

畫面：**Logs** 分頁，掃過上一班次的記錄。

- ☐ 無 `Error` 等級記錄。
- ☐ 無 `GoldenRunRatioLowSnr`（基準線被拒絕）。
- ☐ 無 `LeakCalibrationSuspended`（洩漏率校正被暫停）。
- ☐ 無非預期的 `RatiosReloaded` / 設定變更記錄——代表有人動過設定，須確認是否為授權變更。

### 4.6 L1 判定準則與處置

依「最嚴重的一項」決定整台機台的巡檢結論：

| 結論 | 條件 | 處置 |
|---|---|---|
| **正常** | 所有項目合格 | 簽名結案 |
| **觀察** | 出現任一「觀察」條件：比值 110–120%、SNR 5–10、斜率持續為正、強度較前次變化 20–30% | 記錄；**縮短巡檢間隔為每 4 小時一次**；連續兩班仍在觀察 → 升為異常 |
| **異常** | 比值 > 120%、WARNING 橫幅、LOW SIGNAL、光譜出現新峰／飽和、Test Mode = True、擷取中斷 | **2 小時內**通報設備工程師執行 L2 |
| **緊急** | ALARM 橫幅、多條洩漏指標同步陡升、洩漏率讀值明顯攀升 | **立即**依 §8 通報，並依廠內規定評估是否暫停投料 |

## 5. 光譜 × 趨勢 綜合判讀表

這張表是 L1 與 L2 共用的核心判讀工具——**同樣一個「數值變了」，要靠「哪些線一起變」才能分辨原因**。

| 光譜表現 | 強度趨勢 | 比值（% of baseline） | 最可能原因 | 動作 |
|---|---|---|---|---|
| 所有峰同步下降，峰形不變 | 全線同步緩降 | **持平** | 觀察窗汙染／光纖劣化／對位偏移 | L2：清潔觀察窗 → **重錄 Golden Run** |
| O 777、OH 309、NO 237 升高，N₂ 337 不變 | 指標線與參考線**分歧** | **多條同步上升** | **空氣洩漏（典型）** | §8 緊急流程 |
| 只有 O 777 升高 | 單線上升 | 單一比值上升 | 該線受干擾（含 F 製程的 SiF 777）／製程含氧氣體變動 | L2：查干擾（§7.3） |
| N₂⁺ 391.4 陡升 | 陡升 | 上升 | **空氣漏入的高敏感早期指標** | §8：即使其他線還沒動也要查 |
| 所有峰同步上下擺動 | 全線同相位振盪 | 持平 | 電漿功率／壓力／匹配器擺動 | 通報製程；非洩漏 |
| 出現金屬峰（Fe/Cr/Al） | 新線出現 | 不定 | 腔體壁／載具濺射、零件損傷 | 通報設備；安排開腔檢查 |
| 出現 CN 388、H 656 | 新線出現 | 可能伴隨 OH 上升 | 有機物污染、O-ring 侵蝕、水氣 | L2 判定；可能是**慢漏＋水氣** |
| 峰整體平移 | 曲線莫名掉低 | 可能整體偏移 | 波長漂移 | L2：Wavelength Calibration（§6.3） |
| 峰變寬、變形 | 抖動增加 | σ 變大、門檻自動放寬 | 硬體平均模式問題 | L2：Average Mode → `Software`（手冊 §9.3） |
| 光譜斷裂／撕裂 | 出現尖刺 | 突跳 | 幀完整性問題 | L2：Acquire Mode → `Oneshot`（手冊 §9.2） |
| 譜線接近雜訊底 | 曲線淹在雜訊裡 | `Low Signal` | 積分時間不足／訊號太弱 | L2：見手冊 §9.4 |

> **記住這條主線**：
> **「強度變、比值不變」＝ 光路或電漿條件問題（本系統設計上要忽略它）。**
> **「比值變」＝ 電漿裡的化學組成真的變了，才可能是洩漏。**

## 6. 第二階段（L2）深入巡檢

L2 的核心問題不是「今天有沒有漏」，而是：**「這套偵測策略，今天還抓得到漏嗎？」**
一套門檻設得太鬆、基準線過期、譜線已掉進雜訊的系統，會天天顯示綠燈，然後在真的漏氣時什麼都不說。

### 6.1 基準線（Golden Run）有效性複核

| 檢查項 | 合格條件 | 不合格處置 |
|---|---|---|
| 基準線清單完整性 | **每支在跑的配方都有**對應的基準線 | 跑一段確定良品的製程 → **Capture Golden Run** |
| 基準線年齡 | 建議 **≤ 3 個月**，或距上次 PM 之後 | 重錄 |
| 每條比值都有基準值 | 沒有比值顯示「無基準線」 | 查 Logs 的 `GoldenRunRatioLowSnr`；先救訊號再重錄（§6.2） |
| 基準線 σ 合理 | σ／mean 建議 **< 10%** | σ 過大代表錄製當時電漿不穩，重錄 |
| 長期偏移 | 各比值日常值應圍繞 100% | 若**長期穩定停在 105–115%** 而非漏氣所致，代表基準線已不代表現況 → 重錄 |
| 名稱可辨識 | 名稱含**配方＋日期** | 更名規範化，避免選錯基準線 |

> ⚠️ **重錄 Golden Run 的前提是「確定此刻沒有洩漏」。** 若在已經慢漏的狀態下重錄，
> 等於把漏氣狀態定義成正常——系統從此永遠不會報警。**重錄前應先完成一次實體檢漏或升壓率測試。**
> 這是整套系統最重要的一條紀律。

### 6.2 訊噪比與光路健康度

- 記錄各比值目前的 **SNR** 值，與前次 L2 比較，**做成長期趨勢**（本系統不會自動畫 SNR 長期圖，請記在巡檢表上）。
- SNR 逐月下降 → 光路劣化（觀察窗鍍膜、光纖老化）。在掉到門檻（預設 5）以前就要處理，**不要等到 `Low Signal`**。
- 參考線（N₂ 337 或 Ar 750）的絕對強度也一併記錄，作為觀察窗汙染速率的指標。
- 處置順序（同手冊 §9.4）：拉長 Integration Time → 提高 Average Count（配 `Software` 平均）→ 檢查光纖與觀察窗 → 該線本來就弱則改 `AbsoluteIntensity` 模式 → **最後手段**才是調低 Min SNR（**不可設為 0**）。
- 每次更動積分時間或平均設定後，**必須重錄 Golden Run**（曝光條件變了，舊基準線無效）。

### 6.3 波長漂移查核與校正

1. 在 Monitor 全譜圖上放大一條**已知波長且明確的譜線**（建議 N₂ 337.1 nm 或 Ar 750.4 nm）。
2. 讀出實際峰位，與標稱值相減。
3. 判定：

| 偏差 | 處置 |
|---|---|
| ≤ 0.1 nm | 合格，不動 |
| 0.1–0.5 nm | 到 **Wavelength Calibration** 分頁登記該譜線的偏移量 |
| > 0.5 nm | 異常，先查機械／溫度／光譜儀本身，再談校正（上限 ±5 nm） |

4. 存檔後**必須回 Monitor 分頁 Stop → Start** 才生效（暫存機制）。
5. 校正會改變擷取窗位置 → **重錄 Golden Run**。

> 波長修正是**依「物種＋波長」對整份目錄生效**的，所以修一次，所有用到該譜線的比值（訊號線或參考線）
> 一起對齊。不需要逐條比值去改。

### 6.4 洩漏偵測策略複核【L2 核心】

依序回答六個問題，任何一個答不出「是」，就要重新走 §7 的策略制定流程。

| # | 問題 | 判斷依據 |
|---|---|---|
| 1 | **訊號線選得對嗎？** | 洩漏指標物種，是否**確定不由製程氣體本身產生**？（見 §7.2） |
| 2 | **參考線選得對嗎？** | 參考線物種是否由製程**穩定供應**、且**與洩漏無關**？流量會隨步驟變動的氣體不適合當參考線 |
| 3 | **有沒有譜線干擾？** | 對照 §7.3 的干擾清單，特別是含氟製程的 SiF 777 vs O 777 |
| 4 | **門檻合理嗎？** | 檢視近一個月的 Ratio Review：門檻線是否**穿過正常資料的雜訊帶**（會誤報）或**遠高於實際漏氣時的上升幅度**（會漏報） |
| 5 | **監測模式對嗎？** | 弱訊號線用 `Ratio` 會劇烈跳動 → 應改 `AbsoluteIntensity`；但該模式**不再抵銷電漿條件漂移**，需要更穩定的操作點與更頻繁的重錄基準線 |
| 6 | **複合判定合理嗎？** | `RequireTwoForAlarm`（預設開）要求兩條比值同時 Alarm。若該機台只有一條可靠指標線，此設定會讓警報**永遠不觸發** |

**所有設定變更都必須記錄**：變更項目、前值、後值、原因、變更人、驗證方式。
變更後記得：Ratio Setup 與 Wavelength Calibration 的修改是**暫存**的，需 **Stop → Start** 才生效（Leak Calibration 例外，存檔即生效）。

### 6.5 洩漏率校正驗證（有做定量的機台）

1. 確認目前 **Baseline 與校正配對**（狀態顯示 `Active`，不是 `BaselineMismatch`）。
2. 以**標準漏孔（calibrated leak）**通入已知漏率，讀取 Leak Monitor 的洩漏率估計值。
3. 判定：偏差 **≤ ±30%** 視為合格（本系統定位是趨勢預警，不是計量儀器）；偏差過大則重做校正（Leak Calibration 分頁）。
4. ☐ 確認校正用的氣體是**空氣**（或與待測洩漏相同的氣體）——用惰性氣體做的校正無法對應 O／OH／NO 的上升。
5. 記錄本次驗證的漏率、讀值、偏差百分比。

### 6.6 誤報／漏報審查（回放）

- 到 **Ratio Review** 分頁，回放過去一週的比值資料。
  - 對每次曾發生的 WARNING / ALARM：是**持續上升**（真事件）還是**短暫尖峰**（雜訊／製程切換瞬態）？
  - 短暫尖峰多 → 提高 **Confirm time**（預設 15 s）比調高門檻更好，**不會犧牲靈敏度**。
- 到 **Recordings** 分頁，抽查一組完整光譜，確認 CSV 有正常落地且可重新解析。
- 統計本週：誤報次數、漏報（事後才由其他手段發現的洩漏）次數，記入巡檢表。**漏報一次就必須重新檢討策略。**

### 6.7 組態備份與版本記錄

- ☐ 備份 **`settings.json`**（`Config` 資料夾）——一個檔案就涵蓋裝置參數、記錄器設定、比值定義、Golden Run 基準線、洩漏率校正、波長修正。
- ☐ 備份檔名含**機台編號＋日期**，存到廠內備份路徑。
- ☐ 確認預設帳號 `admin/admin` **已更改**，且帳號清單中沒有離職人員。
- ☐ 清理超過保存期限的舊 `Data\` 資料夾。

## 7. 洩漏偵測策略制定流程（L2 專用）

新機台導入、換製程、或 §6.4 複核不合格時走這套流程。

### 7.1 七個步驟

**步驟 1 — 列出製程氣體與副產物。**
把該配方所有進氣（含清洗步驟的 NF₃／O₂／Ar）與已知副產物列出來。**這一步決定後面全部**。

**步驟 2 — 選洩漏指標（訊號線）。**
原則：**該物種必須是製程本身不會產生的**。空氣漏入的候選指標：

| 指標 | 波長 | 特性 |
|---|---|---|
| O | 777.2 nm | 強、易測；但**製程若通 O₂／N₂O／CO₂ 則不可用** |
| OH | 308.9 nm | 對**水氣／潮濕漏點**敏感；製程含 H 源（SiH₄、NH₃、H₂）時背景偏高 |
| NO | 237.0 nm | N＋O 反應產物，**同時需要氮和氧才會出現**，對「空氣」的專一性高；訊號較弱 |
| N₂⁺ | 391.4 nm | 對空氣漏入**極敏感的早期指標**；受電子溫度影響，需配對穩定的參考線 |
| N₂ | 337.1 nm | 製程通 N₂／NH₃／N₂O 時**不能當指標**，只能當參考線 |

**步驟 3 — 選參考線。**
原則：製程**穩定供應**、流量在該步驟中**不變**、且**與洩漏無關**。優先順序：

1. **Ar 750.4 / 811.5 nm** —— 若製程有通固定流量的 Ar，這是最理想的 actinometer。
2. **N₂ 337.1 nm** —— 製程本身大量供應 N₂ 時可用（但此時 N₂ 就不能當指標）。
3. **Hα 656.3 nm** —— 製程含穩定 H 源時可用。

**步驟 4 — 決定監測模式。**
訊號線在該機台上 SNR 穩定 > 10 → `Ratio`（預設，能抵銷電漿條件漂移）。
訊號線先天很弱、SNR 徘徊在 5 附近 → `AbsoluteIntensity`（少一個雜訊來源，但不再抵銷漂移）。

**步驟 5 — 錄基準線並觀察一週。**
在**確定無洩漏**（剛做完檢漏）的狀態下 Capture Golden Run，先**不設嚴格門檻**，讓它跑一週，用 Ratio Review 看正常波動帶有多寬。

**步驟 6 — 依實測波動帶設定門檻。**
見 §7.4。**門檻要根據實測的雜訊帶決定，不要沿用預設值就上線。**

**步驟 7 — 用標準漏孔驗證，並存檔基準文件。**
通入已知漏率，確認：(a) 系統確實會報；(b) 報的時間延遲可接受；(c) 上升的是預期的那幾條比值。
驗證通過後，**截圖存檔該機台的「標準光譜」與「正常趨勢」**，作為日後 L1 巡檢的比對基準，並備份 `settings.json`。

### 7.2 依機台製程的選線指引

> ⚠️ 下表是**判斷原則的示範**，不是可直接套用的配方。每台機台的實際光譜必須現場確認後才可定案（步驟 5–7）。

| 製程類型 | 典型氣體 | 不可用作指標 | 建議指標 | 建議參考線 |
|---|---|---|---|---|
| PECVD SiN | SiH₄ / NH₃ / N₂ | N₂（製程本身就有大量 N） | **O 777、OH 309** | N₂ 337（背景穩定）或 Ar 750 |
| PECVD SiO₂（SiH₄+N₂O） | SiH₄ / N₂O | **O 與 N 都不可用** | **N₂⁺ 391 的相對變化**；必要時改用**升壓率／氦檢漏**輔助 | Ar 750（若有通 Ar） |
| PECVD SiO₂（TEOS+O₂） | TEOS / O₂ | O（製程供應） | **N₂ 337、N₂⁺ 391、NO 237** | Ar 750 或 O 777（此處 O 反而穩定） |
| 電漿蝕刻（氟碳系） | CF₄ / C₄F₈ / O₂ / Ar | O（常通 O₂）；**O 777 另有 SiF 干擾** | **N₂ 337、N₂⁺ 391** | **Ar 750／811（理想）** |
| 電漿蝕刻（氯系） | Cl₂ / BCl₃ / Ar | — | **O 777、N₂ 337、OH 309** | Ar 750／811 |
| 腔體清洗（NF₃ / 遠端電漿） | NF₃ / Ar | — | 清洗步驟通常**不建議納入監控**（化學劇烈變動） | — |
| 純惰性／氫氣製程 | Ar / H₂ | — | **O 777、OH 309、NO 237、N₂ 337 全可用**（最理想的監控情境） | Ar 750／811 |

**共通原則**：若某支配方**找不到任何乾淨的洩漏指標**（例如同時通 O₂ 與 N₂O 的製程），誠實的做法是**在該配方停用洩漏監控**（或只保留趨勢記錄不報警），改在**其他配方或待機／抽真空階段**做監控——而不是硬設一組會誤報的門檻。**待機抽真空時的空腔電漿是很好的檢漏窗口**，因為此時沒有製程氣體干擾。

### 7.3 已知譜線干擾清單

同一波長可能來自多個物種，選線與判讀時必須避開：

| 波長 | 可能來源 | 影響 |
|---|---|---|
| **777 nm** | **O 777.2** vs **SiF 777.0 / 777.9** | 含氟＋含矽製程（蝕刻、NF₃ 清洗）會讓 O 777 假性升高 |
| **308.9 nm** | **OH 308.9** vs **Cl₂ 308.9**、Al 308.2 | 氯系蝕刻、含鋁製程會干擾 OH 判讀 |
| **237 nm** | **NO 237.0** vs **SiO 234.4 / 238.8** 鄰近 | 含矽製程需確認峰形，必要時改用 NO 其他band head |
| **336–337 nm** | **N₂ 337.1** vs **NH 336.0** | 含 NH₃ 製程中兩者靠近，需足夠解析度 |
| **388 nm** | **N₂⁺ 388.4** vs **CN 388.3** | 有機污染或含碳製程會混淆 N₂⁺ 判讀 |
| **750.4 nm** | **Ar 750.4** vs **N₂ 750.4** | 目錄中兩物種同波長，選線時務必確認選到的是哪一個物種 |
| **427.8 nm** | **N₂ 427.8** vs **N₂⁺ 427.8** | 同上 |

> 判斷是否受干擾的實務方法：**在只通該製程氣體、確定無洩漏的狀態下看該峰是否存在**。
> 若存在，它就有背景，不適合當純粹的洩漏指標（或至少基準線要在同條件下錄）。

### 7.4 門檻設定建議

用 §7.1 步驟 5 觀察到的**實際波動帶**來設，而不是照抄預設值：

| 參數 | 預設 | 調整原則 |
|---|---|---|
| **Warn factor** | 1.2 | 設在「正常波動帶上緣」之上一點。實測波動若只有 ±3%，1.2 太鬆，可收到 1.10 |
| **Alarm factor** | 1.5 | 一般設為 Warn 的 1.5–2 倍幅度 |
| **Warn σ** | 3.0 | 雜訊大的比值靠 σ 這一路把關（系統取 factor 與 σ 兩者**較大者**） |
| **Alarm σ** | 6.0 | 同上 |
| **EMA τ** | 5 s | 訊號吵 → 加大（代價：反應變慢）。緩漏偵測可到 10–20 s |
| **Confirm time** | 15 s | **對付短暫尖峰誤報的第一選擇**——比調高門檻好，因為不犧牲靈敏度 |
| **Min SNR** | 5.0 | 弱線可略降但**絕不設 0**；設 0 等於關掉假警報保護 |
| **RequireTwoForAlarm** | 開 | 有 ≥2 條可靠指標線時保持開啟（大幅降低誤報）；只有 1 條時**必須關閉**，否則永不報警 |

**設完的驗收條件**：(a) 一週內誤報 0 次；(b) 標準漏孔測試必報；(c) 門檻線在 Ratio Review 上目視**明顯高於正常雜訊帶、明顯低於漏氣時的上升幅度**。

## 8. 異常升級與處置矩陣

| 等級 | 觸發條件 | 通報對象 | 時限 | 立即動作 |
|---|---|---|---|---|
| **L0 記錄** | 「觀察」條件 | 記入巡檢表 | — | 縮短巡檢間隔為每 4 小時 |
| **L1 通知** | 比值 > 120%、WARNING、LOW SIGNAL、新譜線出現 | 設備工程師 | 2 小時 | 保留現況、勿改設定；工程師執行 L2 |
| **L2 告警** | ALARM 橫幅、多條指標同步上升 | 設備工程師＋製程工程師＋領班 | **立即** | 依下方 ALARM 處置流程 |
| **L3 停機** | 洩漏率持續攀升、伴隨製程異常或膜質異常 | 加通報部門主管 | **立即** | 依廠內規定評估暫停投料、隔離 WIP |

### ALARM 發生時的處置流程

1. **記錄**狀態橫幅出現的時間、洩漏率讀值與 confidence、當時的配方與步驟。
2. **判定型態**——看哪幾條比值進了 ALARM：
   - **O／OH／NO（或 N₂⁺）同時上升** → 典型空氣洩漏，繼續步驟 3。
   - **只有單一條上升** → 優先懷疑譜線干擾或製程變化（對照 §7.3），仍需查證。
3. **回放確認**：到 **Ratio Review** 看這段時間是**持續上升**還是**短暫尖峰**。持續上升才是真事件。
4. **關聯比對**：與機台自身的真空度、壓力、RF 反射功率、腔體升壓率記錄交叉比對。
5. **實體檢查**：O-ring、法蘭、觀察窗、閥件、波紋管、feedthrough；必要時做**氦質譜檢漏**確認漏點。
6. **修復並驗證**：修復後跑一段製程，確認比值回到 100% 附近。
7. **清除鎖存**：確認排除後，按 **Acknowledge Alarm**（Operator+）。**警報是鎖存的，不會自己消失——這是刻意設計，不要用重開程式來「清警報」。**
8. **結案記錄**：填寫異常單，含根因、處置、驗證結果；若基準線在漏氣期間被人重錄過，**必須重新錄一次**。

> ⚠️ **絕對禁止**：以「調高門檻」「關閉該比值」「重錄 Golden Run」作為 ALARM 的處置手段。
> 這三個動作都會讓警報消失，但漏氣還在。任何一項若確有必要，須由工程師在**確認無洩漏之後**執行並記錄。

## 9. 事件驅動巡檢

以下事件發生後，**不等排程，立刻執行對應項目**：

| 事件 | 必做項目 |
|---|---|
| **PM／開腔／換 O-ring** | 實體檢漏合格後 → **重錄 Golden Run** → 觀察一班次 |
| **清潔觀察窗／更換光纖** | 檢查強度回升幅度 → **重錄 Golden Run**（強度變了，舊基準線無效） |
| **更改積分時間／平均設定** | **重錄 Golden Run**（曝光條件變了） |
| **換配方／新配方導入** | 切換 Baseline 至對應基準線（洩漏率校正會自動跟著切換）→ 按 **Reset Run** → 若無對應基準線則走 §7 全流程 |
| **更改 Ratio Setup / Wavelength Calibration** | 存檔後 **Stop → Start** 使其生效 → 確認生效 → **重錄 Golden Run** |
| **光譜儀更換／重新連接** | 確認 Serial 與 Test Mode → 波長查核（§6.3）→ 重錄 Golden Run |
| **軟體升級** | 備份 `settings.json` → 升級後確認比值設定與基準線都在 → 確認 Configuration 分頁的權限保護仍有效 |
| **發生過 ALARM 並修復** | 依 §8 步驟 6–8；確認修復後才可重錄基準線 |
| **連續兩班次被判「觀察」** | 升級為異常，執行完整 L2 |

## 12. 附錄 B：常見誤報原因

| 現象 | 原因 | 處置 |
|---|---|---|
| 製程步驟切換瞬間跳 WARNING | 氣體切換瞬態 | 加大 **Confirm time**（優先），或在該步驟不納入監控 |
| 每次點火／熄火時跳警報 | 電漿建立過程的化學瞬態 | 同上；確認 PlasmaPresentFloor 是否合適 |
| 週期性、固定時間出現 | 腔體清洗步驟、機台自動程序 | 確認是否應排除該步驟 |
| 單一比值頻繁跳動、其他不動 | 該譜線受干擾（§7.3）或訊號太弱 | 換譜線、或改 `AbsoluteIntensity` 模式 |
| 換班後開始頻繁警報 | 換了配方卻沒切 Baseline | 切換至正確基準線（L1 巡檢項 3-3） |
| PM 後全面偏高 | 基準線是 PM 前錄的（強度條件已變） | 檢漏合格後重錄 Golden Run |
| 長期穩定停在 110% 左右 | 基準線已不代表現況 | 確認無漏後重錄 |
| 雨季／濕度高時 OH 偏高 | 環境水氣經微漏進入 | 真實訊號，非誤報——查實體漏點 |
| 全部比值同時劇烈跳動 | 電漿不穩（功率／匹配器） | 通報製程，非洩漏 |
| 顯示 `Low Signal` 後就再也不報警 | 該比值已被排除在判定外 | **這是漏報風險，必須處理**（§6.2） |
