# Ratio Setup, emission lines and wavelength correction

Editing the ratio set, the line catalog and its user lines, and the catalog-level wavelength correction.

## `RatioSetupViewModel` + `RatioEditViewModel` + `RatioSetupPanel`

Ratio Setup tab: a staged editor for the species-ratio configuration. Up to `RatioSetupViewModel.MaxRatios` (10) ratios, reordered with ▲/▼ (`MoveUpCommand`/`MoveDownCommand` — row N is SECS slot N, and a move keeps the row object, so its key and with it the baseline, calibration and any latch carry over, which delete-and-re-add would not; `RatioSetupReorderTests`); each picks a signal and a reference line (species + wavelength) from the species-grouped `SpectralLineCatalog`, plus per-ratio extraction mode (`PeakHeight` / `Integral` / `RawMean`) and alarm thresholds. Each entry also has a **monitoring method** (`RatioDefinition.MonitorMode`): `Ratio` (signal ÷ reference — the actinometric default) or `AbsoluteIntensity`, where the monitored quantity is the signal line's absolute baseline-subtracted intensity and **the reference line is not used at all** (see `PlasmaGate` in `leak-engine.md`; the picker is hidden in that mode). Absolute mode is for weak/near-noise lines where the ratio of two small numbers swings wildly — dropping the reference division removes one noise source — at the cost of no longer cancelling plasma-condition drift (so it needs a stable operating point and more frequent re-baselining). The mode branches the monitored value in `RatioMonitor.Update` and the Golden-Run / calibration-point accumulation in `LeakMonitorEngine`; everything else (Golden Run baseline, σ thresholds + live-σ widening, SNR gate, state machine) is shared across both modes. **Pedestal handling — keyed on `RatioDefinition.ValueHasPedestal` (a `RawMean` numerator, in *either* monitor mode), not on the monitor mode.** A value carrying the continuum pedestal compresses everything defined as *(value ÷ baseline)* into a fraction of a percent, so those quantities switch to σ units: (a) the **% -of-baseline trend** plots a σ-normalized score `100 + (20/SigmaWarn)·(ema − baseMean)/EffectiveSigma` (`RatioMonitor.PercentOfBaselineDisplay` — baseline stays at 100, one warn-σ above lands at 120, so the shared 100/120/150 guide lines still hold) and the per-row slope reads in σ/min; (b) the **leak-rate calibration** fits and inverts the *absolute* rise `Δ = value − baseMean` (σ straight from the EWMA scatter, no division), stamped by `RatioSensitivity.Absolute` and supplied by `LeakMonitorEngine.CurrentValueUnits()`; (c) the Warn/Alarm **factors** are ignored. Everything else — a baseline-subtracted line in either mode, whose mean *is* the signal — keeps the honest `ema/baseMean·100` and the fractional rise, which is also immune to a pure re-scaling. **Dividing by a reference line does not remove the pedestal**, which is what the predicate used to assume: `(pedestal + line) / reference` is the same affine offset scaled by `1/reference`, so the fraction-of-baseline is compressed exactly as in absolute mode. It went unnoticed because nothing looks wrong — `Math.Max` just takes the multiplicative branch instead, and it wins once `mean/σ > SigmaWarn/(WarnFactor−1)`, i.e. past 60 at the factory 1.05/1.12. Measured on one machine, `N₂ 337.1 RawMean / Ar 750.4` at mean/σ ≈ 119 was warning at 5.9 σ and alarming at 14.2 σ against a configured 3/6. Widening the predicate re-judges such ratios without touching their stored baselines (the monitored value is unchanged, and `Mode`/`ReferenceLabel`/`ExtractionRevision` are what a baseline is matched on) — but it does loosen their thresholds, and it flips their leak-rate unit, so a calibration fitted against the fractional rise is refused until re-fitted. `RatioPedestalTests` pins both branches. A fit is rejected if that unit changed since calibration (`LeakRateEstimator.Estimate`, same spirit as the reference-label gate), which is what invalidates every pre-existing absolute-mode calibration on upgrade. Save persists into `LeakMonitorSettings.Ratios` in `settings.json` (same file as the Configuration tab), gated to Engineer+. Edits are **staged** — they take effect only when OES acquisition restarts: `MainViewModel` watches `DeviceViewModel.IsAcquiring` and, on a Stop→Start transition, calls `LeakMonitorEngine.ReloadRatios()`, which rebuilds the monitors and raises `RatiosReloaded` (the Leak Monitor tab rebuilds its rows in response). **Latched alarms survive that rebuild**: `ReloadRatios` snapshots which keys were latched, then re-arms each one whose definition still `MeasuresSameAs` the old (same mode, same monitored line, same reference in ratio mode — thresholds and smoothing deliberately excluded, since retuning a threshold doesn't change what is measured) and logs `LeakMonitorAlarmLatchDropped` for the rest. Without it, restarting acquisition cleared every confirmed leak without an Acknowledge, which is exactly what happened twice in a real run; `_overall` is recomputed rather than forced to `Idle` so a carried-over latch still reads Alarm immediately. `RatioEditViewModel` reuses an untouched line's original `LineRegion` so editing one ratio never re-labels another. Each line-picker entry is a `SpectralLineOption` (catalog line + its current wavelength offset), so a line carrying a correction shows `+0.20 nm → 777.4 nm` beside its species and wavelength — in the dropdown and in the closed combo. The offsets are display-only; `RatioSetupViewModel.RefreshCorrections` re-reads them in place (leaving unsaved ratio edits alone) when `WavelengthCorrectionViewModel` raises `CorrectionsSaved`. Because several species share a wavelength (Ar and N2 both list 750.4 nm), a saved region is matched back to its catalog line by the species in its `Label` first, falling back to the globally nearest wavelength. The Leak Monitor tab is therefore display-only for ratio config (no live reference/enable controls).

## `LinePickerViewModel`

the **emission-line picker on the Configuration tab**, filling the logger's `TriggerWavelength` and `MonitoredWavelengthsText` from the catalog instead of from memory. `LoggerPanel` is a framework (`Aqst.OesApp.Wpf`) control that knows nothing about emission lines, and `SpectralLineCatalog` is defined here, so the picker sits beside the panel and writes into the same properties a hand-typed value would — **an input aid that owns no state**, which is why there is no second copy of the setting to drift out of step (a checkbox-list design would have had to answer "what does a hand-typed 250.3 look like when it matches no line"). It writes the **catalog** wavelength, never the corrected one: a recorder holding `777.4` would match neither the catalog nor the correction table after someone retuned the offset, so the correction is named in the hint text instead. Setting a trigger while `TriggerMode` is a whole-frame mode writes the value and *says* triggering won't use it rather than switching the mode — percentile mode is chosen deliberately. Adding a monitored line skips duplicates (±0.05 nm) and notes when the list passes `WavelengthTrendViewModel.MaxMonitoredWavelengths`, since the CSV takes every entry as a column while the trend chart draws the first five — capping the list would make wanting eight columns cost the chart. `SpectralLineOption.Display` exists for this picker; the Ratio Setup combos template the parts themselves.

## `UserSpectralLine` + `SpectralLineTableViewModel`

the **emission-line table** at the top of the Wavelength Calibration tab. `SpectralLineCatalog.BuiltIn` is fixed and read-only (it is the shared reference; editing it would make two tools' configurations incomparable); `SetUserLines` layers the site's own lines over it, and `All` / `Species` are recomputed from both. A user species always carries the `u` prefix (`SpectralLineCatalog.UserPrefix`), **applied by the editor rather than typed** — the operator enters `N2`, the row stores `uN2` — so a user line can never collide with or shadow a built-in one, and a ratio label, Golden Run `ReferenceLabel` or CSV column header that came from one says so on its face. Reusing a built-in species name is allowed and expected (`uN2` beside `N2` is the "the built-in N₂ lines don't include mine" case). Stored in `LeakMonitorSettings.UserSpectralLines` — in `settings.json`, not a file of its own, because a ratio can reference a user line and the manual promises that one file is a machine's whole configuration. **Removing or moving a line a ratio or correction references is refused**: nothing visible would break today (a `RatioDefinition` holds its own region copy), but the next Ratio Setup open would fail to match the missing species, fall back to the nearest wavelength and silently re-point that ratio — with no signal at the deletion and none later. CSV import is **merge-only** (skips what is already there, never removes), which is what makes it exempt from that same check; export writes the user lines alone. Saving takes effect **immediately** — a catalog line is not something the running engine computes with — so it has its own Save button separate from the staged correction table below it, and `MainViewModel` pushes it into the Ratio Setup pickers via `RatioSetupViewModel.RefreshLineCatalog()` rather than making the operator restart acquisition to find out.

## `WavelengthCorrection` + `WavelengthCalibration` + `WavelengthCorrectionViewModel` + `WavelengthCorrectionPanel`

Wavelength Calibration tab: a staged editor for a **catalog-level wavelength-drift correction overlay**. Each row corrects one catalog `(species, wavelength)` emission line by an additive offset (nm), stored sparsely in `LeakMonitorSettings.WavelengthCorrections` (only corrected lines are persisted; everything else uses offset 0). Because the key is the catalog `(species, wavelength)`, a single correction re-aligns **every** ratio (signal *or* reference) that uses that line — unlike the earlier per-ratio-line approach (reverted `e03f47a`) that stored the offset on each `LineRegion` separately. `WavelengthCalibration` (pure, no engine/UI deps) builds a `(species, wavelength) → offset` lookup and applies it at monitor-build time: in the `LeakMonitorEngine` constructor and `ReloadRatios`, each `RatioDefinition` is replaced in `_defs` (and its `RatioMonitor`) by a **corrected clone** whose region `CenterNm` is shifted, while `_settings.Ratios` keeps the raw catalog wavelength — so the correction reaches extraction (and thus Golden Run capture, calibration, SNR, CSV logging, all of which read `_defs`) but never leaks back into `settings.json`. Region→catalog matching keys on the region `Label`'s leading species token + `CenterNm`, with a small alias map folding the reference-preset labels (`"N₂"→"N2"`, `"Hα"→"H"`) back to catalog species. Save is gated to Engineer+, validates the offset range (±`MaxOffsetNm` = 5 nm) and rejects duplicate `(species, wavelength)` rows, and — like every Ratio Setup edit — is **staged**: it takes effect only on the next OES acquisition restart (`ReloadRatios`). Note this correction is deliberately distinct from `LineRegion.PeakSearchHalfWidthNm`, which already re-centers ±1 nm on the local peak each frame; the overlay is for larger axis drift or when the wrong peak sits inside that search window.
