# Ratio Setup, emission lines and wavelength correction

Editing the ratio set, the line catalog and its user lines, and the catalog-level wavelength correction.

## `RatioSetupViewModel` + `RatioEditViewModel` + `RatioSetupPanel`

Ratio Setup tab: a staged editor for the species-ratio configuration. Up to `RatioSetupViewModel.MaxRatios` (10) ratios, reordered with ▲/▼ (`MoveUpCommand`/`MoveDownCommand` — row N is SECS slot N, and a move keeps the row object, so its key and with it the baseline, calibration and any latch carry over, which delete-and-re-add would not; `RatioSetupReorderTests`); each picks a signal and a reference line (species + wavelength) from the species-grouped `SpectralLineCatalog`, plus per-ratio extraction mode (`PeakHeight` / `Integral` / `RawMean`) and alarm thresholds. Each entry also has a **monitoring method** (`RatioDefinition.MonitorMode`): `Ratio` (signal ÷ reference — the actinometric default) or `AbsoluteIntensity`, where the monitored quantity is the signal line's absolute baseline-subtracted intensity and **the reference line is not used at all** (see `PlasmaGate` in `leak-engine.md`; the picker is hidden in that mode). Absolute mode is for weak/near-noise lines where the ratio of two small numbers swings wildly — dropping the reference division removes one noise source — at the cost of no longer cancelling plasma-condition drift (so it needs a stable operating point and more frequent re-baselining). The mode branches the monitored value in `RatioMonitor.Update` and the Golden-Run / calibration-point accumulation in `LeakMonitorEngine`; everything else (Golden Run baseline, σ thresholds + live-σ widening, SNR gate, state machine) is shared across both modes. **Pedestal handling — keyed on `RatioDefinition.ValueHasPedestal` (a `RawMean` numerator, in *either* monitor mode), not on the monitor mode.** A value carrying the continuum pedestal compresses everything defined as *(value ÷ baseline)* into a fraction of a percent, so those quantities switch to σ units: (a) the **% -of-baseline trend** plots a σ-normalized score `100 + (20/SigmaWarn)·(ema − baseMean)/EffectiveSigma` (`RatioMonitor.PercentOfBaselineDisplay` — baseline stays at 100, one warn-σ above lands at 120, so the shared 100/120/150 guide lines still hold) and the per-row slope reads in σ/min; (b) the **leak-rate calibration** fits and inverts the *absolute* rise `Δ = value − baseMean` (σ straight from the EWMA scatter, no division), stamped by `RatioSensitivity.Absolute` and supplied by `LeakMonitorEngine.CurrentValueUnits()`; (c) the Warn/Alarm **factors** are ignored. Everything else — a baseline-subtracted line in either mode, whose mean *is* the signal — keeps the honest `ema/baseMean·100` and the fractional rise, which is also immune to a pure re-scaling. **Dividing by a reference line does not remove the pedestal**, which is what the predicate used to assume: `(pedestal + line) / reference` is the same affine offset scaled by `1/reference`, so the fraction-of-baseline is compressed exactly as in absolute mode. It went unnoticed because nothing looks wrong — `Math.Max` just takes the multiplicative branch instead, and it wins once `mean/σ > SigmaWarn/(WarnFactor−1)`, i.e. past 60 at the factory 1.05/1.12. Measured on one machine, `N₂ 337.1 RawMean / Ar 750.4` at mean/σ ≈ 119 was warning at 5.9 σ and alarming at 14.2 σ against a configured 3/6. Widening the predicate re-judges such ratios without touching their stored baselines (the monitored value is unchanged, and `Mode`/`ReferenceLabel`/`ExtractionRevision` are what a baseline is matched on) — but it does loosen their thresholds, and it flips their leak-rate unit, so a calibration fitted against the fractional rise is refused until re-fitted. `RatioPedestalTests` pins both branches. A fit is rejected if that unit changed since calibration (`LeakRateEstimator.Estimate`, same spirit as the reference-label gate), which is what invalidates every pre-existing absolute-mode calibration on upgrade. Save persists into `LeakMonitorSettings.Ratios` in `settings.json` (same file as the Configuration tab), gated to Engineer+. Edits are **staged** — they take effect only when OES acquisition restarts: `MainViewModel` watches `DeviceViewModel.IsAcquiring` and, on a Stop→Start transition, calls `LeakMonitorEngine.ReloadRatios()`, which rebuilds the monitors and raises `RatiosReloaded` (the Leak Monitor tab rebuilds its rows in response). **Latched alarms survive that rebuild**: `ReloadRatios` snapshots which keys were latched, then re-arms each one whose definition still `MeasuresSameAs` the old (same mode, same monitored line, same reference in ratio mode — thresholds and smoothing deliberately excluded, since retuning a threshold doesn't change what is measured) and logs `LeakMonitorAlarmLatchDropped` for the rest. Without it, restarting acquisition cleared every confirmed leak without an Acknowledge, which is exactly what happened twice in a real run; `_overall` is recomputed rather than forced to `Idle` so a carried-over latch still reads Alarm immediately. **Line windows (#88).** `RatioEditViewModel` keeps one working `LineRegion` per side, starting as a verbatim clone of the loaded region, and `ToDefinition` writes it back as is. It changes only when the operator changes that side's line (→ `LineWindowAdvice.Defaults` for the mode and current pixel pitch, #125), its mode (`WithMode`: half-width, gap and width kept; search 0 for RawMean, `LineWindowAdvice.PeakSearchNm` when leaving RawMean) or one of the four window fields (`Signal…Nm` / `Reference…Nm`, validated at Save by `WindowError`: half-width ≥ 0 and > 0 unless RawMean, gap ≥ 0, width > 0, search ≥ 0, each ≤ `MaxWindowNm` 20). It used to rebuild every region on Save through `RegionFor`, keeping the original only when the picked catalog wavelength equalled `CenterNm` exactly — so a tuned region on a non-catalog centre (`MatchLine` resolves to the *nearest* catalog line of the species: NO 235.6 → NO 237, OH 308.8 → OH 308.9) was reset to factory windows by **any** save, edited or not, with nothing on screen. The lab machine's fix was a user line at the exact centre (`uNO 235.6`), which is now unnecessary but harmless. The line setters compare species + wavelength rather than the option instance, so a picker rebinding to a rebuilt catalog list does not count as a new line. **Asymmetric baseline windows (#112).** `LineRegion.RightBaselineGapNm` / `RightBaselineWidthNm` are nullable; null means "mirror the left", and `BaselineGapNm` / `BaselineWidthNm` are then the left side. The keys (`MeasurementKey`, `WindowKey`) and `MeasuresSameAs` append the right side only when one is set, so a symmetric region keeps the exact key a Golden Run recorded before the field existed — the upgrade costs no baseline. The editor's `SignalSeparateRight` / `ReferenceSeparateRight` checkbox seeds the right side from the left when ticked and writes nulls when unticked; a new line resets it (fresh `LineWindowAdvice.Defaults`), a mode change keeps it (`WithMode` clones). `LineIntensityExtractor.Layout` is the one place the windows are placed (peak-search re-centring included), shared by `Extract` and the preview. **Pixel-based windows (#125).** The spectrometer axis steps 0.6 nm, so the old ±0.5 nm default covered one pixel. `LineWindowAdvice` (pure; `PixelWindowTests`) holds the minimum pixel counts — PeakHeight/RawMean signal 5, baseline width 3, gap 2, peak search 2 — and converts them with the pitch (`PitchOf`, median axis spacing; `FallbackPitchNm` 0.6). Regions stay in nm, so `WindowKey` and the settings schema are unchanged. Two deliberate holes: an **Integral signal window has no minimum** (new lines start at ±1.0 nm) because widening the tuned NO 235.6 / OH 308.8 bands to 7 pixels cut their DV=300 step SNR by 25–35 % on the 11/19 recordings — the extra pixels do not respond to the leak, and plasma flicker, not pixel noise, dominated the ratio noise either way; and a **peak search of 0 is a pinned window**, not a narrow one. `RatioEditViewModel` takes a pitch provider (`RatioSetupViewModel` passes `LinePreviewViewModel.PitchNm`, the shown or newest live frame; `PitchChanged` refreshes every row), shows `…CoverageText` / `…CoverageWarning` per side, and `ApplySuggestedWidthsCommand` raises only the too-narrow windows of both sides through the working regions, so Save's `BaselinesInvalidatedBy` and the engine's `WindowKey` check treat it like a hand edit. Existing ratios are never migrated. `LinePreview` adds the same warning. The factory ratios and `ReferenceLineCatalog` presets meet the minimums; `PixelWindowTests` also checks they overlap no catalogue line, with an explicit allow-list for what no placement can avoid (Ar 750.4 vs Cl 754.7; N₂ 357.7 in dense band structure). `LabLeakTest20261119Tests.Pixel_based_windows_lower_noise_without_losing_the_leak_step` (needs the recordings) prints old vs new noise and step SNR per ratio and fails if either is worse by more than 2 %. **Line preview (#112).** `LinePreview.Compute` (pure; `LinePreviewTests`) takes a frame, a region and the line catalogue and returns the placed windows, the shift, the engine's own reading, the zoom range and warnings (< 2 pixels in a window, a window off the spectrum, a baseline window over another catalogue line outside the line's own signal/search span). `LinePreviewViewModel` picks the frame — the newest live one (`MainViewModel.FanOutSpectrum` hands it every effective frame; the panel's 1 s `DispatcherTimer` draws it unless frozen) or a frame of a parsed recording (`Recording.FromArchive` for a zip, `RecordingCsvParser.ReadFull` off the UI thread) — applies the wavelength corrections exactly as the engine does, and redraws on any `PropertyChanged` of the selected row, so it shows unsaved edits. `SpectralLineOption.ToString` returns `Display`, which also gives the line pickers' items a UI Automation name (run-app's `combo` can select them). Save also lists, via `BaselinesInvalidatedBy`, the ratios whose `WindowKey` changed while the active Golden Run holds a baseline for them — the same comparison the engine's acceptance makes (`leak-engine.md`). Each line-picker entry is a `SpectralLineOption` (catalog line + its current wavelength offset), so a line carrying a correction shows `+0.20 nm → 777.4 nm` beside its species and wavelength — in the dropdown and in the closed combo. The offsets are display-only; `RatioSetupViewModel.RefreshCorrections` re-reads them in place (leaving unsaved ratio edits alone) when `WavelengthCorrectionViewModel` raises `CorrectionsSaved`. Because several species share a wavelength (Ar and N2 both list 750.4 nm), a saved region is matched back to its catalog line by the species in its `Label` first, falling back to the globally nearest wavelength. The Leak Monitor tab is therefore display-only for ratio config (no live reference/enable controls).

**Judging block (#95).** Under Alarm thresholds, per ratio: *Golden Run baseline* (`GoldenRunJudging`), *Rolling baseline (step)* (`StepJudging`) and its Warn / Alarm rise in percent (stored as fractions, `StepWarnRise` / `StepAlarmRise`). Save refuses an alarming entry with neither path running — the message points to the TrendOnly role, which is how an entry is recorded without being judged — and step rises that do not put Alarm at or above a positive Warn (`RatioEditViewModel.JudgingError`). Step is unavailable for a raw (`RawMean`) reading, which carries the pedestal (`StepAvailable`, mirroring `RatioDefinition.StepJudgingActive`), so such an entry needs the Golden Run path. With step as the only path the Golden Run factor / σ boxes are disabled but keep their values (`GoldenRunFieldsEnabled`). **The four fields are carried through `ToDefinition` for every row**, edited or not, and are independent of `RegionFor`: a save that rebuilds a line region (#88) must not touch them, and `RatioSetupJudgingTests` holds that. The global step windows (`stepLookbackSeconds` and friends) are `settings.json`-only, like `requireTwoForAlarm`.

## `LinePickerViewModel`

the **emission-line picker on the Configuration tab**, filling the logger's `TriggerWavelength` and `MonitoredWavelengthsText` from the catalog instead of from memory. `LoggerPanel` is a framework (`Aqst.OesApp.Wpf`) control that knows nothing about emission lines, and `SpectralLineCatalog` is defined here, so the picker sits beside the panel and writes into the same properties a hand-typed value would — **an input aid that owns no state**, which is why there is no second copy of the setting to drift out of step (a checkbox-list design would have had to answer "what does a hand-typed 250.3 look like when it matches no line"). It writes the **catalog** wavelength, never the corrected one: a recorder holding `777.4` would match neither the catalog nor the correction table after someone retuned the offset, so the correction is named in the hint text instead. Setting a trigger while `TriggerMode` is a whole-frame mode writes the value and *says* triggering won't use it rather than switching the mode — percentile mode is chosen deliberately. Adding a monitored line skips duplicates (±0.05 nm) and notes when the list passes `WavelengthTrendViewModel.MaxMonitoredWavelengths`, since the CSV takes every entry as a column while the trend chart draws the first five — capping the list would make wanting eight columns cost the chart. `SpectralLineOption.Display` exists for this picker; the Ratio Setup combos template the parts themselves.

## `UserSpectralLine` + `SpectralLineTableViewModel`

the **emission-line table** at the top of the Wavelength Calibration tab. `SpectralLineCatalog.BuiltIn` is fixed and read-only (it is the shared reference; editing it would make two tools' configurations incomparable); `SetUserLines` layers the site's own lines over it, and `All` / `Species` are recomputed from both. A user species always carries the `u` prefix (`SpectralLineCatalog.UserPrefix`), **applied by the editor rather than typed** — the operator enters `N2`, the row stores `uN2` — so a user line can never collide with or shadow a built-in one, and a ratio label, Golden Run `ReferenceLabel` or CSV column header that came from one says so on its face. Reusing a built-in species name is allowed and expected (`uN2` beside `N2` is the "the built-in N₂ lines don't include mine" case). Stored in `LeakMonitorSettings.UserSpectralLines` — in `settings.json`, not a file of its own, because a ratio can reference a user line and the manual promises that one file is a machine's whole configuration. **Removing or moving a line a ratio or correction references is refused**: nothing visible would break today (a `RatioDefinition` holds its own region copy), but the next Ratio Setup open would fail to match the missing species, fall back to the nearest wavelength and silently re-point that ratio — with no signal at the deletion and none later. CSV import is **merge-only** (skips what is already there, never removes), which is what makes it exempt from that same check; export writes the user lines alone. Saving takes effect **immediately** — a catalog line is not something the running engine computes with — so it has its own Save button separate from the staged correction table below it, and `MainViewModel` pushes it into the Ratio Setup pickers via `RatioSetupViewModel.RefreshLineCatalog()` rather than making the operator restart acquisition to find out.

## `WavelengthCorrection` + `WavelengthCalibration` + `WavelengthCorrectionViewModel` + `WavelengthCorrectionPanel`

Wavelength Calibration tab: a staged editor for a **catalog-level wavelength-drift correction overlay**. Each row corrects one catalog `(species, wavelength)` emission line by an additive offset (nm), stored sparsely in `LeakMonitorSettings.WavelengthCorrections` (only corrected lines are persisted; everything else uses offset 0). Because the key is the catalog `(species, wavelength)`, a single correction re-aligns **every** ratio (signal *or* reference) that uses that line — unlike the earlier per-ratio-line approach (reverted `e03f47a`) that stored the offset on each `LineRegion` separately. `WavelengthCalibration` (pure, no engine/UI deps) builds a `(species, wavelength) → offset` lookup and applies it at monitor-build time: in the `LeakMonitorEngine` constructor and `ReloadRatios`, each `RatioDefinition` is replaced in `_defs` (and its `RatioMonitor`) by a **corrected clone** whose region `CenterNm` is shifted, while `_settings.Ratios` keeps the raw catalog wavelength — so the correction reaches extraction (and thus Golden Run capture, calibration, SNR, CSV logging, all of which read `_defs`) but never leaks back into `settings.json`. Region→catalog matching keys on the region `Label`'s leading species token + `CenterNm`, with a small alias map folding the reference-preset labels (`"N₂"→"N2"`, `"Hα"→"H"`) back to catalog species. Save is gated to Engineer+, validates the offset range (±`MaxOffsetNm` = 5 nm) and rejects duplicate `(species, wavelength)` rows, and — like every Ratio Setup edit — is **staged**: it takes effect only on the next OES acquisition restart (`ReloadRatios`). Note this correction is deliberately distinct from `LineRegion.PeakSearchHalfWidthNm`, which already re-centers ±1 nm on the local peak each frame; the overlay is for larger axis drift or when the wrong peak sits inside that search window.
