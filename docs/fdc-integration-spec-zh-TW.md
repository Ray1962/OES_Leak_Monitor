# OES Leak Monitor × FDC 整合規格（PM3）

> **對象：** 廠內 FDC 系統的開發與維運人員。
> **目的：** 說明 FDC 要如何連上 PM3 的 OES Leak Monitor、讀哪些資料、怎麼判讀、怎麼知道每筆資料屬於哪個製程，以及第一階段要記錄與通知什麼。
> **第一階段範圍：** **只記錄與通知**，不扣貨、不 Hold 腔體、不對設備下任何命令。
> **FDC 是 OES 唯一的 SECS host。** 主機台的製程事件不經過 FDC：EAP 以 TCP 直接轉送給 OES（`eap-tool-event-tcp-spec-zh-TW.md`），OES 再把目前的製程視窗以 VID 030／031 報給 FDC（第 6 節）。
> **依據：** `Satellite_SECS_Specification_v2.md`（欄位語意）、`secs-integration.md`（設備端實作）、`EAP ceid-events.md`（主機台 CEID 表）。三者與本文衝突時，以前兩份為準，並回頭修正本文。
> **沿革：** 本文原為給 EAP 平台的 `eap-integration-spec-zh-TW.md`。2026-10-26 確認現場 OES 的 SECS host 是 FDC，改寫為本文；原本「EAP 以 S2F41 `TOOL_EVENT` 轉送製程事件」的做法改成上述 TCP 連線。

## 1. 系統配置

```
┌──────────────┐  SECS（既有）  ┌──────────────┐
│   Tool PC    │──────────────▶│     EAP      │
│  (PM2／PM3)  │   EAP = host  │              │
└──────────────┘               └──────▲───────┘
                                      │ TCP：主機台製程事件（EVT／HB）
                                      │ OES 主動連入，見 eap-tool-event-tcp-spec
┌──────────────┐  SECS（本規格）┌──────┴───────┐
│     FDC      │──────────────▶│    OES PC    │
│              │   FDC = host  │  只看 PM3    │
└──────────────┘               └──────────────┘
```

- **OES Leak Monitor 是一台獨立的 SECS 設備**，有自己的 HSMS 連線，和主機台的連線無關。
- **FDC 是它唯一的 host。** HSMS-SS 一條連線只能有一個 host，EAP 不會、也無法連進這條連線。
- **只裝在 PM3。** 製程資訊只有一條來源：主機台 → EAP → OES。FDC 不需要自己收主機台的 CEID，讀 OES 的 VID 030／031 就知道 PM3 在跑哪個製程（第 6 節）。
- OES 不知道批次、配方、晶圓；它只看光譜。**把洩漏和批次接起來是 FDC 的工作**（第 6 節）。

## 2. 連線參數

| 項目 | 值 | 說明 |
|---|---|---|
| 協定 | HSMS-SS（SECS-II over TCP/IP） | |
| 連線模式 | **OES = Passive（監聽）、FDC = Active（主動連入）** | |
| IP／Port | 依現場設定，預設 port 5000 | 由設備工程師在 OES 的 SECS 分頁設定，交給 FDC 方。**不是** EAP TCP 連線用的 port |
| Device ID | 依現場設定 | HSMS 交握不檢查 Device ID；填錯要到資料訊息才會收到 S9F1 |
| T3／T5／T6／T7／T8 | 45／10／10／10／10 秒（預設） | FDC 有指定值時，雙方一起改 |
| 機台號 `cc` | **03**（待現場確認，見第 10 節） | 決定所有 SVID／ALID／CEID 的第 2～3 碼 |

> 兩端都會主動送 S1F13，日誌中看到兩次是正常的。OES 端每 10 秒重試一次，直到 FDC 回 COMMACK = 0。

## 3. 連線後的初始化順序

每次建立通訊（包括斷線重連）都要完整跑一次。下表每一項都已確認設備端支援。

| 步驟 | 訊息 | 目的 |
|---|---|---|
| 1 | S1F13 → S1F14 | 建立通訊 |
| 2 | S1F1 → S1F2 | 確認型號與軟體版本 |
| 2a | S1F17 → S1F18 | 依 FDC 慣例要求 ON-LINE（設備端支援；ONLACK 0 = 接受、2 = 已在線上，兩者皆可） |
| 3 | S2F31 → S2F32 | 對時（見下方注意） |
| 4 | S1F11 → S1F12 | 讀 SVID 名單，和第 4.1 節比對（全域 32 項 + 槽位 250 項）；**缺項要告警**，不要默默略過 |
| 5 | S5F5 → S5F6 | 讀警報清單，應有 5 條，ALID 為 ASCII |
| 6 | S5F3 → S5F4 | 啟用全部警報 |
| 7 | S2F43 → S2F44 | **開啟 S5、S6 的暫存（spooling）**，斷線期間的警報與事件才不會遺失 |
| 8 | S2F33 → S2F35 → S2F37 | 定義報告、連到 CEID、啟用事件（第 4.3 節） |
| 9 | S2F23 → S2F24 | 訂閱 Trace（第 4.1 節） |
| 10 | S6F23 → S6F24 | 取回斷線期間暫存的訊息 |
| 11 | S1F3 → S1F4 | 讀一次 VID 007／010／016／030／031，重建目前狀態與製程視窗（規則 R6、R9） |
| 11a | S1F3 → S1F4 | 讀 10 個槽位的位移 16～25，建立「槽位號 → Key」對照（規則 R11、R12）。重連後也要讀——斷線期間可能錯過 CEID 507 |

> **對時的注意事項：** S2F31 只會設定 OES 回報給 Host 的 SECS 時鐘，**不會改 OES PC 的系統時間**。OES 寫的 CSV 與日誌用的是 PC 時鐘，所以 **OES PC 要另外接廠內 NTP**，否則事後拿 CSV 和 FDC 的紀錄對時會對不上。

## 4. 使用的識別碼

以下 `cc = 03`。SVID 為 `10327000vv`、ALID 為 `10327nnn`、CEID 為 `10327nnn`。

### 4.1 SVID（狀態變數）

**Trace 訂閱建議：** 每 10 秒取樣（DSPER `"000010"`），每 6 筆回報一次。

| VID | SVID | 項目 | 型別 | Trace | 用途 |
|---|---|---|---|---|---|
| 001 | `1032700001` | Leak rate（mbar·L/s） | F4 | ✔ | 漏率，**須搭配 004** |
| 004 | `1032700004` | Leak rate valid | U4 | ✔ | 001 是否有效 |
| 006 | `1032700006` | Calibration status | U4 | | 0 未校正／1 有效／2 基準不符 |
| 007 | `1032700007` | Composite leak level | U4 | ✔ | 0 Idle／1 Normal／2 Warning／3 Alarm |
| 009 | `1032700009` | Warning ratio count | U4 | | 判讀細節 |
| 010 | `1032700010` | Alarm ratio count | U4 | | 判讀細節 |
| 011 | `1032700011` | Low-signal ratio count | U4 | | 判讀細節 |
| 013 | `1032700013` | Active Golden Run name | A | | 現用基準名稱 |
| 015 | `1032700015` | Acquisition mismatch | U4 | ✔ | 1 = 基準已不適用 |
| 016 | `1032700016` | Test / replay mode | U4 | ✔ | **1 = 不是實機量測** |
| 021 | `1032700021` | Plasma present | U4 | ✔ | 1 = OES 判定電漿開啟 |
| 027 | `1032700027` | Process class | A | ✔ | 製程類別。製程事件生效時（030 = 2 或 3）由事件決定，否則為 OES 從光譜判定的結果 |
| 028 | `1032700028` | Process class state | U4 | ✔ | 027 的有效性，見規則 R8 |
| 029 | `1032700029` | Process step index | U4 | | 電漿步驟累計序號 |
| 030 | `1032700030` | Tool event context state | U4 | ✔ | OES 依據的製程視窗狀態：0 未使用、1 狀態不明、2 在視窗內、3 不在任何視窗內，見規則 R9 |
| 031 | `1032700031` | Tool event window class | A | ✔ | 目前視窗的類別（`A`／`B`）；030 ≠ 2 時為空字串 |
| 032 | `1032700032` | Last tool CEID | U4 | | OES 最後收到的主機台 CEID（EAP 經 TCP 轉送）；用來確認 EAP 的轉送確實到達（6.5） |

完整的 VID 001～032 定義見 `Satellite_SECS_Specification_v2.md` §1.4(a)；數值範例見 `secs-global-vid-example-zh-TW.html`。

**比值槽位 VID 101～400。** 每組比值（OES 的 Ratio Setup 第 N 列，N = 1～10）佔 30 個號碼：

```
SVID = 1032700000 + 100 + (N − 1) × 30 + 位移        （cc = 03）
例：槽位 2 的位移 03 = 1032700133；槽位 1 的位移 25 = 1032700125
```

| 位移 | 項目 | 型別 | Trace | 用途 |
|---|---|---|---|---|
| 03 | Percent of baseline / σ score | F4 | ✔ | 該比值偏離基準多少；**單位看 18**（規則 R10） |
| 05 | Ratio state | U4 | ✔ | 0 Normal、1 Warning、2 Alarm、3 NoPlasma、4 LowSignal、5 NoBaseline、6 Disabled、7 Observing、8 NotApplicable |
| 14／15 | Ratio leak rate／Used in fusion | F4／U4 | | 只由該比值推得的漏率；15 = 0 時 14 不採用 |
| 16 | Slot enabled | U4 | | 1 = 啟用 |
| 18 | Value semantics | U4 | | 0 = 03 是基準百分比、1 = σ 分數 |
| 20／23 | Signal wavelength／species | F4／A | | 在看哪條譜線（例：337.1 nm、`N2`） |
| 22 | Slot display name | A | | 給人看的名稱；非 ASCII 字元會變成 `?`（例：`N? 337 / Ar 750`） |
| 25 | Ratio key | A | | **不變的識別碼**，用來追蹤同一組比值（規則 R12）；空字串 = 空槽位 |

其餘位移（01～02、04、06～13、17、19、21、24）見規格 §1.4(b)。沒有值時 F4 一律送 0、不送 NaN（規則 R13）。Trace 建議只訂閱啟用槽位的 03 與 05；10 個槽位全訂是 20 項，仍在一般 Trace 的負荷內。

### 4.2 ALID（警報）

S5F1 的 ALID 以 **ASCII** 送出（`<A[8] "10327002">`）。ALCD bit7 = 1 為發生、0 為解除。

| ALID | 警報 | 第一階段處理 |
|---|---|---|
| `10327001` | Leak warning | 記錄；不通知（第 7 節） |
| `10327002` | **Leak alarm** | 記錄 + **通知** |
| `10327012` | OES connection lost（光譜儀斷線） | 記錄 + 通知（OES 停止量測） |
| `10327013` | OES acquisition error | 記錄 + 通知 |
| `10327014` | OES data write failure | 記錄 + 通知 |

ALTX 帶有當下數值，例如：
`CH3 OES LEAK ALARM composite=3, 2 alarm / 0 warning of 3 ratios, leak rate 2.400e-003 +/-4.1e-004 mbar-L/s (conf 0.64)`。
測試或回放資料的 ALTX 結尾會加 `[TEST/REPLAY DATA]`。

### 4.3 CEID（事件）與建議報告

| CEID | 事件 | 建議連結的報告 |
|---|---|---|
| `10327502` | Operator acknowledged（操作者解除鎖存警報） | RPTID 1：VID 007、010、013 |
| `10327507` | Ratio configuration reloaded（比值槽位身分改變） | RPTID 3：槽位 1～10 的位移 25（或收到後直接以 S1F3 重讀 10 槽的 16～25） |
| `10327508` | Acquisition started（OES 開始採集） | RPTID 2：VID 013、015、016 |
| `10327509` | Acquisition stopped（OES 停止採集） | RPTID 2 |

> 507 **只在槽位身分（位移 16～25）真的改變時**送出：工程師在 OES 調整比值順序、增刪比值（其後的比值會移到別的槽位）、改譜線、監測方式、擷取方式、啟用、名稱或波長修正，並重新開始採集之後。只改門檻、平滑不會送。

> OES 的 508／509 是**光譜儀開始／停止採集**，不是電漿開啟／關閉。電漿有無看 VID 021。

## 5. 判讀規則（必須實作）

以下行為都已對照設備端程式碼確認。FDC 的語意層必須處理，否則會產生假警報或漏報。

| # | 規則 | 寫錯的後果 |
|---|---|---|
| R1 | **VID 001 必須搭配 004 讀。** 004 = 0 時 001 送 0，存成 NULL，不是「漏率 0」 | 趨勢圖上出現大量假的「零漏」 |
| R2 | **VID 016 = 1 的資料一律標成「非量測」**，不可進 SPC、報表或通知 | 測試或回放的警報被當成真的 |
| R3 | **VID 015 = 1** 時，另發一則「OES 需重抓基準」給設備工程師 | 曝光參數改了，所有判定都在比錯的東西 |
| R4 | **007 = 3（Alarm）是鎖存的。** 漏氣停止也不會自己回落，警報持續時間要算到 CEID 502 | 把「沒人處理」算成「漏了很久」 |
| R5 | **ALID 是成對的。** 以 (ALID, set)／(ALID, clear) 維護「有效警報表」。Warning 升 Alarm 時，OES 先 clear 001、再 set 002 | 警報表殘留已結束的警報 |
| R6 | **重連後用 S1F3 讀 007 校正警報表**，即使已開啟 spooling 也要做 | 斷線期間的轉態遺失，警報表與實際不符 |
| R7 | **VID 008 和 009 不可相加或相減。** 008 只排除停用的比值；009 只算 Warning（Alarm 算在 010）。要判斷「有沒有異常」，看 007 | 鎖存 Alarm 時讀到 009 = 0，誤判為正常 |
| R8 | **讀 027 前先看 028。** 027 空字串有三種原因，只有 028 分得出來（0 未設分類器、1 無電漿步驟、2 尚未判定、3 已分類、4 無法分類） | 把「還沒判定」當成「不是製程 A」 |
| R9 | **VID 030 = 1 不只是「還沒收到事件」。** 也包括：視窗逾時（超過 OES 端的上限仍未收到 End）、OES 與 EAP 的 TCP 連線 75 秒沒有任何訊息、EAP 回報它自己不知道 PM3 的狀態或與主機台斷線，以及事件暫不套用（OES 回放錄檔時一律如此；測試模式預設如此——此時 016 也是 1）。030 = 1 時 OES 照未使用製程事件時的方式判定，**警報仍然有效**。**030 = 3 只表示不在任何視窗內，與有沒有電漿無關**，有沒有電漿看 021 | 把「不明」期間的警報當成無效；把「視窗外」當成「沒有電漿」 |
| R10 | **讀槽位的位移 03 前先讀 18。** 18 = 0 時 03 是基準百分比（100 = 基準）；= 1 時是 σ 分數（100 = 基準、120 = 警告、150 = 警報）。兩者刻度相同但意義不同，不可混算、不可畫在同一條軸上當同一個量 | 把 σ 分數 126 讀成「高出基準 26 %」 |
| R11 | **收到 CEID `10327507` 後，先重讀 10 個槽位的位移 16～25，再相信下一筆槽位數值。** 507 代表至少有一個槽位換了比值或改了定義 | 重排後把新比值的數值記到舊比值名下 |
| R12 | **以位移 25（Key）追蹤比值，不要以槽位號或位移 22。** 槽位號在重排後會換人；22 是可以隨時改的顯示名稱。25 建立後永不改變，改名、重排都不變。25 為空字串表示空槽位（與「有設定但停用」的 16 = 0 不同） | 歷史資料接錯比值；改名後同一組比值變成兩條趨勢 |
| R13 | **槽位的 F4 沒有值時送 0，不是「量到 0」。** 05 = 3 或 6 時 01～15 都無意義；05 = 5 時 10～13 無意義；19 = 2 時 06 無意義；17 = 1（絕對強度）時 07、09、21 為 0、24 為空字串；VID 006 ≠ 1 時 14、15 為 0。完整對照見規格 §1.4(b) | 把停判期間的 0 畫進趨勢，看起來像比值掉到零 |

## 6. 製程視窗：讀 VID 030／031

### 6.1 來源

PM3 交替跑不同製程，OES 的判定只在對的製程裡有意義。**主機台知道此刻在跑哪個製程**；它的製程事件送到 EAP，EAP 以 TCP 原樣轉送給 OES，OES 依自己的 CEID 對照表維護「製程視窗」，並報在：

| VID | 內容 |
|---|---|
| 030 | 0 未使用製程事件、1 狀態不明、2 在視窗內、3 不在任何視窗內 |
| 031 | 030 = 2 時的視窗類別；其他情況為空字串 |
| 032 | OES 最後收到的主機台 CEID |

**FDC 不需要自己收主機台的事件**：讀 030／031 得到的，就是 OES 判定時實際使用的那個視窗，兩邊不會對不上。

OES 對照表（設備端設定，PM3）：

| 主機台 CEID（Start／End） | 事件 | 031 |
|---|---|---|
| 3100439529／3100439530 | Chamber Process／Chamber precoat | `A` |
| 3099591660／3099591661 | Chamber Clean | `B` |
| 3100167145／3100167146 | Auto Leak check（主機台升壓測漏） | `LEAK_CHECK`（沒有比值指定這個類別，只用來讓 FDC 標記；見 10.1 N7） |

**Chamber Process 與 Chamber precoat 的 CEID 相同。** 兩者是同一個製程，差別只在 precoat 沒有放晶圓。從 CEID 分不出來，OES 從光譜也分不出來（兩者都是 `A`）。處理方式見 6.3。

### 6.2 視窗定義

| FDC 的視窗 | VID 030／031 | OES 警報的意義 |
|---|---|---|
| `PROCESS_A` | 2 ／ `A` | **有效**：製程 A 電漿中偵測到漏氣 |
| `CLEAN` | 2 ／ `B` | **不適用**：現場比值組指定在製程 A，清潔期間這些比值不判定（槽位位移 05 = 8 NotApplicable） |
| `LEAK_CHECK` | 2 ／ `LEAK_CHECK` | 主機台測漏中，通常沒有電漿 |
| `OUTSIDE` | 3 ／ 空 | 不在任何視窗內。指定類別的比值不判定；若仍出現警報，來自沒有指定類別的比值，記錄並標為「視窗外」 |
| `UNKNOWN` | 1 ／ 空 | OES 不知道目前的視窗（規則 R9），照未使用製程事件時的方式判定。**警報有效**，但沒有依製程篩選 |
| `NOT_IN_USE` | 0 ／ 空 | OES 沒有啟用製程事件 |

**關聯規則：**

- **收到 S5F1（set）時，立刻以 S1F3 讀 030、031、021、016**，用讀到的值標記這筆警報。不要用 Trace 的最後一筆：Trace 每 10 秒取樣一次，視窗剛切換時會標錯。
- 每一筆 Trace 樣本都以同一筆樣本裡的 030／031 標記（建議 030、031 都放進 Trace，見 4.1）。
- **視窗的開始與結束時間，以 FDC 觀察到 030／031 變化的時間為準**，解析度等於 Trace 週期（建議 10 秒）。需要更精確的時刻時，OES 的 Ratio CSV 每一幀都有 `ToolContext`／`ToolWindowClass` 欄位，可以事後對照。
- 時間基準用 **FDC 收到訊息的時間**。OES 的 S6F11 與 S5F1 不帶設備時間戳；暫存（spooled）訊息到達較晚，以 S6F23 取回時要另外標記「延遲到達」。
- 警報跨視窗（例如 `PROCESS_A` 期間 set，結束後才 clear）時，以 **set 時的視窗**為準。

### 6.3 有沒有晶圓（Chamber Process vs. precoat）

目前沒有任何系統知道 ProcessStart 時 PM3 裡有沒有晶圓（列為待補需求，見第 10 節）。第一階段：

- **兩者用同一條規則**：OES 判定在兩者期間都有效。precoat 時漏氣一樣是漏氣，而且是在**第一片晶圓進腔之前**發現，處理價值最高。
- **完整保存每個 `PROCESS_A` 視窗的開始與結束時間。** 之後補上晶圓資訊時，可以用時間戳回頭判斷每一筆 OES 警報當時有沒有晶圓、影響哪些 Lot。

### 6.4 交叉驗證

| 檢查 | 條件 | 不符時代表 |
|---|---|---|
| 電漿有無 | `PROCESS_A` 視窗內，021 應為 1 | OES 的電漿門檻設太高，該製程完全沒被判定 |
| 主機台測漏對照 | 每個 `LEAK_CHECK` 視窗，保存前後 10 分鐘的 OES 007／001 摘要，與主機台的測漏結果並排 | 累積起來就是 OES 漏報、誤報的實地證據。主機台測漏結果的取得方式待定（10.1 N3） |

030 = 2 時，027／028 已經是製程事件給的值，所以「027 應為 `A`」這類比對等於拿事件比對事件，沒有意義。OES 端若同時開著光譜分類器，分類結果與視窗不符時，OES 會自己記一筆 `ToolEventClassMismatch`。

### 6.5 確認 EAP 的轉送正常

EAP 轉送事件不經過 FDC，但 FDC 從 OES 的 VID 就看得出轉送是否正常：

| 現象 | 代表 | 處理 |
|---|---|---|
| 030 長時間為 1，032 也不變 | OES 沒收到 EAP 的事件：TCP 連線中斷，或 EAP 沒有在轉送 | 通知設備工程師看 OES SECS 分頁的 `EAP link` 狀態（操作手冊 §9.15） |
| 032 有在變，但 PM3 跑 Chamber Process 時 030／031 不是 2／`A` | OES 的對照表沒有這個 CEID，或 OES 正在回放／測試模式（016 = 1） | 通知設備工程師 |
| PM3 製程結束後 030 仍是 2 | EAP 漏轉了 End。OES 會在下一筆心跳時修正，或 600 秒後作廢 | 記錄；頻繁發生時通知 EAP 平台 |

## 7. 第一階段動作：記錄與通知

**不扣貨、不 Hold 腔體、不對任何設備下命令。** FDC 不送 S2F41：OES 唯一接受的遠端命令 `TOOL_EVENT` 是給轉送製程事件用的，現場改由 EAP 以 TCP 轉送。原因：OES 在這台機台的偵測能力尚未經實地驗證（`leak-monitor-plan-zh-TW.md` §16.1 的結論為 NO-GO），且 2026-09 曾因基準擷取錯誤整天顯示 Alarm。先累積誤報率，再決定是否放權。

| 觸發 | 條件 | 通知對象 | 內容 |
|---|---|---|---|
| ALID `10327002` set | VID 016 = 0 | 設備工程師 | 時間、PM3 視窗、ALTX、當下 VID 001／004／013 |
| ALID `10327012`～`014` set | 不論 016 | 設備工程師 | 時間、ALTX；註明「OES 已停止量測」 |
| VID 015 由 0 變 1 | VID 016 = 0 | 設備工程師 | 「OES 基準已不適用，需重抓 Golden Run」 |
| CEID `10327502` | — | 不通知，只記錄 | 解除時間、警報持續時間 |
| ALID `10327001` set | — | 不通知，只記錄 | Warning 次數納入月報 |

通知範例：

```
[OES PM3] 洩漏警報 (Alarm)
時間：2026-10-22 14:03:11
PM3 視窗：PROCESS_A（開始於 14:01:40）
OES：CH3 OES LEAK ALARM composite=3, 2 alarm / 0 warning of 3 ratios
漏率：2.4E-3 mbar·L/s（有效）　基準：Recipe 1
處理：請至 OES 畫面確認並由操作者按 Acknowledge
```

## 8. 資料保存

| 資料 | 建議結構 | 保存期限（建議） |
|---|---|---|
| OES 警報 | 一筆一列：ALID、set 時間、clear 時間、ALTX、set 時的 PM3 視窗、是否測試資料（016）、是否延遲到達 | 永久 |
| OES 事件 | 一筆一列：CEID、時間、報告內容 | 永久 |
| OES Trace | 時序資料：時間、各 VID 值、PM3 視窗 | 1 年 |
| PM3 視窗 | 一筆一列：類別（031）、開始、結束（依 030／031 的變化，見 6.2） | 永久（之後補晶圓資訊要用） |
| 主機台測漏對照 | 每次 LEAK_CHECK：開始、結束、主機台結果、前後 10 分鐘 OES 007／001 摘要 | 永久 |

OES PC 本身也保存 SECS 收送日誌（`Log\secs_YYYYMMDD.log`）、與 EAP 的 TCP 收送日誌（`Log\eap_YYYYMMDD.log`）與 Ratio CSV，各方有爭議時可以互相對照。

**月報建議**：Alarm 次數（依視窗分類）、每次 Alarm 的處理結果（真漏／基準問題／不明）、OES 斷線時數、與主機台測漏結果的一致率。這份統計是第二階段「是否放權」的依據。

## 9. 驗收方式

不需要真的漏氣。OES 的 Replay 分頁可以播放一段記錄過的漏氣錄檔（Normal → Warning → Alarm）。

| # | 步驟 | 預期 |
|---|---|---|
| 1 | FDC 連線，跑完第 3 節初始化 | 每一步回覆碼為 0；S1F11 名單與第 4.1 節一致 |
| 2 | OES SECS 分頁勾選 **Report test / replay data too**，播放漏氣錄檔 | FDC 依序收到 `10327001` set → `10327001` clear + `10327002` set |
| 3 | 檢查步驟 2 的資料 | **全部標記為「非量測」（VID 016 = 1），且沒有發出通知**（驗證 R2） |
| 4 | 操作者在 OES 按 Acknowledge | 收到 `10327002` clear 與 CEID `10327502` |
| 5 | Alarm 期間拔掉網路線 30 秒再接回 | 重連後警報表正確；暫存訊息取回且標記延遲（驗證 R6） |
| 6 | 取消勾選 **Report test / replay data too** 後再播一次 | **收不到 ALID**；但 S1F3 讀 007 仍會變化 |
| 7 | 在主機台跑一次 PM3 Chamber Process（EAP 的 TCP 轉送已上線） | FDC 讀到 030 = 2、031 = `A`，End 之後 030 = 3；032 為該製程的 End CEID；FDC 記下一個 `PROCESS_A` 視窗 |
| 8 | 在主機台跑一次 PM3 Auto Leak check | 031 = `LEAK_CHECK`；FDC 記下一個 `LEAK_CHECK` 視窗與前後的 OES 摘要 |
| 9 | 請 EAP 平台暫停 TCP 服務超過 75 秒 | 030 變為 1；這段期間發生的警報 FDC 標記為 `UNKNOWN` 且照常通知；恢復後 030 回到正確值 |
| 10 | 步驟 2 播放漏氣錄檔期間，Trace 追蹤槽位 1～3 的位移 05 | 依序走過 0（Normal）→ 1（Warning）→ 2（Alarm）；以出廠比值組驗收時，位移 25 為 `R_N2Ar`、`R_NOAr`、`R_N2357Ar`（現場比值組則以 OES Ratio Setup 畫面為準） |
| 11 | 請設備工程師在 OES Ratio Setup 把第 1 列往下移一列（▼）、存檔，Stop → Start（之後移回） | 收到 CEID `10327507`；重讀後槽位 1、2 的位移 25 對調（驗證 R11、R12）。只改門檻再重啟則**不會**收到 507 |
