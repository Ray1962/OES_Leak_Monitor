OES Leak Monitor × FDC 整合規格（PM3）

對象： 廠內 FDC 系統的開發與維運人員。 目的： 說明 FDC 要如何連上 PM3 的 OES Leak Monitor、讀哪些資料、怎麼判讀、怎麼知道每筆資料屬於哪個製程，以及第一階段要記錄與通知什麼。 第一階段範圍： 只記錄與通知，不扣貨、不 Hold 腔體、不對設備下任何命令。 FDC 是 OES 唯一的 SECS host。 主機台的製程事件不經過 FDC：EAP 以 TCP 直接轉送給 OES（eap-tool-event-tcp-spec-zh-TW.md），OES 再把目前的製程視窗以 VID 030／031 報給 FDC（第 6 節）。 依據： Satellite_SECS_Specification_v2.md（欄位語意）、secs-integration.md（設備端實作）、EAP ceid-events.md（主機台 CEID 表）。三者與本文衝突時，以前兩份為準，並回頭修正本文。 沿革： 本文原為給 EAP 平台的 eap-integration-spec-zh-TW.md。2026-10-26 確認現場 OES 的 SECS host 是 FDC，改寫為本文；原本「EAP 以 S2F41 TOOL_EVENT 轉送製程事件」的做法改成上述 TCP 連線。

1. 系統配置

┌──────────────┐  SECS（既有）  ┌──────────────┐
│   Tool PC    │──────────────▶│     EAP      │

                                      │ OES 主動連入，見 eap-tool-event-tcp-spec
┌──────────────┐  SECS（本規格）┌──────┴───────┐

└──────────────┘               └──────────────┘
  • OES Leak Monitor 是一台獨立的 SECS 設備，有自己的 HSMS 連線，和主機台的連線無關。
  • FDC 是它唯一的 host。 HSMS-SS 一條連線只能有一個 host，EAP 不會、也無法連進這條連線。
  • 只裝在 PM3。 製程資訊只有一條來源：主機台 → EAP → OES。FDC 不需要自己收主機台的 CEID，讀 OES 的 VID 030／031 就知道 PM3 在跑哪個製程（第 6 節）。
  • OES 不知道批次、配方、晶圓；它只看光譜。把洩漏和批次接起來是 FDC 的工作（第 6 節）。

5. 判讀規則（必須實作）

以下行為都已對照設備端程式碼確認。FDC 的語意層必須處理，否則會產生假警報或漏報。

#規則寫錯的後果
R1VID 001 必須搭配 004 讀。 004 = 0 時 001 送 0，存成 NULL，不是「漏率 0」趨勢圖上出現大量假的「零漏」
R2VID 016 = 1 的資料一律標成「非量測」，不可進 SPC、報表或通知測試或回放的警報被當成真的
R3VID 015 = 1 時，另發一則「OES 需重抓基準」給設備工程師曝光參數改了，所有判定都在比錯的東西
R4007 = 3（Alarm）是鎖存的。 漏氣停止也不會自己回落，警報持續時間要算到 CEID 502把「沒人處理」算成「漏了很久」
R5ALID 是成對的。 以 (ALID, set)／(ALID, clear) 維護「有效警報表」。Warning 升 Alarm 時，OES 先 clear 001、再 set 002警報表殘留已結束的警報
R6重連後用 S1F3 讀 007 校正警報表，即使已開啟 spooling 也要做斷線期間的轉態遺失，警報表與實際不符
R7VID 008 和 009 不可相加或相減。 008 只排除停用的比值；009 只算 Warning（Alarm 算在 010）。要判斷「有沒有異常」，看 007鎖存 Alarm 時讀到 009 = 0，誤判為正常
R8讀 027 前先看 028。 027 空字串有三種原因，只有 028 分得出來（0 未設分類器、1 無電漿步驟、2 尚未判定、3 已分類、4 無法分類）把「還沒判定」當成「不是製程 A」
R9VID 030 = 1 不只是「還沒收到事件」。 也包括：視窗逾時（超過 OES 端的上限仍未收到 End）、OES 與 EAP 的 TCP 連線 75 秒沒有任何訊息、EAP 回報它自己不知道 PM3 的狀態或與主機台斷線，以及事件暫不套用（OES 回放錄檔時一律如此；測試模式預設如此——此時 016 也是 1）。030 = 1 時 OES 照未使用製程事件時的方式判定，警報仍然有效。030 = 3 只表示不在任何視窗內，與有沒有電漿無關，有沒有電漿看 021把「不明」期間的警報當成無效；把「視窗外」當成「沒有電漿」
R10讀槽位的位移 03 前先讀 18。 18 = 0 時 03 是基準百分比（100 = 基準）；= 1 時是 σ 分數（100 = 基準、120 = 警告、150 = 警報）。兩者刻度相同但意義不同，不可混算、不可畫在同一條軸上當同一個量把 σ 分數 126 讀成「高出基準 26 %」
R11收到 CEID 10327507 後，先重讀 10 個槽位的位移 16～25，再相信下一筆槽位數值。 507 代表至少有一個槽位換了比值或改了定義重排後把新比值的數值記到舊比值名下
R12以位移 25（Key）追蹤比值，不要以槽位號或位移 22。 槽位號在重排後會換人；22 是可以隨時改的顯示名稱。25 建立後永不改變，改名、重排都不變。25 為空字串表示空槽位（與「有設定但停用」的 16 = 0 不同）歷史資料接錯比值；改名後同一組比值變成兩條趨勢
R13槽位的 F4 沒有值時送 0，不是「量到 0」。 05 = 3 或 6 時 01～15 都無意義；05 = 5 時 10～13 無意義；19 = 2 時 06 無意義；17 = 1（絕對強度）時 07、09、21 為 0、24 為空字串；VID 006 ≠ 1 時 14、15 為 0。完整對照見規格 §1.4(b)把停判期間的 0 畫進趨勢，看起來像比值掉到零

6. 製程視窗：讀 VID 030／031

6.1 來源

PM3 交替跑不同製程，OES 的判定只在對的製程裡有意義。主機台知道此刻在跑哪個製程；它的製程事件送到 EAP，EAP 以 TCP 原樣轉送給 OES，OES 依自己的 CEID 對照表維護「製程視窗」，並報在：

VID內容
0300 未使用製程事件、1 狀態不明、2 在視窗內、3 不在任何視窗內
031030 = 2 時的視窗類別；其他情況為空字串
032OES 最後收到的主機台 CEID

FDC 不需要自己收主機台的事件：讀 030／031 得到的，就是 OES 判定時實際使用的那個視窗，兩邊不會對不上。

OES 對照表（設備端設定，PM3）：

主機台 CEID（Start／End）事件031
3100439529／3100439530Chamber Process／Chamber precoatA
3099591660／3099591661Chamber CleanB
3100167145／3100167146Auto Leak check（主機台升壓測漏）LEAK_CHECK（沒有比值指定這個類別，只用來讓 FDC 標記；見 10.1 N7）

Chamber Process 與 Chamber precoat 的 CEID 相同。 兩者是同一個製程，差別只在 precoat 沒有放晶圓。從 CEID 分不出來，OES 從光譜也分不出來（兩者都是 A）。處理方式見 6.3。

關聯規則：

  • 收到 S5F1（set）時，立刻以 S1F3 讀 030、031、021、016，用讀到的值標記這筆警報。不要用 Trace 的最後一筆：Trace 每 10 秒取樣一次，視窗剛切換時會標錯。
  • 每一筆 Trace 樣本都以同一筆樣本裡的 030／031 標記（建議 030、031 都放進 Trace，見 4.1）。
  • 視窗的開始與結束時間，以 FDC 觀察到 030／031 變化的時間為準，解析度等於 Trace 週期（建議 10 秒）。需要更精確的時刻時，OES 的 Ratio CSV 每一幀都有 ToolContext／ToolWindowClass 欄位，可以事後對照。
  • 時間基準用 FDC 收到訊息的時間。OES 的 S6F11 與 S5F1 不帶設備時間戳；暫存（spooled）訊息到達較晚，以 S6F23 取回時要另外標記「延遲到達」。
  • 警報跨視窗（例如 PROCESS_A 期間 set，結束後才 clear）時，以 set 時的視窗為準。

6.3 有沒有晶圓（Chamber Process vs. precoat）

目前沒有任何系統知道 ProcessStart 時 PM3 裡有沒有晶圓（列為待補需求，見第 10 節）。第一階段：

  • 兩者用同一條規則：OES 判定在兩者期間都有效。precoat 時漏氣一樣是漏氣，而且是在第一片晶圓進腔之前發現，處理價值最高。
  • 完整保存每個 PROCESS_A 視窗的開始與結束時間。 之後補上晶圓資訊時，可以用時間戳回頭判斷每一筆 OES 警報當時有沒有晶圓、影響哪些 Lot。

檢查條件不符時代表
電漿有無PROCESS_A 視窗內，021 應為 1OES 的電漿門檻設太高，該製程完全沒被判定

030 = 2 時，027／028 已經是製程事件給的值，所以「027 應為 A」這類比對等於拿事件比對事件，沒有意義。OES 端若同時開著光譜分類器，分類結果與視窗不符時，OES 會自己記一筆 ToolEventClassMismatch。
