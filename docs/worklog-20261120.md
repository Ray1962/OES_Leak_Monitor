## 1. 問題

實驗機與現場光譜儀的像素間距約 **0.6 nm/px**。原本的預設取線窗是以 nm 固定值訂的（例如訊號 ±0.5 nm、基準寬 1.0 nm），換算後：

- 訊號窗只涵蓋 1 個像素，峰頂稍微漂移就落在窗外，RawMean 也無法平均雜訊；
- 基準窗只有 1–2 個像素，底線與雜訊估計不穩；
- 間隙（gap）不到 2 個像素，線翼會漏進基準窗；
- 峰搜尋範圍不到 2 個像素，跟不上一個像素的漂移。

## 2. 設計決定（grill 會議 Q1–Q6）

| # | 決定 |
|---|---|
| Q1 | 預設窗改以「像素數」訂，依當下光譜的實際間距換成 nm（設定仍以 nm 儲存，`WindowKey` 不變） |
| Q2 | 最低像素數：訊號 5、基準 3、間隙 2、峰搜尋 2 |

| Q6 | 驗證結果推翻了 Integral 加寬：**Integral 訊號窗不設像素下限**（新 Integral 線仍從 ±1.0 nm 起）；**峰搜尋 = 0 視為刻意固定，不檢查**；錄檔比較容許差 2% |

## 3. 程式修改

### 3.1 新增 `LineWindowAdvice`（純邏輯，無 UI）

- `PitchOf(wavelengths)`：取波長軸相鄰間距的中位數；沒有光譜時退回 `FallbackPitchNm = 0.6`。
- `Defaults(line, mode, pitch)`：產生新線的建議窗。PeakHeight/RawMean 訊號半寬 = 5 px × pitch / 2；Integral 為 ±1.0 nm；RawMean 不搜尋（0）。
- `Pixels(width, pitch)`：`floor(width / pitch)`，即「不論落在軸上哪裡都保證涵蓋」的像素數。
- `Check(region, pitch)`：列出該模式實際用到的每個窗與其最低值。RawMean 只檢查訊號窗；Integral 訊號窗與峰搜尋 0 的最低值為 0。
- `ApplySuggested(region, pitch)`：只把**過窄**的窗拉到建議值；中心、已夠寬的窗、Integral 訊號窗、峰搜尋 0 都不動；不對稱右側分開處理。
- `CoverageText` / `WarningText`：編輯器顯示用文字（例如 `Too narrow: Gap 1 px (needs ≥2)`）。

### 3.2 Ratio Setup 介面

- `RatioEditViewModel`：分子、分母各自顯示像素涵蓋文字與警告；新增 `HasNarrowWindows`、`ApplySuggestedWidthsCommand`。原本的 `BuildRegion` 改由 `LineWindowAdvice.Defaults` 取代。
- `RatioSetupViewModel`：把 Line preview 量到的像素間距傳給編輯器。
- `LinePreviewViewModel` / `LinePreview`：新增 `PitchNm` 與 `PitchChanged` 事件；預覽圖上也顯示 "Too narrow" 警告。
- `RatioSetupPanel.xaml`：每一側加入涵蓋文字與警告列，訊號區加入 Apply suggested widths 按鈕。
- 按 Apply 後的修改屬於暫存編輯，可以用 Revert 還原。

## 4. 錄檔驗證（11/19 漏氣測試）

新增 `Pixel_based_windows_lower_noise_without_losing_the_leak_step`，比較舊窗與新窗在 DV=300 的 step SNR：

- Ar RawMean 由 1 px 加寬到 5 px：持平或更好。
- 已調好的 Integral 帶（NO 235.6、OH 308.8）加寬到 7 px：step SNR **下降 25–35%**。多出來的像素不回應漏氣，而雜訊主要來自**電漿閃爍**，不是像素雜訊。

所以 Integral 訊號窗不設下限（Q6）。

- **既有比值不會被自動修改**。開啟 Ratio Setup 時，過窄的窗會顯示警告，要由工程師按 Apply suggested widths 並重新驗證。

- Golden Run 基準會記錄擷取時用的取線窗（PR #118），所以套用新窗之後應重新擷取 Golden Run。
