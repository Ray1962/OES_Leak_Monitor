# OES Leak Monitor × EAP 整合規格（PM3）

> **對象：** 廠內 EAP 平台的開發與維運人員。
> **目的：** 說明 EAP 要如何連上 PM3 的 OES Leak Monitor、讀哪些資料、怎麼判讀，以及怎麼和主機台的製程事件接起來。
> **第一階段範圍：** **只記錄與通知**，不扣貨、不 Hold 腔體、不對設備下控制命令。唯一要送給 OES 的是 S2F41 `TOOL_EVENT`——把主機台的製程事件轉送過去，這是資訊轉送，不是控制（§6.5）。
> **依據：** `Satellite_SECS_Specification_v2.md`（欄位語意）、`secs-integration.md`（設備端實作）、`EAP ceid-events.md`（主機台 CEID 表）。三者與本文衝突時，以前兩份為準，並回頭修正本文。

## 1. 系統配置

```
                    ┌──────────────────────┐
                    │      EAP 平台         │
                    └───┬──────────────┬───┘
       既有連線（主機台）│              │新增連線（本規格）
                    ┌───┴───┐      ┌───┴──────────────────┐
                    │ 主機台 │      │ OES Leak Monitor PC   │
                    │ PM2/PM3│      │ 只看 PM3（cc = 03）   │
                    └───────┘      └──────────────────────┘
```

- **OES Leak Monitor 是一台獨立的 SECS 設備**，有自己的 HSMS 連線，和主機台的連線無關。
- **只裝在 PM3。** EAP 只需要把它和主機台 **PM3** 的事件關聯起來。
- OES 不知道批次、配方、晶圓；它只看光譜。**把洩漏和批次接起來是 EAP 的工作**（第 6 節）。

## 2. 連線參數

| 項目 | 值 | 說明 |
|---|---|---|
| 協定 | HSMS-SS（SECS-II over TCP/IP） | |
| 連線模式 | **OES = Passive（監聽）、EAP = Active（主動連入）** | |
| IP／Port | 依現場設定，預設 port 5000 | 由設備工程師在 OES 的 SECS 分頁設定，交給 EAP 方 |
| Device ID | 依現場設定 | HSMS 交握不檢查 Device ID；填錯要到資料訊息才會收到 S9F1 |
| T3／T5／T6／T7／T8 | 45／10／10／10／10 秒（預設） | EAP 有指定值時，雙方一起改 |
| 機台號 `cc` | **03**（待現場確認，見第 10 節） | 決定所有 SVID／ALID／CEID 的第 2～3 碼 |

> 兩端都會主動送 S1F13，日誌中看到兩次是正常的。OES 端每 10 秒重試一次，直到 EAP 回 COMMACK = 0。

## 3. 連線後的初始化順序

每次建立通訊（包括斷線重連）都要完整跑一次。下表每一項都已確認設備端支援。

| 步驟 | 訊息 | 目的 |
|---|---|---|
| 1 | S1F13 → S1F14 | 建立通訊 |
| 2 | S1F1 → S1F2 | 確認型號與軟體版本 |
| 2a | S1F17 → S1F18 | 依平台慣例要求 ON-LINE（設備端支援；ONLACK 0 = 接受、2 = 已在線上，兩者皆可） |
| 3 | S2F31 → S2F32 | 對時（見下方注意） |
| 4 | S1F11 → S1F12 | 讀 SVID 名單，和第 4.1 節比對；**缺項要告警**，不要默默略過 |
| 5 | S5F5 → S5F6 | 讀警報清單，應有 5 條，ALID 為 ASCII |
| 6 | S5F3 → S5F4 | 啟用全部警報 |
| 7 | S2F43 → S2F44 | **開啟 S5、S6 的暫存（spooling）**，斷線期間的警報與事件才不會遺失 |
| 8 | S2F33 → S2F35 → S2F37 | 定義報告、連到 CEID、啟用事件（第 4.3 節） |
| 9 | S2F23 → S2F24 | 訂閱 Trace（第 4.1 節） |
| 10 | S6F23 → S6F24 | 取回斷線期間暫存的訊息 |
| 11 | S1F3 → S1F4 | 讀一次 VID 007／010／016／030，重建目前狀態（規則 R6、R9） |
| 12 | S2F41 → S2F42 | **補送目前的製程視窗**：若平台知道 PM3 此刻在某個製程視窗內（已收到 Start、尚未收到 End），而步驟 11 讀到的 VID 030 ≠ 2，就把那個 Start 的 CEID 以 `TOOL_EVENT` 再送一次（§6.5）。OES 重新啟動後在下一個視窗邊界之前都是「狀態不明」，補送可以縮短這段時間 |

> **對時的注意事項：** S2F31 只會設定 OES 回報給 Host 的 SECS 時鐘，**不會改 OES PC 的系統時間**。OES 寫的 CSV 與日誌用的是 PC 時鐘，所以 **OES PC 要另外接廠內 NTP**，否則事後拿 CSV 和 EAP 的紀錄對時會對不上。

## 4. 使用的識別碼

以下 `cc = 03`。SVID 為 `10327000vv`、ALID 為 `10327nnn`、CEID 為 `10327nnn`。

### 4.1 SVID（狀態變數）

**Trace 訂閱建議：** 每 10 秒取樣（DSPER `"000010"`），每 6 筆回報一次。

| VID | SVID | 項目 | 型別 | Trace | 用途 |
|---|---|---|---|---|---|
| 001 | `1032700001` | Leak rate（mbar·L/s） | F4 | ✔ | 漏率，**須搭配 004** |
| 004 | `1032700004` | Leak rate valid | U4 | ✔ | 001 是否有效 |
| 006 | `1032700006` | Calibration status | U4 | | 0 未校正／1 有效／2 基準不符 |
| 007 | `1032700007` | Composite leak level | U4 | ✔ | 0 Idle／1 Normal／2 Warning／3 Alarm |
| 009 | `1032700009` | Warning ratio count | U4 | | 判讀細節 |
| 010 | `1032700010` | Alarm ratio count | U4 | | 判讀細節 |
| 011 | `1032700011` | Low-signal ratio count | U4 | | 判讀細節 |
| 013 | `1032700013` | Active Golden Run name | A | | 現用基準名稱 |
| 015 | `1032700015` | Acquisition mismatch | U4 | ✔ | 1 = 基準已不適用 |
| 016 | `1032700016` | Test / replay mode | U4 | ✔ | **1 = 不是實機量測** |
| 021 | `1032700021` | Plasma present | U4 | ✔ | 1 = OES 判定電漿開啟 |
| 027 | `1032700027` | Process class | A | ✔ | 製程類別。製程事件生效時（030 = 2 或 3）由事件決定，否則為 OES 從光譜判定的結果 |
| 028 | `1032700028` | Process class state | U4 | ✔ | 027 的有效性，見規則 R8 |
| 029 | `1032700029` | Process step index | U4 | | 電漿步驟累計序號 |
| 030 | `1032700030` | Tool event context state | U4 | ✔ | OES 依據的製程視窗狀態：0 未使用、1 狀態不明、2 在視窗內、3 不在任何視窗內，見規則 R9 |
| 031 | `1032700031` | Tool event window class | A | ✔ | 目前視窗的類別（`A`／`B`）；030 ≠ 2 時為空字串 |
| 032 | `1032700032` | Last tool CEID | U4 | | OES 最後收到的 `TOOL_EVENT` CEID；用來確認平台的轉送確實到達 |

完整的 VID 001～032 定義見 `Satellite_SECS_Specification_v2.md` §1.4(a)；數值範例見 `secs-global-vid-example-zh-TW.html`。

### 4.2 ALID（警報）

S5F1 的 ALID 以 **ASCII** 送出（`<A[8] "10327002">`）。ALCD bit7 = 1 為發生、0 為解除。

| ALID | 警報 | 第一階段處理 |
|---|---|---|
| `10327001` | Leak warning | 記錄；不通知（第 7 節） |
| `10327002` | **Leak alarm** | 記錄 + **通知** |
| `10327012` | OES connection lost（光譜儀斷線） | 記錄 + 通知（OES 停止量測） |
| `10327013` | OES acquisition error | 記錄 + 通知 |
| `10327014` | OES data write failure | 記錄 + 通知 |

ALTX 帶有當下數值，例如：
`CH3 OES LEAK ALARM composite=3, 2 alarm / 0 warning of 3 ratios, leak rate 2.400e-003 +/-4.1e-004 mbar-L/s (conf 0.64)`。
測試或回放資料的 ALTX 結尾會加 `[TEST/REPLAY DATA]`。

### 4.3 CEID（事件）與建議報告

| CEID | 事件 | 建議連結的報告 |
|---|---|---|
| `10327502` | Operator acknowledged（操作者解除鎖存警報） | RPTID 1：VID 007、010、013 |
| `10327508` | Acquisition started（OES 開始採集） | RPTID 2：VID 013、015、016 |
| `10327509` | Acquisition stopped（OES 停止採集） | RPTID 2 |

> OES 的 508／509 是**光譜儀開始／停止採集**，不是電漿開啟／關閉。電漿有無看 VID 021。

## 5. 判讀規則（必須實作）

以下行為都已對照設備端程式碼確認。EAP 的語意層必須處理，否則會產生假警報或漏報。

| # | 規則 | 寫錯的後果 |
|---|---|---|
| R1 | **VID 001 必須搭配 004 讀。** 004 = 0 時 001 送 0，存成 NULL，不是「漏率 0」 | 趨勢圖上出現大量假的「零漏」 |
| R2 | **VID 016 = 1 的資料一律標成「非量測」**，不可進 SPC、報表或通知 | 測試或回放的警報被當成真的 |
| R3 | **VID 015 = 1** 時，另發一則「OES 需重抓基準」給設備工程師 | 曝光參數改了，所有判定都在比錯的東西 |
| R4 | **007 = 3（Alarm）是鎖存的。** 漏氣停止也不會自己回落，警報持續時間要算到 CEID 502 | 把「沒人處理」算成「漏了很久」 |
| R5 | **ALID 是成對的。** 以 (ALID, set)／(ALID, clear) 維護「有效警報表」。Warning 升 Alarm 時，OES 先 clear 001、再 set 002 | 警報表殘留已結束的警報 |
| R6 | **重連後用 S1F3 讀 007 校正警報表**，即使已開啟 spooling 也要做 | 斷線期間的轉態遺失，警報表與實際不符 |
| R7 | **VID 008 和 009 不可相加或相減。** 008 只排除停用的比值；009 只算 Warning（Alarm 算在 010）。要判斷「有沒有異常」，看 007 | 鎖存 Alarm 時讀到 009 = 0，誤判為正常 |
| R8 | **讀 027 前先看 028。** 027 空字串有三種原因，只有 028 分得出來（0 未設分類器、1 無電漿步驟、2 尚未判定、3 已分類、4 無法分類） | 把「還沒判定」當成「不是製程 A」 |
| R9 | **VID 030 = 1 不只是「還沒收到事件」。** 也包括視窗逾時（超過 OES 端的上限仍未收到 End）、以及事件暫不套用（OES 回放錄檔時一律如此；測試模式預設如此——此時 016 也是 1）。030 = 1 時 OES 照未使用製程事件時的方式判定。**030 = 3 只表示不在任何視窗內，與有沒有電漿無關**，有沒有電漿看 021 | 把逾時當成平台沒轉送；把「視窗外」當成「沒有電漿」 |

## 6. 與主機台製程事件的關聯

### 6.1 使用的主機台事件（PM3）

| 主機台 CEID | 事件 | 說明欄 | EAP 用途 |
|---|---|---|---|
| 3100439529／3100439530 | PM3 ProcessStart／End | Chamber Process／Chamber precoat | **製程 A 視窗**：OES 判定有效 |
| 3099591660／3099591661 | PM3 ProcessStart／End | Chamber Clean | **清潔視窗**：OES 判定不適用 |
| 3100167145／3100167146 | PM3 ProcessStart／End | Auto Leak check | **主機台升壓測漏**：OES 的對照組 |
| 2697019492／2697019493 | PM3 slit door Open／Close | PM3 slit | 標註（傳送腔氣體進入 PM3） |

**Chamber Process 與 Chamber precoat 的 CEID 相同。** 兩者是同一個製程，差別只在 precoat 沒有放晶圓。從 CEID 分不出來，OES 從光譜也分不出來（兩者都會判為製程 A）。處理方式見 6.3。

### 6.2 視窗定義

EAP 依主機台事件維護 PM3 的「目前視窗」：

| 視窗 | 開始 | 結束 | OES 警報的意義 |
|---|---|---|---|
| `PROCESS_A` | 3100439529 | 3100439530 | **有效**：製程 A 電漿中偵測到漏氣 |
| `CLEAN` | 3099591660 | 3099591661 | **不適用**：OES 的比值組不是為清潔製程設計的 |
| `LEAK_CHECK` | 3100167145 | 3100167146 | 主機台測漏中，通常沒有電漿 |
| `IDLE` | 以上皆非 | | OES 判定為 Idle 或 NoPlasma，警報不應出現；若出現，視為異常並記錄 |

**關聯規則：**
- OES 的每一筆 ALID 和每一筆 Trace 樣本，都標記收到當下 PM3 所在的視窗與視窗開始時間。
- 時間基準用 **EAP 收到訊息的時間**。OES 的 S6F11 與 S5F1 不帶設備時間戳；暫存（spooled）訊息到達較晚，以 S6F23 取回時要另外標記「延遲到達」。
- 警報跨視窗（例如 PROCESS_A 期間 set，結束後才 clear）時，以 **set 時的視窗**為準。

### 6.3 有沒有晶圓（Chamber Process vs. precoat）

EAP 目前不知道 ProcessStart 時 PM3 裡有沒有晶圓（列為待補需求，見第 10 節）。第一階段：

- **兩者用同一條規則**：OES 判定在兩者期間都有效。precoat 時漏氣一樣是漏氣，而且是在**第一片晶圓進腔之前**發現，處理價值最高。
- **完整保存每個 PROCESS_A 視窗的開始與結束時間。** 之後平台補上晶圓資訊時，可以用時間戳回頭判斷每一筆 OES 警報當時有沒有晶圓、影響哪些 Lot。

### 6.4 交叉驗證

| 檢查 | 條件 | 不符時代表 |
|---|---|---|
| OES 製程類別 | `PROCESS_A` 視窗內，028 = 3 時 027 應為 `A` | 對時錯誤、腔體對應錯誤，或 OES 分類規則需要重調 |
| 電漿有無 | `PROCESS_A` 視窗內，021 應為 1 | OES 的電漿門檻設太高，該製程完全沒被判定 |
| 主機台測漏對照 | 每次 `LEAK_CHECK` 的結果與前後 OES 讀值並排保存 | 累積起來就是 OES 漏報、誤報的實地證據 |

第一項的意義在 OES 使用製程事件後改變：030 = 2 時，027／028 已經是事件給的值，比對它等於比對平台自己。此時改看下一節的「視窗一致」；OES 端若同時開著光譜分類器，分類結果與視窗不符會由 OES 記一筆 `ToolEventClassMismatch`。

### 6.5 把主機台事件轉送給 OES（S2F41 `TOOL_EVENT`）

OES 只看光譜，不知道主機台此刻在跑哪個製程。平台把主機台的 PM3 製程事件**原樣轉送**給 OES，OES 依自己的對照表開關製程視窗，指定了製程類別的比值（現場設定為 `A`）只在 Chamber Process／precoat 視窗內判定，Chamber Clean 期間不會拿製程 A 的基準去判。

**這是資訊轉送，不是控制命令**：OES 收到後只更新製程視窗，不啟停採集、不解除警報、不改任何設定。第 7 節「不對設備下控制命令」的原則不變。

**要轉送的 CEID：** 至少 6.1 表中的 PM3 製程事件：

| 主機台 CEID | 事件 | OES 對照表（設備端設定） |
|---|---|---|
| 3100439529／3100439530 | Chamber Process／precoat Start／End | 類別 `A` 的 Start／End |
| 3099591660／3099591661 | Chamber Clean Start／End | 類別 `B` 的 Start／End |

**可以不加篩選地轉送**整台主機台的事件：OES 對照表沒有的 CEID 回 HCACK 0、只記錄不處理，不必在平台另外維護過濾清單。

**訊息格式**（完整定義見 `Satellite_SECS_Specification_v2.md` §7）：

```
S2F41 W
<L[2]
  <A[10] "TOOL_EVENT">
  <L[2]
    <L[2] <A[4] "CEID"> <A[10] "3100439529"> >
    <L[2] <A[4] "TIME"> <A[16] "2026102314030000"> >    # 選填，主機台事件的發生時間
  >
>
```

- `CEID`：必填，ASCII 十進位數字（亦接受 U1／U2／U4／U8）。
- `TIME`：選填，`YYYYMMDDhhmmsscc` 或 `YYYYMMDDhhmmss`（本地時間）。**建議帶上**主機台事件的時間戳，平台轉送有延遲時，OES 的日誌仍記得正確的事件時間。格式錯誤時 OES 回 HCACK 3、**該事件不採用**。

**回覆碼：**

| HCACK | 意義 | 平台的處理 |
|---|---|---|
| 0 | 收下（或 CEID 不在 OES 對照表，記錄後不處理） | 正常 |
| 1 | OES 的 profile 沒有 `TOOL_EVENT`（舊版 profile） | 通知設備工程師補 profile（見 10.2） |
| 2 | OES 未啟用製程事件，或不在 ONLINE／REMOTE | 通知設備工程師；持續轉送無害 |
| 3 | 參數錯誤（缺 `CEID`、`CEID` 無法解讀、`TIME` 格式錯誤、參數名稱不對） | 修正轉送格式 |

**轉送後的確認：** S1F3 讀 VID 030～032。032 會立刻變成剛送的 CEID；030／031 在 OES 的**下一幀光譜**才更新（採集停止時不會變）。

| PM3 狀態（平台的視窗） | 預期的 OES VID 030／031 | 不符時代表 |
|---|---|---|
| `PROCESS_A` | 2 ／ `A` | 轉送漏了、OES 未啟用、或 OES 正在回放／測試模式（016 = 1） |
| `CLEAN` | 2 ／ `B` | 同上 |
| 其他 | 3 ／ 空字串（重新啟動後尚未收到邊界時為 1） | 漏轉了某個 End |

**OES 端的保護規則**（平台不需處理，但看日誌時要知道）：視窗開著又收到 Start 會關舊開新；對不上的 End 會被忽略；視窗開太久（OES 端預設 600 秒）未收到 End 會作廢並回到「狀態不明」。三種情況 OES 都記警告。

## 7. 第一階段動作：記錄與通知

**不扣貨、不 Hold 腔體、不對任何設備下控制命令。**（6.5 的 `TOOL_EVENT` 是把主機台事件轉送給 OES 的資訊轉送，不屬於控制命令。） 原因：OES 在這台機台的偵測能力尚未經實地驗證（`leak-monitor-plan-zh-TW.md` §16.1 的結論為 NO-GO），且 2026-09 曾因基準擷取錯誤整天顯示 Alarm。先累積誤報率，再決定是否放權。

| 觸發 | 條件 | 通知對象 | 內容 |
|---|---|---|---|
| ALID `10327002` set | VID 016 = 0 | 設備工程師 | 時間、PM3 視窗、ALTX、當下 VID 001／004／013 |
| ALID `10327012`～`014` set | 不論 016 | 設備工程師 | 時間、ALTX；註明「OES 已停止量測」 |
| VID 015 由 0 變 1 | VID 016 = 0 | 設備工程師 | 「OES 基準已不適用，需重抓 Golden Run」 |
| CEID `10327502` | — | 不通知，只記錄 | 解除時間、警報持續時間 |
| ALID `10327001` set | — | 不通知，只記錄 | Warning 次數納入月報 |

通知範例：

```
[OES PM3] 洩漏警報 (Alarm)
時間：2026-10-22 14:03:11
PM3 視窗：PROCESS_A（開始於 14:01:40）
OES：CH3 OES LEAK ALARM composite=3, 2 alarm / 0 warning of 3 ratios
漏率：2.4E-3 mbar·L/s（有效）　基準：Recipe 1
處理：請至 OES 畫面確認並由操作者按 Acknowledge
```

## 8. 資料保存

| 資料 | 建議結構 | 保存期限（建議） |
|---|---|---|
| OES 警報 | 一筆一列：ALID、set 時間、clear 時間、ALTX、set 時的 PM3 視窗、是否測試資料（016）、是否延遲到達 | 永久 |
| OES 事件 | 一筆一列：CEID、時間、報告內容 | 永久 |
| OES Trace | 時序資料：時間、各 VID 值、PM3 視窗 | 1 年 |
| PM3 視窗 | 一筆一列：類型、開始、結束、主機台 CEID | 永久（之後補晶圓資訊要用） |
| 主機台測漏對照 | 每次 LEAK_CHECK：開始、結束、主機台結果、前後 10 分鐘 OES 007／001 摘要 | 永久 |

OES PC 本身也保存 SECS 收送日誌（`Log\secs_YYYYMMDD.log`）與 Ratio CSV，雙方有爭議時可以互相對照。

**月報建議**：Alarm 次數（依視窗分類）、每次 Alarm 的處理結果（真漏／基準問題／不明）、OES 斷線時數、與主機台測漏結果的一致率。這份統計是第二階段「是否放權」的依據。

## 9. 驗收方式

不需要真的漏氣。OES 的 Replay 分頁可以播放一段記錄過的漏氣錄檔（Normal → Warning → Alarm）。

| # | 步驟 | 預期 |
|---|---|---|
| 1 | EAP 連線，跑完第 3 節初始化 | 每一步回覆碼為 0；S1F11 名單與第 4.1 節一致 |
| 2 | OES SECS 分頁勾選 **Report test / replay data too**，播放漏氣錄檔 | EAP 依序收到 `10327001` set → `10327001` clear + `10327002` set |
| 3 | 檢查步驟 2 的資料 | **全部標記為「非量測」（VID 016 = 1），且沒有發出通知**（驗證 R2） |
| 4 | 操作者在 OES 按 Acknowledge | 收到 `10327002` clear 與 CEID `10327502` |
| 5 | Alarm 期間拔掉網路線 30 秒再接回 | 重連後警報表正確；暫存訊息取回且標記延遲（驗證 R6） |
| 6 | 取消勾選 **Report test / replay data too** 後再播一次 | **收不到 ALID**；但 S1F3 讀 007 仍會變化 |
| 7 | 在主機台跑一次 PM3 Chamber Process | EAP 建立 PROCESS_A 視窗，並把 Start／End 以 `TOOL_EVENT` 轉送：HCACK 0；視窗內 VID 030 = 2、031 = `A`，End 之後 030 = 3；032 為最後送出的 CEID |
| 8 | 轉送一個 OES 對照表沒有的 CEID（例如 slit door） | HCACK 0；VID 032 更新、030 不變 |
| 9 | 送一筆 `TIME` 格式錯誤的 `TOOL_EVENT` | HCACK 3，該事件不採用 |
