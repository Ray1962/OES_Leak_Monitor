1. 目的與適用範圍

1.1 監控目的

在製程腔體上以光纖取電漿自身的發光，用比值法（actinometry）即時判斷是否有空氣（氮、氧、水氣）漏入製程腔。

空氣漏入會改變某些物種的發光強度，而製程本身供應的參考譜線維持不變 —— 用比值而非絕對強度，是為了消掉功率、壓力、觀察窗汙染這類與洩漏無關的漂移。

⚠️ 「哪些物種會上升」必須在你的機台上實測確認，不能照抄。 常見的假設是 O、OH、NO、N₂⁺ 同時上升；但在一台 Ar 80 sccm / 0.95 torr / RF 50 W 的實機上，對 100 單位的空氣洩漏實測（皆已除以 Ar 750.4）：

譜線反應譜線反應
N₂ 337.1+71.0%（33.8σ）O 777.2+3.2%（0.7σ）
NO 237+57.1%（18.3σ）N₂⁺ 391.4+4.5%（0.8σ）
N₂ 357.7+41.6%（16.2σ）OH 308.9+0.0%（0.1σ）

也就是說：氮是示蹤物，氧完全不動，而常被當成「高敏感早期指標」的 N₂⁺ 391.4 一點反應也沒有。壓力、功率、氣體組成一變，會動的物種就可能換人。上線前務必依 §7 的步驟 5–7 用一次已知洩漏挑線，並依實測結果修正下面的判讀表。

漏氣在半導體製程上的後果是實質的：膜質劣化（含氧、含氮）、顆粒增加、腔體與泵浦腐蝕、真空件壽命縮短，嚴重時整批 WIP 報廢。這套系統的價值在於「在製程結果變壞之前就看到趨勢」，所以巡檢的重點不是「有沒有跳警報」，而是「趨勢有沒有在慢慢變」。

1.2 兩階段巡檢的分工

階段名稱目的需要的能力
第一階段（L1）一般性簡易巡檢只問一句話：現在跟平常一不一樣？ 不調參數、不改設定，發現異常就記錄並上報會操作介面即可（Operator 權限）
第二階段（L2）深入巡檢確認偵測策略本身還有效：基準線、譜線選擇、門檻、SNR、波長、洩漏率校正需懂製程氣體與光譜（Engineer 權限）

⚠️ L1 人員不得更改任何設定。 調整門檻、換譜線、重錄 Golden Run 一律屬於 L2。 L1 若「因為一直跳警報就把門檻調高」，等於關掉這套系統。

1.3 不在本計畫範圍內

  • 光譜儀硬體本身的計量校正（送校）。
  • 腔體的實體檢漏（氦質譜檢漏、升壓率測試）——本系統是線上早期指標，確認漏點仍需實體檢漏。
  • 機台的製程參數調整。

4. 第一階段（L1）每日巡檢

原則：由「光」到「數」——先看光譜長相（§4.1），再看時間趨勢（§4.2），最後才看系統給的結論（§4.3）。反過來只看警報燈，會漏掉「還沒到門檻但已經在爬」的緩漏。

4.0 步驟 0 — 連線與擷取狀態（30 秒）

在 Monitor 分頁確認：

  • ☐ Test Mode = False
  • ☐ Frame 每幀點數與平常一致（例如 2048），沒有變成 1000（測試模式的點數）
  • ☐ Last（最後一幀時間）在數秒內持續更新——停住代表擷取已中斷
  • ☐ Serial（序號）與該機台配掛的光譜儀相符

任一項不符 → 停止判讀，直接進入 §8 升級流程。

4.1 步驟 1 — 檢查電漿強度光譜【重點一】

畫面：Monitor 分頁上半部的全譜圖（DevicePanel）。操作：滑鼠滾輪縮放、右鍵 → Zoom All（快捷鍵 A）回到全譜。

看五件事，由粗到細：

(1) 整體強度水準

  • 全譜最高峰的計數值與前次巡檢相比，變化應在 ±20% 以內。
  • 明顯偏低（例如掉到 70% 以下）→ 觀察窗汙染、光纖鬆脫或彎折、電漿功率下降。
  • 明顯偏高 → 有人改過積分時間，或製程條件改變。

⚠️ 強度絕對值的變化本身不是洩漏。洩漏看的是比值（§4.3）。但強度大幅下降會讓譜線掉進雜訊底， 使系統進入 Low Signal 而失去偵測能力——這才是要抓的。

(2) 訊號飽和（削頂）

  • ☐ 沒有任何峰的頂端呈現平頂／被切平的形狀。
  • 飽和代表該波長已超出偵測器量程，強度讀值不再正確，比值必然失真。
  • 發現飽和 → 記錄並上報（L2 需縮短 Integration Time 後重錄 Golden Run）。

(3) 基線（暗背景）水準

  • 譜線之間的「谷底」應接近平坦且貼近零；若整條基線被整體抬高，通常是雜散光、外部漏光（機台門開著、維修燈照到觀察窗）或偵測器溫度異常。
  • ☐ 巡檢時確認腔體觀察窗附近沒有外部光源照入。

(4) 關鍵譜線是否都在、形狀是否正常

對照該機台的標準光譜照片（L2 於策略定案時拍存，見 §7.1 步驟 7），逐一確認下列譜線存在且峰形對稱：

譜線波長角色
N₂ (SPS)337.1 nm常用參考線／電漿存在判定
OH308.9 nm洩漏指標（水氣）
NO237.0 nm洩漏指標（N+O 反應產物）
O777.2 nm洩漏指標（氧原子）
Ar750.4 / 811.5 nm參考線（若製程有通 Ar）
N₂⁺391.4 nm空氣漏入的高敏感指標（若策略有納入）
  • ☐ 峰形對稱、無分裂、無明顯變寬 ——變寬或偏移見手冊 §9.3（多為硬體平均模式問題）。
  • ☐ 沒有新出現的、平常不存在的峰。新峰的常見來源：金屬（Fe 372 / Cr 425 / Al 396 → 腔體或載具被濺射）、CN 388（有機物或 O-ring 被侵蝕）、H 656（水氣或有機物）。新峰一律記錄並上報。

(5) 幀完整性

  • ☐ 光譜沒有出現斷裂／撕裂（波形中間出現不連續的階梯或錯位段）。
  • 這是 Z5／乙太網路機種在長積分時間下的已知現象，處置是 L2 把 Acquire Mode 改為 Oneshot（手冊 §9.2）。

4.2 步驟 2 — 檢查電漿強度趨勢【重點二】

畫面：Monitor 分頁下半部的 Wavelength Trend（時間 vs 強度，保留 30 分鐘）。

這張圖畫的是每幀原始計數（刻意不濾波），最多 6 條線：Trigger 波長 ＋ Monitored Wavelengths 前 5 個。

建議巡檢操作順序：

  1. 先按 Zoom All 看完整 30 分鐘。
  2. 勾 Smooth（τ ≈ 3 s EMA）——雜訊被壓下去後，緩慢的趨勢才看得出來。切換時歷史也會一起重算。
  3. 再勾 Normalize——所有線以「勾選當下」為 1.0，這時看的是各線之間有沒有分歧。 洩漏的特徵就是「洩漏指標線往上跑、參考線持平」，正規化後一眼可辨。
  4. 判讀完取消 Normalize，把畫面留在原始狀態給下一班。

檢查四件事：

#檢查項正常異常樣態
1平穩度各線在 30 分鐘內圍繞水平帶波動有線單調上升／下降
2同步性所有線一起動（功率、壓力波動的正常表現）只有部分線在動 → 化學組成真的變了
3階梯跳動無出現方波狀突跳 → 有人改參數、或幀撕裂
4訊號中斷曲線連續出現斷點／歸零 → 擷取中斷或電漿熄滅

判讀的關鍵是「同步 vs 分歧」：

  • 全部線同步緩降（正規化後仍重疊）→ 光路問題（觀察窗汙染、光纖），不是洩漏。
  • O／OH／NO 上升而 N₂ 或 Ar 持平（正規化後明顯分岔）→ 高度懷疑空氣洩漏，即使 Leak Monitor 尚未跳警報，也要立即記錄並上報。這是本系統最有價值的一個判讀，也是把「巡檢」做成「預警」的關鍵。

💡 每條趨勢線取的是該波長 ±0.5 nm 內的峰值（吸收波長漂移用的峰值定位，不是濾波）， 所以小幅波長漂移不會讓線掉下去；若某線莫名掉到接近零，多半是漂移已超過 ±0.5 nm，或該峰真的消失了。

4.3 步驟 3 — Leak Monitor 狀態與比值列

畫面：Leak Monitor 分頁。這一步是看「系統的結論」，但要用前兩步的觀察去驗證它。

  • ☐ 狀態橫幅：應為綠色 OK — within baseline。
    • 灰色 Idle → 沒電漿或沒基準線（若製程正在跑卻顯示 Idle，屬異常，上報）。
    • 橘 WARNING / 紅 ALARM → 進入 §8 處置流程。
  • ☐ 沒有「LOW SIGNAL」警示。出現代表有比值的譜線太靠近雜訊底，該比值已被排除在警報判定之外——系統的偵測能力已經缺一角，必須上報（處置見手冊 §9.4，屬 L2）。
  • ☐ 沒有「測試模式」註記。
  • ☐ Baseline 下拉選的是今天這支配方對應的基準線。選錯基準線 = 拿別的配方當標準，全部判讀作廢。這是實務上最常見的人為錯誤，每次巡檢都要確認。
  • ☐ 逐條比值列，記錄下列數值到巡檢表：
欄位L1 判定
狀態應為 Normal（綠）
% of baseline100 ± 10% 視為正常；110–120% 記為「觀察」；> 120% 為異常（已達預設 Warn factor）
斜率應接近 0；持續為正即使百分比還低，也記為「觀察」
SNR應 > 10；5–10 記為「觀察」（逼近預設下限 5）；< 5 該比值已被停用
baseline (mean ± σ)與前次巡檢應完全相同——數值變了代表基準線被重錄過，須確認是誰、為什麼
  • ☐ 趨勢圖（% of baseline，30 分鐘）：所有比值曲線應在 100% 附近水平擺動。任何一條呈現持續上升，即使還在門檻以下，都要記錄。
  • ☐ 洩漏率讀值（若已做校正）：記錄數值與 confidence。
    • 顯示 calibration "X" needs its baseline … → 校正與目前基準線不配對，估算已暫停，上報。

4.4 步驟 4 — 資料記錄器與儲存空間

畫面：Monitor 分頁的 Recorder 狀態列（Reset Run 下方那條，唯讀，不需權限即可檢視）。

  • ☐ 徽章不是紅色 OFF —— OFF 代表全光譜記錄器沒武裝，不會產生強度 CSV（比值 CSV 不受影響，仍照常寫）。有電漿時應為 SAVING；沒電漿時 ARMED 為正常。
  • ☐ 沒有橘色「not saved」小字 —— 出現代表武裝狀態沒寫進 settings.json，下次重開就會失效（需工程師補按 Configuration 的 Save）。
  • ☐ SAVING 時右側有檔名，且滑鼠停留可看到完整路徑。
  • ☐ 當日的 Data\YYYYMM\DD\ 資料夾內有今天的 CSV，且檔案大小持續成長。
  • ☐ 資料碟剩餘空間 > 20%。程式不會刪除任何量測資料；餘量低於 10% 時它會在開／關程式時跳出警告（手冊 §7.4）。若該機台已啟用自動壓縮，過期資料會變成 DD.zip —— 壓縮不是刪除，回放也不受影響：Recordings / Ratio Review 會直接讀壓縮檔，清單上標示 zip。

兩份檔案的產生條件不同（手冊 §7.3）：

  • 強度 CSV（_OES1_）只在記錄器武裝且強度高於觸發門檻時才寫 —— 當班沒跑電漿就沒有檔案，屬正常。
  • 比值 CSV（_Ratio_）只要 OES 在擷取就一直寫，跨午夜會自動換日換檔。擷取中卻沒有今天的比值檔 = 異常（手冊 §9.8），因為這代表洩漏監控的歷史沒有被留下來，每週 L2 的回放審查（§6.6）會沒有資料可看。

⚠️ 武裝／解除武裝在 Engineer 權限的 Configuration 分頁，L1 人員無法也不需要操作 —— 只負責看狀態列並回報。這是一次性設定，不是每日動作。

4.5 步驟 5 — 系統日誌快掃

畫面：Logs 分頁，掃過上一班次的記錄。

  • ☐ 無 Error 等級記錄。
  • ☐ 無 GoldenRunRatioLowSnr（基準線被拒絕）。
  • ☐ 無 LeakCalibrationSuspended（洩漏率校正被暫停）。
  • ☐ 無非預期的 RatiosReloaded / 設定變更記錄——代表有人動過設定，須確認是否為授權變更。

6. 第二階段（L2）深入巡檢

L2 的核心問題不是「今天有沒有漏」，而是：「這套偵測策略，今天還抓得到漏嗎？」 一套門檻設得太鬆、基準線過期、譜線已掉進雜訊的系統，會天天顯示綠燈，然後在真的漏氣時什麼都不說。

檢查項合格條件不合格處置

⚠️ 重錄 Golden Run 的前提是「確定此刻沒有洩漏」。 若在已經慢漏的狀態下重錄， 等於把漏氣狀態定義成正常——系統從此永遠不會報警。重錄前應先完成一次實體檢漏或升壓率測試。 這是整套系統最重要的一條紀律。

6.2 訊噪比與光路健康度

  • 記錄各比值目前的 SNR 值，與前次 L2 比較，做成長期趨勢（本系統不會自動畫 SNR 長期圖，請記在巡檢表上）。
  • SNR 逐月下降 → 光路劣化（觀察窗鍍膜、光纖老化）。在掉到門檻（預設 5）以前就要處理，不要等到 Low Signal。
  • 參考線（N₂ 337 或 Ar 750）的絕對強度也一併記錄，作為觀察窗汙染速率的指標。
  • 處置順序（同手冊 §9.4）：拉長 Integration Time → 提高 Average Count（配 Software 平均）→ 檢查光纖與觀察窗 → 該線本來就弱則改 AbsoluteIntensity 模式 → 最後手段才是調低 Min SNR（不可設為 0）。
  • 每次更動積分時間或平均設定後，必須重錄 Golden Run（曝光條件變了，舊基準線無效）。

6.3 波長漂移查核與校正

  1. 在 Monitor 全譜圖上放大一條已知波長且明確的譜線（建議 N₂ 337.1 nm 或 Ar 750.4 nm）。
  2. 讀出實際峰位，與標稱值相減。
  3. 判定：
偏差處置
≤ 0.1 nm合格，不動
0.1–0.5 nm到 Wavelength Calibration 分頁登記該譜線的偏移量
> 0.5 nm異常，先查機械／溫度／光譜儀本身，再談校正（上限 ±5 nm）
  1. 存檔後必須回 Monitor 分頁 Stop → Start 才生效（暫存機制）。
  2. 校正會改變擷取窗位置 → 重錄 Golden Run。

波長修正是依「物種＋波長」對整份目錄生效的，所以修一次，所有用到該譜線的比值（訊號線或參考線） 一起對齊。不需要逐條比值去改。

6.4 洩漏偵測策略複核【L2 核心】

依序回答六個問題，任何一個答不出「是」，就要重新走 §7 的策略制定流程。

#問題判斷依據

2參考線選得對嗎？參考線物種是否由製程穩定供應、且與洩漏無關？流量會隨步驟變動的氣體不適合當參考線

6.5 洩漏率校正驗證（有做定量的機台）

  1. 確認目前 Baseline 與校正配對（狀態顯示 Active，不是 BaselineMismatch）。
  2. 以標準漏孔（calibrated leak）通入已知漏率，讀取 Leak Monitor 的洩漏率估計值。
  3. 判定：偏差 ≤ ±30% 視為合格（本系統定位是趨勢預警，不是計量儀器）；偏差過大則重做校正（Leak Calibration 分頁）。
  4. ☐ 確認校正用的氣體是空氣（或與待測洩漏相同的氣體）——用惰性氣體做的校正無法對應 O／OH／NO 的上升。
  5. 記錄本次驗證的漏率、讀值、偏差百分比。

6.6 誤報／漏報審查（回放）

  • 到 Ratio Review 分頁，回放過去一週的比值資料。
    • 對每次曾發生的 WARNING / ALARM：是持續上升（真事件）還是短暫尖峰（雜訊／製程切換瞬態）？
    • 短暫尖峰多 → 提高 Confirm time（預設 15 s）比調高門檻更好，不會犧牲靈敏度。
  • 到 Recordings 分頁，抽查一組完整光譜，確認 CSV 有正常落地且可重新解析。
  • 統計本週：誤報次數、漏報（事後才由其他手段發現的洩漏）次數，記入巡檢表。漏報一次就必須重新檢討策略。
  • ☐ 本週若動過偵測設定（比值定義、抽取模式、門檻、波長校正），依操作手冊 §8.5 做一次重播驗證：拿本機曾經真的跳過警報的那段錄檔重播一次，確認新設定仍然抓得到，而且不會比原本晚。不需要硬體、不會影響生產。改了設定卻沒驗過，等於把「還抓不抓得到」留到下次真的漏氣時才知道。

7. 洩漏偵測策略制定流程（L2 專用）

新機台導入、換製程、或 §6.4 複核不合格時走這套流程。

7.1 七個步驟

步驟 1 — 列出製程氣體與副產物。 把該配方所有進氣（含清洗步驟的 NF₃／O₂／Ar）與已知副產物列出來。這一步決定後面全部。

步驟 2 — 選洩漏指標（訊號線）。 原則：該物種必須是製程本身不會產生的。空氣漏入的候選指標：

指標波長特性
O777.2 nm強、易測；但製程若通 O₂／N₂O／CO₂ 則不可用
OH308.9 nm對水氣／潮濕漏點敏感；製程含 H 源（SiH₄、NH₃、H₂）時背景偏高
NO237.0 nmN＋O 反應產物，同時需要氮和氧才會出現，對「空氣」的專一性高；訊號較弱
N₂⁺391.4 nm對空氣漏入極敏感的早期指標；受電子溫度影響，需配對穩定的參考線
N₂337.1 nm製程通 N₂／NH₃／N₂O 時不能當指標，只能當參考線

步驟 3 — 選參考線。 原則：製程穩定供應、流量在該步驟中不變、且與洩漏無關。優先順序：

  1. Ar 750.4 / 811.5 nm —— 若製程有通固定流量的 Ar，這是最理想的 actinometer。
  2. N₂ 337.1 nm —— 製程本身大量供應 N₂ 時可用（但此時 N₂ 就不能當指標）。
  3. Hα 656.3 nm —— 製程含穩定 H 源時可用。

步驟 4 — 決定監測模式。 訊號線在該機台上 SNR 穩定 > 10 → Ratio（預設，能抵銷電漿條件漂移）。 訊號線先天很弱、SNR 徘徊在 5 附近 → AbsoluteIntensity（少一個雜訊來源，但不再抵銷漂移）。

步驟 5 — 錄基準線並觀察一週。 在確定無洩漏（剛做完檢漏）的狀態下 Capture Golden Run，先不設嚴格門檻，讓它跑一週，用 Ratio Review 看正常波動帶有多寬。

步驟 6 — 依實測波動帶設定門檻。 見 §7.4。門檻要根據實測的雜訊帶決定，不要沿用預設值就上線。

步驟 7 — 用標準漏孔驗證，並存檔基準文件。 通入已知漏率，確認：(a) 系統確實會報；(b) 報的時間延遲可接受；(c) 上升的是預期的那幾條比值。 驗證通過後，截圖存檔該機台的「標準光譜」與「正常趨勢」，作為日後 L1 巡檢的比對基準，並備份 settings.json。

L3 停機洩漏率持續攀升、伴隨製程異常或膜質異常加通報部門主管立即依廠內規定評估暫停投料、隔離 WIP

ALARM 發生時的處置流程

  1. 記錄狀態橫幅出現的時間、洩漏率讀值與 confidence、當時的配方與步驟。
  2. 判定型態——看哪幾條比值進了 ALARM：
    • O／OH／NO（或 N₂⁺）同時上升 → 典型空氣洩漏，繼續步驟 3。
    • 只有單一條上升 → 優先懷疑譜線干擾或製程變化（對照 §7.3），仍需查證。
  3. 回放確認：到 Ratio Review 看這段時間是持續上升還是短暫尖峰。持續上升才是真事件。
  4. 關聯比對：與機台自身的真空度、壓力、RF 反射功率、腔體升壓率記錄交叉比對。
  5. 實體檢查：O-ring、法蘭、觀察窗、閥件、波紋管、feedthrough；必要時做氦質譜檢漏確認漏點。
  6. 修復並驗證：修復後跑一段製程，確認比值回到 100% 附近。
  7. 清除鎖存：確認排除後，按 Acknowledge Alarm（Operator+）。警報是鎖存的，不會自己消失——這是刻意設計，不要用重開程式來「清警報」。
  8. 結案記錄：填寫異常單，含根因、處置、驗證結果；若基準線在漏氣期間被人重錄過，必須重新錄一次。

⚠️ 絕對禁止：以「調高門檻」「關閉該比值」「重錄 Golden Run」作為 ALARM 的處置手段。 這三個動作都會讓警報消失，但漏氣還在。任何一項若確有必要，須由工程師在確認無洩漏之後執行並記錄。
