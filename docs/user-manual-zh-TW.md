## 1. 這個軟體在做什麼

OES Leak Monitor 用**光學發射光譜（OES）**即時偵測製程腔體的**空氣洩漏**。

核心方法是 **actinometry（比值法）**：

- 空氣漏進電漿後，會改變某些物種的發光強度 —— **哪些物種，取決於你的電漿**（見下方警告）。
- 但譜線的絕對強度也會隨電漿功率、壓力、氣流、窗口髒污而漂移 —— 直接看絕對強度會誤判。
- 所以把「訊號譜線」除以一條**參考譜線**。電漿條件漂移會同時放大／縮小兩者，相除後被抵消，剩下的變化就主要來自洩漏。

> ⚠️ **哪些譜線會對洩漏起反應，是你機台的實驗結果，不是常識。**
>
> 教科書上的 actinometry 多半拿 **O 777.2 / Ar** 當空氣洩漏指標，本軟體早期的出廠預設比值也是照這個假設配的。但在一台 **Ar 80 sccm、0.95 torr、RF 50 W** 的實機上實測：**O 777.2 對 100 單位的空氣洩漏只有 0.7σ 的反應（等於沒有），而 N₂ 337.1 有 33.8σ** —— 分子與分母的角色完全反了過來。
>
> 壓力、功率、氣體組成一變，會動的物種就可能換人。**上線前一定要用一次已知洩漏實測，確認哪條線真的會動**（見 §1.1）。跳過這一步，監控器會看起來一切正常而完全抓不到洩漏。

### 1.1 上線前必做：用一次已知洩漏挑譜線

1. 讓製程在**正常條件**下穩定，錄一次 Golden Run。
2. 用針閥或標準漏孔，分幾個階段引入空氣，**每階維持至少 60 秒**。階數越多越好 —— 三階只能看出有沒有反應，九階才能看出線性與偵測下限。
3. 事後用 Recordings 分頁比對「基準期」與「最大洩漏期」的平均光譜。
4. 挑出變化最大的譜線 —— 但**一定要先除以一條惰性參考線**（Ar 750.4 或 811.5）。洩漏常會讓整個光譜一起亮 5–10%，那是電漿阻抗改變，不是化學變化；不除掉它，每條線看起來都有反應。
5. 用挑出來的線設定比值（§6.4），重錄 Golden Run，再跑一次洩漏測試，確認警告／警報會在你要的劑量觸發。

> **判斷標準不是「變化幾 %」，而是「變化是雜訊的幾倍」。** 一條變化 +50% 但基準散度 8% 的線（6σ），不如一條變化 +17% 但散度 2% 的線（8.5σ）。Golden Run 會把每個比值的 σ 記下來，用它來比。

前述那台機器的實測結果，可以當作這個程序的範例（100 單位空氣洩漏，全部已除以 Ar 750.4）：

| 譜線 | 基準散度 | 變化 | **偵測力** | 判定 |
|---|---|---|---|---|
| N₂ 337.1 | 2.1% | +71.0% | **33.8σ** | 主指標 |
| NO 237 | 3.1% | +57.1% | 18.3σ | 次指標 |
| N₂ 357.7 | 2.6% | +41.6% | 16.2σ | 可用 |
| N 746.8 | 6.2% | +64.7% | 10.4σ | 太吵 |
| O 777.2 | 4.3% | +3.2% | 0.7σ | **無反應** |
| N₂⁺ 391.4 | 5.7% | +4.5% | 0.8σ | **無反應** |
| OH 308.9 | 0.7% | +0.0% | 0.1σ | **無反應** |

軟體會：

1. 在無洩漏的良品製程中錄下**基準線（Golden Run）** —— 每個比值的平均值與標準差 σ。
2. 即時計算比值，做 EMA 平滑，與基準線比較。
3. 超過警告／警報門檻並**持續一段時間**後才升級狀態（避免瞬間雜訊誤報）。
4. 若做過**洩漏率校正（Leak Calibration）**，還會把比值上升量換算成**定量洩漏率 Q̂（mbar·L/s）**。

同時它也是一台資料記錄器：當指定波長的強度超過門檻時，自動開檔記錄光譜 CSV 與比值 CSV，事後可在 Recordings / Ratio Review 分頁回放。

## 2. 安裝與啟動

### 2.1 標準安裝（免安裝 .NET）

發布產物是一個資料夾，內含單一 `.exe` 與數個原生 DLL：

```
OES_Leak_Monitor.exe          ← 主程式（已內含 .NET 8 執行環境）
UserApplication.dll           ← OES 硬體 SDK
SiUSBXp.dll                   ← USB 驅動介面
libsodium.dll                 ← SDK 相依
vcruntime140.dll              ← 以下三個是 libsodium.dll 需要的 VC++ 執行階段
vcruntime140_1.dll
msvcp140.dll
wpfgfx_cor3.dll               ← 以下為 WPF 原生元件
PresentationNative_cor3.dll
D3DCompiler_47_cor3.dll
PenImc_cor3.dll
vcruntime140_cor3.dll
user-manual-zh-TW.html        ← 本手冊
daily-inspection-plan-zh-TW.html
```

> ⚠️ **整個資料夾要一起複製，不能只拷貝 `.exe`。**
> 那幾個 DLL 是刻意放在 `.exe` 旁邊的 —— SDK 的 `DllResolver` 只會在程式所在目錄找它們。少了 `UserApplication.dll` / `SiUSBXp.dll`，程式仍會啟動，但**連線會無聲地掉進測試模式**（畫面看得到假光譜，卻連不到硬體）。

`vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll` 是隨程式一起帶的 **Visual C++ 執行階段**。`UserApplication.dll` 透過 `libsodium.dll` 相依於它，因此在**從未安裝過 Visual C++ 2015–2022 x64 Redistributable 的乾淨電腦上**，少了它們就會連 DLL 都載不起來 → 同樣無聲掉進測試模式。名字相似的 `vcruntime140_cor3.dll` 是 WPF 的私有改名副本，**不能替代**。帶著這三個檔，目標電腦就不需要另外安裝 Redistributable。

需求：64 位元 Windows。目標電腦**不需要**安裝 .NET，也不需要安裝 VC++ Redistributable。

### 2.2 啟動

雙擊 `OES_Leak_Monitor.exe`。首次啟動會在 `%APPDATA%\OES_Leak_Monitor\` 建立設定與資料夾。

### 2.3 測試模式（無硬體）

沒接到光譜儀時，按 **Connect** 會自動退回**測試模式**，產生合成光譜（正弦波＋雜訊，約 200–800 nm、1000 點）。整個 UI 都能操作，適合教育訓練與功能驗證。

**怎麼一眼看出現在是測試模式**：Monitor 分頁 `DevicePanel` 底部的 **Test Mode** 會變成紅色粗體 `True`，旁邊狀態列寫出原因（滑鼠停在上面看完整句子），`Serial` 顯示 `TEST_MODE_SIMULATOR`。同時系統日誌會記一筆 **警告** `Device_TestModeFallback`，Description 就是原因。**接了硬體卻看到這些，代表硬體沒連上，資料是假的** —— 見 §9.1。

在測試模式下：

- Leak Monitor 分頁會顯示 **"test mode"** 註記，並註明目前的光譜來源是合成波形還是重播的錄檔、警報是否生效。
- **警報預設被抑制**（`SuppressAlarmsInTestMode`），比值照算照畫，但不會真的跳 ALARM。要演練警報，在 **Replay** 分頁勾 **Raise leak alarms during replay**。
- 可以在 **Replay** 分頁選一個已錄製的全光譜 CSV 來取代合成波形，用真實電漿資料驗證偵測演算法（見 §6.8 與 §8.5）。

## 3. 帳號與權限

### 3.1 四種角色

| 角色 | 等級 | 可以做什麼 |
|---|---|---|
| **Guest** | 0 | 只能看。**不能關閉程式**（必須先登入） |
| **Operator** | 1 | 連線／啟動擷取、Start/Stop Save、Reset Run、**Acknowledge Alarm** |
| **Engineer** | 2 | 以上全部，加：Configuration 分頁、Capture Golden Run、Ratio Setup 存檔、Wavelength Calibration 存檔、Leak Calibration 存檔 |
| **Admin** | 3 | 以上全部，加：**Users** 使用者管理（新增／刪除帳號、改密碼、改角色） |

### 3.2 登入

右上角工具列：

- **Sign In** — 未登入（Guest）時顯示。
- **Sign Out** — 已登入時顯示。
- **Users** — 只有 Admin 看得到。

**出廠預設帳號：`admin` / 密碼 `admin`。**

> 🔒 **請在第一次部署後立刻改掉這組密碼**（Sign In 成 admin → Users → 改密碼）。

### 3.3 自動鎖定

閒置超過 **5 分鐘**（`AutoLockTimeoutMinutes`）會自動登出回 Guest。滑鼠移動或按鍵都會重置計時。

若在 Configuration 分頁時角色掉到 Engineer 以下，畫面會自動跳回 Monitor 分頁。

## 5. 快速上手：從零到監控

第一次在一台新機台上導入，依序做完這六步：

### 步驟 1 — 連線並確認有光譜

1. 到 **Monitor** 分頁。
2. 按 **Connect**。下方狀態列的 **Test Mode** 應顯示 `False`，**Serial** 應顯示實際序號。
   - 若顯示 `True` 但硬體確實接著 → 見 §9.1。
3. 按 **Start**。全光譜圖應開始更新，**Last** 時間持續跳動。

### 步驟 2 — 調整硬體參數

1. 到 **Configuration** 分頁（需 Engineer）。
2. 設定 **Integration Time**（積分時間）：讓最強的譜線約落在滿刻度的 50–80%，不要飽和。
3. 需要降雜訊時調 **Average Count**；若發現峰位被硬體平均扭曲，把 **Average Mode** 改成 `Software`（見 §6.2.1）。
4. 按 **Apply** 推送到硬體，再按 **Save** 寫入 `settings.json`。

### 步驟 3 — 設定要監控的比值

1. 到 **Ratio Setup** 分頁。
2. 出廠預設已有四組比值，全部以 **Ar 750.4 nm** 為參考線：`N₂ 337 / Ar 750`（主指標）、`NO 237 / Ar 750`（次指標）、`N₂ 358 / Ar 750`（第三條，讓「三取二」有餘裕），以及**出廠不啟用**的 `N₂ 358 absolute`。完整規格見 §10.5。
3. 檢查你的光譜儀波段是否涵蓋這些波長 —— 涵蓋不到的請**取消勾選**或改選別的譜線。
4. 若某條訊號線太弱（接近雜訊底），把該比值的 **Monitoring method** 改成 `AbsoluteIntensity`（見 §6.3.2）。
5. 按 **Save**。
6. **⚠️ 回 Monitor 分頁按 Stop → 再按 Start**。Ratio Setup 的修改是「暫存」的，只有在擷取重啟後才生效。

### 步驟 4 — 錄基準線（Golden Run）

1. 讓機台跑一段**確定沒有洩漏**的良品製程，電漿條件穩定。
2. 到 **Leak Monitor** 分頁 → 按 **Capture Golden Run**。
3. 輸入配方／基準線名稱（例如 `Recipe-A-20260804`）。
4. 勾選「I confirm the process is currently running leak-free.」→ 按 **Start Capture**。
5. 預設平均 **60 秒**。進度條跑完後，基準線立刻寫入 `settings.json`。
6. 上方 **Baseline** 下拉會自動選到這條新基準線。
7. **若跳出視窗，先看完再繼續**：警告視窗代表有比值沒拿到基準線（那幾條不會參與警報）；**Yes / No 的確認視窗**代表這次擷取會讓同名舊基準線的某些比值消失，按 No 就什麼都不會被改動；錯誤視窗代表一條都沒拿到，這次擷取已被丟棄、舊基準線原封不動 —— 依視窗上的原因排除後重錄（見 §6.3.5 與 §9.5）。

此時洩漏偵測就已經在運作了 —— 狀態列會顯示 `OK — within baseline`。

> **製程不是一直穩定的怎麼辦？** 緩啟動（前幾秒還在爬升）或短製程（一次 run 比擷取視窗還短），現場擷取抓不到乾淨的一段。改用 **Baseline Builder** 分頁：事後從錄製檔上把穩定段挑出來，短製程還可以把好幾次 run 合起來（見 §6.7）。多步驟製程則需要每個 step 各一份基準、換 step 時人工切換。

### 步驟 5（選用）— 洩漏率定量校正

只有需要把「比值上升」讀成 **mbar·L/s** 時才要做。見 §6.5。

### 步驟 6 — 開啟資料記錄

1. **Configuration** → 下半部 **Data Logger**。
2. 設定 **Trigger Wavelength**（判斷「電漿開了」的波長，例如 337.1）與 **Save Threshold Intensity**。
3. 按 **Apply** → **Save**。
4. 按 **Start Save** 武裝觸發器。當強度持續超過門檻達 **Start Confirm Time** 後，自動開檔。

## 6. 分頁詳解

### 6.1 Monitor（即時監看）

#### 6.1.1 頂部：Reset Run

**Reset Run**（Operator+）用在「調完參數，想從乾淨的狀態重新開始這一爐」：

- 關閉目前的 Intensity CSV 與 Ratio CSV。兩者開新檔的時機不同：**Intensity CSV 要等下一次超過門檻**，**Ratio CSV 下一幀就開新檔**。
- 清空 Monitor 強度趨勢圖與 Leak Monitor 的 % 趨勢圖。
- 重置各比值的即時平滑。

**保留不動**：Golden Run 基準線、洩漏率校正、已鎖存的警報（必須由人按 Acknowledge 才清除）、擷取本身持續進行。

> **鎖存的警報也會跨越「停止 → 啟動擷取」。** 重啟擷取會套用 Ratio Setup 的暫存修改（重建所有比值），以前那個重建會把鎖存的警報一起清掉 —— 等於**不用 Acknowledge 就能讓一個已確認的洩漏消失**。現在只有「該比值被刪除、停用，或被改成量別的東西」時鎖存才會放掉，而且會在日誌記一筆 `LeakMonitorAlarmLatchDropped`。只調門檻或平滑參數不算改變量測對象，鎖存會保留。

> 若你剛改過**積分時間**或其他會影響絕對強度的設定，Reset Run 不夠 —— 請**重新錄一次 Golden Run**，因為舊基準線是在不同曝光條件下錄的。

#### 6.1.2 Recorder 狀態列（唯讀）

Reset Run 底下的細長狀態列（標示 **Spectrum recorder**），顯示**全光譜記錄器現在到底有沒有在錄**。純顯示，這裡按不到任何東西 —— 記錄器的開關與所有設定都在 Configuration 分頁（需 Engineer），但**看**狀態不需要權限，Guest 也看得到。

> 這條狀態列只講**強度（全光譜）CSV**。**比值 CSV 是另一個獨立的記錄器**，只要 OES 在擷取就一直寫，即使這裡顯示 `OFF` 也照常產生（見 §7.3）。

| 徽章 | 顏色 | 意義 |
|---|---|---|
| `OFF` | 紅 | 記錄器**沒有武裝** —— 不會產生強度 CSV（比值 CSV 不受影響，見 §7.3） |
| `ARMED` | 藍 | 已武裝，等待強度跨過觸發門檻。右側會寫出目前的門檻條件 |
| `STARTING` | 橘 | 已高於門檻，正在等 Start confirm 時間 |
| `SAVING` | 綠 | 正在寫強度 CSV，右側顯示**目前檔名** |
| `STOPPING` | 橘 | 已低於門檻，正在等 Stop confirm 時間 |

滑鼠停在狀態列上會顯示**完整檔案路徑**（沒有開檔時則顯示開檔條件）。

若右側出現橘色小字 **「armed but not saved — reverts to OFF on restart」**，表示有人在 Configuration 分頁按了 Start Save 卻**沒有按 Save** —— 目前確實在錄，但這個狀態沒有寫進 `settings.json`，**下次重開程式就會變回 OFF**。回 Configuration 按一次 **Save** 即可消除。反向的「disarmed but not saved」同理。

> 💡 每日巡檢的第一眼就看這條 —— 它是「以為在錄、其實沒錄」這個失效模式唯一的可見警示。

#### 6.1.3 裝置控制列（DevicePanel）

| 按鈕 | 作用 |
|---|---|
| **Connect** | 連線光譜儀。找不到硬體時退回測試模式 |
| **Disconnect** | 中斷連線 |
| **Start** | 開始連續擷取 |
| **Stop** | 停止擷取（Ratio Setup / Wavelength Calibration 的暫存修改就是靠 Stop→Start 生效） |
| **Save CSV** | 把目前這張光譜存成 CSV，**同時凍結一條疊圖**在圖上當參考 |
| **Clear Spectrum** | 清掉所有由 Save CSV 疊上去的參考光譜 |

下方狀態列：**Serial**（序號）、**Frame**（每幀點數）、**Last**（最後一幀時間）、**Test Mode**（True/False）。

圖表操作：滾輪縮放、右鍵選單有 Zoom In / Zoom Out / **Zoom All**（快捷鍵 `A`）。

#### 6.1.4 強度趨勢圖（Wavelength Trend）

畫面下半部，顯示**時間 vs 強度**，最多 6 條線：

- **Trigger 波長**（Configuration 裡設的那個「Selected wavelength」）。
- **Monitored Wavelengths** 清單的前 **5** 個波長。

每條線取的是該波長 **±0.5 nm 範圍內的峰值** —— 這是「峰值定位」，用來吸收波長漂移，**不是**雜訊濾波。預設畫的是每幀原始計數，刻意不濾波，讓它像示波器一樣誠實。

| 控制項 | 說明 |
|---|---|
| **Smooth** | 套用 τ ≈ 3 s 的 EMA 平滑。切換時**連已經畫在螢幕上的歷史也會一起重算** |
| **Normalize** | 以「勾選當下」的值為 1.0 做正規化，看各線的相對發散。正規化期間門檻參考線會隱藏 |
| **Zoom All** | 縮放回全部資料。放大狀態下時間軸仍會持續跟隨最新資料 |

虛線是 Save 門檻強度的參考線。保留時間預設 **30 分鐘**，可在 Configuration 分頁的 **Trend charts** 調整（1–480 分鐘，見 §10.7）。

### 6.2 Configuration（設定）

**需 Engineer 權限。** 分上下兩塊，中間可拖曳分隔。底部是共用的動作列。

底部三顆按鈕的差別**很重要**：

| 按鈕 | 作用 |
|---|---|
| **Apply** | 把目前參數**推送到硬體**與記錄器狀態機（立即生效，但**沒有存檔**） |
| **Save** | 把參數**寫入 `settings.json`**（下次開機沿用） |
| **Load Defaults** | 回到出廠值（**不會**自動 Apply，也**不會**自動 Save） |

> 改完記得 **Apply → Save** 兩個都按。只按 Apply 的話，下次開機會回到舊值。

動作列上方還有兩排設定：

- **Emission line** —— 從**譜線目錄**挑一條線，填進上面 Data Logger 區的兩個波長欄位，不必背數字：
  - 下拉依**物種分組**，內定線與你自己加的 `u…` 線一起列出（目錄在 Wavelength Calibration 分頁維護，見 §6.5.1）。存好的自訂線**立刻**出現在這裡。
  - **Set as trigger** → 寫進 **Trigger wavelength**。**Add to monitored** → 附加到 **Monitored wavelengths** 清單尾端；已經在清單裡的（±0.05 nm 內）不會重複加，會提示。
  - 寫進去的一律是**目錄波長**，不是加了漂移修正的波長。若那條線有修正量，下方提示會講明「記錄器不套用修正」——記錄器有自己的波長容差，通常遠大於這類修正；真要用修正後的位置，自己手打即可。
  - 若目前的 **Trigger mode** 不是 `Wavelength`，按 Set as trigger 仍會寫值，但提示會告訴你「這個模式的觸發判定不使用它」——程式**不會**替你改模式（那是你為了配方刻意選的）。
  - 加到第 6 條以後會提示：Monitor 分頁的趨勢圖只畫**前 5 條**，其餘仍然**會**記進強度 CSV。
  > 這一區只是**輸入輔助**：值仍然住在 Data Logger 區的那兩個欄位裡，手打完全等價。按完仍要 **Apply → Save**。
- **Data folder** —— 舊資料自動壓縮與磁碟用量，見 §7.4。
- **Golden Run** —— `capture for ___ seconds`：一次 Golden Run 擷取平均多久，範圍 **5–600 秒**，預設 60。下一次擷取生效，按 **Save** 才會存進 `settings.json`。時間越長，量到的基準 σ 越穩（警報門檻就是靠這個 σ 加寬的），但製程必須整段維持穩定。
- **Trend charts** —— `keep last ___ minutes`：兩張即時趨勢圖（Monitor 分頁的強度趨勢、Leak Monitor 的 % 趨勢）保留多久的歷史。**一個設定同時管兩張圖**，範圍 **1–480 分鐘**，預設 30。按 **Apply** 生效；**縮短時會立刻裁掉圖上已有的資料**（不會等到下一幀才慢慢過期，否則停止擷取時等於永遠不生效）。
  > 每一個點都留在記憶體裡，所以上限 480 分鐘是實際限制而不是偏好。要看更長的區間請用 Recordings / Ratio Review 分頁讀 CSV。

#### 6.2.3 Data Logger（資料記錄器）

門檻觸發式記錄器：**只有在觸發量高於門檻時才開檔寫入**（觸發量是什麼由 Trigger Mode 決定）。

**Trigger Conditions（觸發條件）**

| 參數 | 說明 |
|---|---|
| **Trigger Mode** | 門檻要拿**什麼**來比。三選一，見下方說明 |
| **pct** | `SpectrumPercentile` 模式使用的分位數（0–100，預設 99） |
| **Trigger Wavelength (nm)** | `Wavelength` 模式用來判斷門檻的波長（取最接近的譜線 bin）。接受小數 |
| **Wavelength Tolerance (nm)** | 請求波長與實際 bin 的最大容許差距 |
| **Save Threshold Intensity** | 高於這個強度才可能開始存檔 |
| **Start Confirm Time (s)** | 需**持續**高於門檻幾秒才真的開檔 |
| **Stop Confirm Time (s)** | 需**持續**低於門檻幾秒才收檔 |
| **Min Save Time (s)** | 單一 session 的最短長度，避免產生一堆極短的碎檔 |

**三種 Trigger Mode 怎麼選**

| 模式 | 量的是什麼 | 什麼時候用 |
|---|---|---|
| `Wavelength`（預設） | 單一波長的強度 | 有一條**從點火到熄火都穩定存在**的譜線時最單純 |
| `SpectrumPercentile` | 整張光譜的第 N 分位（預設 99） | **電漿點著後才通入某氣體**、或該氣體只在部分步驟通入時 —— 它跟的是「電漿亮不亮」，與氣體種類無關 |
| `AnyMonitoredWavelength` | Monitored Wavelengths 中**最亮的一條** | 多步驟配方，但希望保留譜線專一性（例如同時盯載氣 Ar 與製程線），避免室內光誤觸發 |

> 💡 **為什麼是分位數而不是「最大值」**：單一壞點或宇宙射線尖峰就能把最大值永久釘在高位，記錄器會一直誤以為電漿開著。實測把一個像素灌到 60000 counts，p99 只從 14813 變成 14831（＋0.1%），而最大值會直接讀成 60000。

> ⚠️ **換模式一定要重設 Save Threshold Intensity**。同一張光譜下，單一譜線可能讀 124、p99 讀 14813、最亮監測線讀 52639 —— 量級差很多。門檻欄位下方的綠色小字會顯示**目前的實際讀值**（`now 14813 · threshold 100`），照著它設就不會猜錯。建議值與實測的取法見 **§10.2**。

> ⚠️ **這個門檻不只管全譜 CSV**。`AbsoluteIntensity` 比值的「電漿存在」判定用的是同一個量、同一個門檻（見 §6.4.2），所以調它會同時改變洩漏監控何時開始評估。設得太低，電漿關閉時的暗電流基座會被當成電漿開著。

> 若觸發量根本無法計算（例如波長超出光譜儀量程），**Logs 分頁會出現一筆錯誤說明原因**，而不是像舊版那樣安靜地什麼都不做。

**Output Files（輸出檔案）**

| 參數 | 說明 |
|---|---|
| **Base Directory** | 留空 = `%APPDATA%\OES_Leak_Monitor\Data`（欄位下方的 *Effective:* 會顯示實際路徑） |
| **File Prefix** | 檔名前綴，例如 `P` |
| **Monitored Wavelengths** | 逗號分隔的波長清單，例如 `387, 482.5`。關閉全光譜時就是 CSV 的欄位；開啟時用於摘要檔 |
| **Include Full Spectrum** | 存下每一個波長欄位（另外產生一個摘要伴隨檔） |
| **Memory Budget (MB)** | 單檔列數上限依此估算，確保單一檔案可以整個載入這麼多 RAM |

**Start Save / Stop Save**

- **Start Save** — *武裝*觸發器。並不是立刻開檔，而是等強度條件成立。
- **Stop Save** — 解除武裝，並**立即**關閉所有開啟中的檔案。

> **出廠預設是「已武裝」。** 全新安裝（以及按下 **Load Defaults**）之後，記錄器就是 armed 的狀態，
> 不必先按 Start Save —— 一台不在錄的洩漏監控器，事後沒有任何東西可以回頭查，而武裝開關又在
> Engineer 才進得去的 Configuration 分頁，Operator 根本看不到它。
> 若 `settings.json` 裡寫的是 `"enabled": false`，那是有人**存過**的決定，程式會照著走，不會自作主張改回來。

**Logger Status** 區塊顯示狀態機目前狀態（`Idle` / `WaitingToStart` / `Saving` / `WaitingToStop`）與目前檔名。本專案是單一 OES，所以只會看到一列 **"OES #1 file"**。

### 6.3 Leak Monitor（洩漏監控主畫面）

這是日常監看時盯著的畫面。由上而下四層：

#### 6.3.1 狀態橫幅（最上方大色塊）

| 顯示文字 | 顏色 | 意義 |
|---|---|---|
| `Idle — waiting for plasma / baseline` | 灰 | 沒電漿、沒基準線，或監控被關閉 |
| `OK — within baseline` | 綠 | 在基準線範圍內 |
| `WARNING — leak signal rising` | 橘 | 有比值持續超過警告門檻 |
| `ALARM — leak signal confirmed` | 紅 | 達警報條件（**鎖存**，必須人工 Acknowledge） |

橫幅下方可能出現兩行小字：
- **測試模式註記** —— 提醒現在是模擬資料。
- **LOW SIGNAL 警示** —— 有啟用中的比值低於它的 SNR 下限（見 §6.3.4）。

**複合判定規則**：預設 `RequireTwoForAlarm = true`，也就是**要有兩個以上比值同時進入 Alarm**，整體狀態才會變 ALARM。這是為了避免單一譜線受干擾就跳警報。

#### 6.3.2 洩漏率讀值（橫幅正下方）

| 顯示 | 意義 |
|---|---|
| `Leak rate: not calibrated` | 還沒做洩漏率校正 |
| `Leak rate: — (waiting for plasma / baseline)` | 有校正，但目前沒有有效讀值 |
| `Leak rate ≈ 2.3E-4 ± 4E-5 mbar·L/s · 87% confidence` | 正常估計值 |
| `… · extrapolated` | 超出校正過的漏率範圍，數字僅供參考 |
| `Leak rate: calibration "X" needs its baseline — select that Golden Run…` | 目前的基準線不是這份校正當初綁定的那條，**估算已暫停**（避免給出錯誤數字） |

#### 6.3.3 工具列

| 控制項 | 權限 | 說明 |
|---|---|---|
| **Baseline** 下拉 | — | 切換使用中的 Golden Run。切換時會**自動配對**綁定該基準線的洩漏率校正 |
| **Capture Golden Run** | Engineer+ | 錄製新基準線（見 §6.3.5） |
| **Cancel** | — | 取消進行中的擷取（只在擷取中出現） |
| **Acknowledge Alarm** | Operator+ | 洩漏排除後，清除鎖存的警報。**會寫進系統日誌**（`LeakMonitorAcknowledged`：是誰按的、清掉哪幾條比值的鎖存、複合狀態怎麼變）—— 鎖存只有這個動作能清除，所以日誌上不會再出現「警報自己消失」 |
| **Zoom All** | — | 趨勢圖縮放回全部資料 |

#### 6.3.4 各比值列

每一列由左到右：

| 欄位 | 說明 |
|---|---|
| 圓點 | 狀態顏色 |
| **名稱** | 例如 `O 777 / N₂ 337` |
| **smoothed ratio** | EMA 平滑後的比值 |
| **百分比** | 相對基準線的 %（100% = 基準線） |
| **baseline (mean ± σ)** | 這條比值的基準線平均值與標準差 |
| **斜率 / SNR** | 上升速率，以及目前訊噪比 |
| **狀態** | `Normal` / `WARNING` / `ALARM` / `No Plasma` / `Low Signal` |

滑鼠停在該列上會顯示詳細數值（含目前的 warn / alarm 門檻）。

**五種狀態**

| 狀態 | 顏色 | 意義 |
|---|---|---|
| `Normal` | 綠 | 低於警告門檻 |
| `WARNING` | 橘 | 持續超過警告門檻 |
| `ALARM` | 紅 | 持續超過警報門檻（鎖存） |
| `No Plasma` | — | 參考譜線太弱，判定電漿沒開 |
| `Low Signal` | 藍紫 | 電漿有開，但訊號或參考譜線太靠近雜訊底 —— **這條比值被排除在警報判定之外** |

> 💡 `Low Signal` 是刻意設計的保護。兩條都接近雜訊的譜線相除，結果再怎麼平滑都沒有意義，硬要判讀只會製造假警報。

**門檻怎麼算**：警告門檻取 `max(WarnFactor × 基準均值, 基準均值 + SigmaWarn × σ)` —— 兩者取大。而且這裡的 σ 會取「Golden Run 的 σ」與「即時 EWMA 的 σ」**較大者**，所以當現場比基準時期更吵時，門檻會自動放寬，不會被自己的抖動觸發。

#### 6.3.5 Golden Run 擷取流程

1. 確保製程正在跑，而且**確定沒有洩漏**。
2. 按 **Capture Golden Run**。
3. 填入配方／基準線名稱。**名稱若和已存在的基準線相同，對話框會出現黃色提示**，寫明將取代哪一份（擷取時間與比值數）—— 對話框預設帶入目前選中的名稱，所以直接按下去就是覆蓋。要保留舊的就換一個名字。
4. 勾選確認框（不勾就不能按 Start Capture）。
5. 按 **Start Capture**，預設平均 **60 秒**（可在 Configuration 分頁調整，5–600 秒，見 §6.2）。
6. 只要**至少有一條比值**取得基準線，這次擷取就會**立即**寫入 `settings.json` 並自動設為使用中的基準線 —— 除非它會讓同名舊基準線的某些比值消失（見下表第三列）。

> **擷取期間不會跳警報。** 那 60 秒比對的是**舊**基準線，而重錄的原因往往正是它已經不適用（換配方），所以偏離幾乎是必然的，不該讓人事後去按 Acknowledge。比值列照常顯示、CSV 照常寫，只是不升級、不鎖存。擷取結束會記一筆 `GoldenRunCaptureDeviation`，寫下各比值在這段期間相對**舊**基準線的位置（有連續光基座的用 σ，其餘用 %）。換配方時那串數字很大是正常的；**重錄同一個配方時它就是重點** —— 若讀到 138%，代表你正要把一個已經偏離的狀態記成「無洩漏」。

擷取結果會當場告訴你：

| 結果 | 畫面 | 發生什麼事 |
|---|---|---|
| **全部比值都拿到基準線** | 狀態列顯示「captured — N ratio baseline(s)」 | 存檔並啟用 |
| **部分比值被拒絕** | 跳出**警告視窗**，列出沒拿到基準線的比值與原因 | 仍然存檔並啟用；被拒的比值顯示 **No Baseline**，**不參與洩漏警報** |
| **會讓同名舊基準線的比值消失** | 跳出**確認視窗**（Yes / No），同時列出「這次哪幾條沒拿到基準線、為什麼」與「舊的有、新的沒有的是哪幾條」 | **按 Yes 才會存檔**；按 No 則整份丟棄，同名舊基準線、使用中基準線與洩漏率校正全部原封不動（日誌記 `GoldenRunCaptureDiscarded`） |
| **沒有任何比值拿到基準線** | 跳出**錯誤視窗** | 這次擷取**整份丟棄**：不存檔、不啟用、**也不會蓋掉同名的舊基準線**。原本使用中的基準線與洩漏率校正完全不受影響 |

> 只有**退步**才會問。四條還是四條的例行重錄不會跳確認視窗 —— 每次都問的視窗，兩週後就會被閉著眼睛按掉。比對只針對**同名被覆蓋**的那一份（不可逆的損失）；若你換了新名字，舊的還在下拉選單裡，隨時可以切回去。

> 為什麼要丟棄：一次什麼都沒量到的擷取，若照樣存檔並啟用，會讓**每一條**比值瞬間失去基準線（面板全變 No Baseline、洩漏警報整個停擺），還會連帶把綁定的洩漏率校正一起解除配對 —— 而這一切的依據是一段根本沒量到東西的資料。日誌記 `GoldenRunEmpty`，訊息會寫明目前使用中的基準線沒有變動。

擷取期間的品質把關：

- 只有**通過 SNR 下限**的幀才會被納入該比值的基準線（跟即時判定用同一道關卡）。
- 若某條比值可評估的幀當中，**通過率不到 50%**，這條比值的基準線會被**直接拒絕**，並記進系統日誌。
  → 避免弱訊號譜線用「剛好往上跳的那幾筆雜訊」湊出一條假基準線。
- 同時會記錄**每條參考譜線各自的 PlasmaPresentFloor**（＝該參考線基準均值的 **20%**），之後用來判斷「電漿有沒有開」（僅 `Ratio` 模式使用）。**是每條參考線一個值**：不同比值若用不同參考線（例如一條用 Ar 811.5、一條用 N₂ 662.4），兩條線的強度可能差幾十倍，共用一個門檻會讓弱的那條被永久判定成「電漿沒開」而安靜失效。兩條比值若用**完全相同**的參考線設定（同一條線、同一種擷取方式與窗寬），則共用同一個 floor，樣本數也加倍。
- **基準均值必須明顯離開 0**：若均值 ≤ 0，或均值不到自身 σ 的 **10 倍**，該比值的基準線會被拒絕並寫進日誌。門檻、% 顯示、洩漏率全都要除以這個均值，一個「−25 ± 95」的基準線會讓三者都變成擲硬幣。日誌訊息會建議改用 `RawMean` 擷取（該波長若本來就沒有峰）。
- **同時記錄擷取當時的取得參數**（積分時間、平均次數、boxcar、acquire / average mode、背景移除等開關、波長軸長度與範圍）。之後只要現況與基準線不符，Leak Monitor 上方會出現警示條，系統日誌也會記一筆 `LeakMonitorAcquisitionMismatch`。

> ⚠️ **什麼時候必須重錄 Golden Run**：改了積分時間或其他影響絕對強度的設定、換了參考譜線（`Ratio` 模式）、改了監控方式或擷取方式、清理過觀察窗、換過光纖、製程配方改變。前三項程式會自動偵測並停用舊基準線；其餘的只有你知道。

#### 6.3.6 趨勢圖

畫每個比值的 **% of baseline** 隨時間變化。保留時間預設 **30 分鐘**，與 Monitor 分頁的強度趨勢**共用同一個設定**（Configuration → Trend charts，見 §10.7）。放大時時間軸仍會跟隨最新資料。

### 6.4 Ratio Setup（比值設定）

**Engineer+ 才能存檔。**

> ⚠️ **這裡的修改是「暫存」的。** 按 Save 只是寫進 `settings.json`；要真正生效，必須回 Monitor 分頁 **Stop → Start** 重啟擷取。畫面上方的黃色提示條就是在講這件事。

#### 6.4.1 左側：比值清單

- 勾選框 = 是否納入洩漏監控。
- **Add** / **Remove** 增刪比值，**最多 10 組**（下方會顯示 `N of 10 ratios`）。

#### 6.4.2 右側：選定比值的細節

**基本**
- **Display name** — 顯示名稱。
- **Enabled** — 是否納入監控。

**Monitoring method（監控方式）** — 這是關鍵選擇：

| 模式 | 監控的量 | 適用情境 |
|---|---|---|
| `Ratio` | 訊號 ÷ 參考 | **預設。** 標準 actinometry，能抵消電漿條件漂移 |
| `AbsoluteIntensity` | 訊號線的絕對強度（扣背景後）<br>**完全不使用參考線** | 訊號線很弱、接近雜訊底時。兩個小數字相除會劇烈擺盪，拿掉除法就少一個雜訊來源 |

`AbsoluteIntensity` 的代價：**不再抵消電漿條件漂移**（功率／壓力／流量變化會直接反映在讀值上）。因此使用它時必須維持穩定的操作點，並更頻繁地重錄基準線。

> **「電漿存在」判定來自記錄器的儲存觸發**（Configuration 分頁的 trigger 波長與 save-start 門檻，建議值見 **§10.2**）。`AbsoluteIntensity` 模式完全只看它 —— 選了這個模式，右側就不會出現 Reference line 欄位；`Ratio` 模式則是**兩個條件都要成立**：儲存觸發過門檻，而且參考譜線本身可用。
>
> 這樣改的原因：絕對強度模式本來就不對參考線做除法，所以那條線根本不必存在；而一條不存在的譜線扣完背景後只剩在 0 附近正負跳動的雜訊，於是「參考線 > 0」變成一枚硬幣，決定這一幀要不要計算。更糟的是，若參考線落在彎曲的連續光上（兩側基準視窗拉出的直線會高於凸型連續光），扣出來會**系統性為負**，該比值就一幀也不會被評估 —— CSV 欄位整片空白，畫面永遠停在 No Plasma。同理，參考線的 SNR 也不再影響 `Low Signal` 判定，只看被監控的那條線。

> **% 趨勢的單位由「擷取方式」決定，不是由監控方式決定**：只有 `AbsoluteIntensity` + `RawMean`（讀值帶連續光基座）才改用 σ 正規化分數（基準線 = 100、高一個 warn-σ = 120，斜率以 σ/min 計）。`AbsoluteIntensity` 搭配 `PeakHeight` / `Integral` 時，讀值已經扣掉背景，基準均值本身就是訊號，所以照常用 `值 ÷ 基準均值 × 100`（斜率 %/min）。

**Signal line（訊號譜線）／ Reference line（參考譜線）**（Reference line 只在 `Ratio` 模式出現）

- **Emission line** — 從依元素分組的譜線 catalog 中挑選。若該譜線套用了波長修正，這裡會顯示例如 `+0.20 nm → 777.4 nm`。
- **Extraction（擷取方式）**：

  | 擷取方式 | 量什麼 | 什麼時候用 |
  |---|---|---|
  | `PeakHeight` | 視窗內扣背景後的最大值 | 窄的原子譜線 |
  | `Integral` | 視窗內扣背景後的積分，單位 **counts·nm** | 分子帶頭（OH、NO、N₂） |
  | `RawMean` | **原始強度**（不扣背景、不找峰） | **該波長根本沒有峰**的時候 |

  前兩種都會把「兩側基準視窗拉出的一條直線」當作連續光扣掉。在有峰的地方這是小修正；**在沒有峰的地方，那條直線就是讀值的全部** —— 連續光通常是凸的，直線會高於中間，扣出來系統性為負；而 peak search 在單調斜坡上等於「往上坡走到底」，每一幀都把視窗釘在搜尋範圍的邊緣。實測（440.7 nm）：`Integral` 讀值 −11.7、**63% 的幀為負**；`RawMean` 讀值 3745 ± 19、**0% 為負**，而且雜訊還更低（不必付出估計背景本身的雜訊）。

  `RawMean` 的代價是讀值帶著連續光基座，所以它也會跟著窗口髒污、雜散光、曝光時間變化 —— 這時**改由 Golden Run 均值扮演背景**：一個在可信時刻量到的基準，而不是每幀猜出來的。`HalfWidthNm` 在這個模式下是平均寬度，設 0 表示「在中心波長做線性內插取值」。

  > ⚠️ `RawMean` 搭配 **`AbsoluteIntensity`** 使用時（建議的組合），三件事會自動改變：
  > 1. **Warn / Alarm factor 被忽略**，只用 σ 門檻 —— 基座的 1.2 倍是好幾十個 σ，那種警報永遠不會響，而且看起來像是有在戒備。
  > 2. **% 趨勢改為 σ 分數**（基準線 = 100，高一個 warn-σ = 120），CSV 欄位也會改叫 `_sigmaScore`。
  > 3. **Min SNR 不適用** —— 原始強度除以連續光雜訊會得到幾百的「SNR」，那是基座不是譜線，所以乾脆不給 SNR（顯示 `—`）。

> ⚠️ **換了參考譜線，原本的 Golden Run 基準線就失效**（`Ratio` 模式的基準線綁定當初的參考譜線）。換完必須重錄。絕對強度模式的基準線不綁參考線，但**改變監控方式**（`Ratio` ↔ `AbsoluteIntensity`）一定會讓舊基準線失效 —— 兩種模式量的根本不是同一個東西。

**Alarm thresholds（警報門檻）**

| 參數 | 預設 | 說明 |
|---|---|---|
| **Warn factor (×mean)** | 1.2 | 基準均值的幾倍觸發警告（1.2 = +20%） |
| **Alarm factor (×mean)** | 1.5 | 基準均值的幾倍觸發警報（1.5 = +50%） |
| **Warn σ (×sigma)** | 3.0 | 基準均值 + 幾個 σ 觸發警告（與上面**取較高者**） |
| **Alarm σ (×sigma)** | 6.0 | 基準均值 + 幾個 σ 觸發警報 |
| **EMA τ (s)** | 5.0 | 指數移動平均時間常數 |
| **Confirm (s)** | 15.0 | 必須持續超過門檻幾秒才升級狀態 |
| **Min SNR** | 5.0 | 兩條譜線都要超過這個訊噪比，比值才被採信。低於此值 → `Low Signal` 並排除在警報外。**填 0 = 關閉這道保護** |

底部 **Save**（Engineer+）／ **Revert**（丟棄未存檔的修改）。

### 6.5 Wavelength Calibration（波長校正）

**Engineer+ 才能存檔。** 這一頁有**上下兩張表**，兩者的生效時機不同，各有自己的 Save：

| 表 | 內容 | 何時生效 |
|---|---|---|
| 上：**Emission lines** | 譜線目錄本身（內定表＋你自己加的線） | **存檔後立即生效**，Ratio Setup 馬上選得到 |
| 下：**Wavelength corrections** | 每條譜線的漂移位移量 | **暫存** → Stop/Start 重啟擷取才生效 |

#### 6.5.1 Emission lines（譜線目錄）

內定表有 60 個物種、約 500 條譜線，**不可修改** —— 它是共同的參考基準，改了會讓不同機台的設定失去可比性。你自己的機台若有一條內定表沒有的線，在這裡加。

- **搜尋框**：輸入物種或波長即時過濾（例如打 `500` 會列出所有 500 附近的線）。要新增之前先搜一次，通常那條線已經在表裡了。
- **User lines only**：只看自己加的線。
- **Source 欄**：`built-in`（灰底、唯讀）或 `user`（可編輯）。
- **Add**：新增一列。你只填**名稱主體**與**波長**，系統會自動在名稱前面加上 **`u`** —— 例如輸入 `N2`、500.0，存成 **`uN2 500.0`**。這個 `u` 是系統的標記，不是你取的名字的一部分，所以不必自己打，也不可能打錯位置。
- **可以沿用內定物種的名字**：內定表已經有 `N2`，你仍然可以建 `uN2` —— 「內定的 N₂ 沒有我要的那條波長」正是最常見的動機。`uN2` 與 `N2` 在資料層面是兩個不同的物種，永遠不會相撞。
- **Remove**：刪除選取的自訂線。**若這條線正在被某個比值（訊號線或參考線）或某筆波長修正引用，會被擋下**，訊息會直接告訴你是誰在用。同理，**改動一條被引用的線的波長也會在存檔時被擋下**。
  > 為什麼要擋：比值存的是譜線區域的**副本**，所以刪掉目錄裡的線，當下什麼都不會壞 —— 錯誤發生在幾週後有人打開 Ratio Setup 按了 Save，那時比值會被默默匹配到**最接近的另一條線**，而且沒有任何線索指回這次刪除。
- **Import CSV… / Export CSV…**：匯入是**合併**（`Species,WavelengthNm` 兩欄，第一列表頭）；已存在的線會被略過，**永遠不會刪掉任何東西**，所以匯入不可能弄丟一條正在被引用的線。匯入後仍要按 **Save lines** 才會存檔。匯出寫出的是你自己的線（不含內定表）。
- **上限**：100 條自訂線；波長需在 **100–1200 nm** 之間。
- 自訂線和內定線一樣，可以在下方的修正表裡加漂移位移 —— 目錄裡的波長是「這條線在文獻上的位置」，位移是「我這台機器把它量到哪裡」，兩件事。

#### 6.5.2 Wavelength corrections（漂移修正）

**同樣是暫存 → Stop/Start 才生效。**

用途：補償光譜儀的**波長軸漂移**。每一列把 catalog 中的一條 `(元素, 波長)` 譜線加上一個位移量（nm）。

**關鍵特性**：因為 key 是 catalog 的 `(元素, 波長)`，所以修正一次就會**同時套用到所有用到這條譜線的比值**（不論它當訊號線還是參考線），不必逐一去改。

| 欄位 | 說明 |
|---|---|
| **Element** | 元素／物種 |
| **Wavelength (nm)** | catalog 中的原始波長 |
| **Correction (nm)** | 加上去的位移量。有效中心 = catalog 波長 + 此值。**上限 ±5 nm** |

沒有任何列時＝所有譜線都用 catalog 原始波長。

**Add** / **Remove** 增刪，底部 **Save** / **Revert**。存檔時會檢查位移範圍，並拒絕重複的 `(元素, 波長)` 組合。

> 💡 **跟 Peak Search 的差別**：每條譜線本來就會在 ±1 nm 內自動重新對準區域峰值。這個修正是給**更大的軸漂移**，或是「±1 nm 搜尋範圍裡剛好卡了另一根錯的峰」的情況用的。
>
> 這裡的修正**只影響量測**，不會寫回 `settings.json` 裡的原始 catalog 波長。

### 6.6 Leak Calibration（洩漏率校正）

**Engineer+ 才能存檔。** 目的：把「比值上升了多少」換算成「漏了多少 mbar·L/s」。

> ⚠️⚠️ **標準漏孔必須是空氣**（或就是你要偵測的那種洩漏）。用惰性氣體（如 He）的標準漏孔**完全無效** —— 它不會抬升 O / OH / NO 的訊號。

#### 6.6.1 原理

對每個比值擬合一條**過原點**的加權最小平方直線：

```
x ≈ s · Q
```

- `x` = 相對基準線的上升量。單位由讀值有沒有帶連續光基座決定：`AbsoluteIntensity` + `RawMean` 用**絕對**上升 `Δ = 值 − 基準均值`（相對上升會被基座壓縮到零點幾個百分點）；其餘一律用**相對**上升 `值/基準均值 − 1`（它對純比例縮放免疫，條件較好）
- `Q` = 已知漏率（mbar·L/s）
- `s` = 該比值的靈敏度

即時運算時反過來求 `Qᵢ = xᵢ / sᵢ`，再把所有比值用**逆變異數加權融合**成一個 `Q̂ ± σ_Q`，並給出跨比值一致性的信心度。

「無洩漏」狀態就是原點（Q = 0, x = 0），不需要另外量一個點。

#### 6.6.2 操作步驟

1. **選 Baseline (Golden Run)** — 這份校正會綁定到這條基準線。
2. **填 Calibration name** — 例如 `Recipe-A-cal-20260804`。
3. 掛上第一顆已知漏率的標準漏孔，**打開它**，等電漿穩定。
4. 按 **Capture Point…**
   - 填 **Known leak rate (mbar·L/s)**，支援科學記號（`1.2e-4`）。
   - 填 **Leak element / label**（選填，建議填標準漏孔編號）。
   - 勾選確認框 → **Start Capture**。預設平均 **30 秒**。
5. 換下一顆不同漏率的標準漏孔，重複步驟 3–4。**至少兩點**，建議三點以上並涵蓋你關心的漏率範圍。
6. 檢查中間的資料表（漏率、標籤、比值數、各比值的 `x ± σ`）。
   - 要刪除某一點：選取後按 **Remove Selected**。
   - 全部重來：**Clear Points**。
7. 按 **Save Calibration**。**Fitted sensitivities** 區塊會顯示各比值擬合出的靈敏度。

存檔後**立即生效**（不像 Ratio Setup 需要重啟擷取），Leak Monitor 分頁的讀值馬上會出現。

#### 6.6.3 有效性把關

校正**只在對應的 Golden Run 是使用中基準線時**才會套用：

| 狀態 | 行為 |
|---|---|
| `NotCalibrated` | 沒有使用中的校正，只做定性警報 |
| `Active` | 正常估算 |
| `BaselineMismatch` | 基準線換成別條了 → **暫停估算**（而不是給出被錯誤縮放的數字） |

切換或重新擷取 Golden Run 時，系統會**自動配對**綁定該基準線的最新校正，所以換配方不會留下過期的 `BaselineMismatch`。狀態轉換都會寫進系統日誌。

若某個比值的 `x` 單位在校正之後被改過（改了監控方式或擷取方式，使讀值從「帶基座」變成「不帶基座」或反之），該比值的擬合會被拒用 —— 兩種單位的斜率不能互相套用。這也代表**升級到本版之後，絕對強度比值的舊校正一律要重做**。

> 完整的數學模型與設計文件見 `docs/leak-rate-calibration.md`。

### 6.7 Baseline Builder（離線建基準）

> 權限：分頁**人人可看**，**Save 需要 Engineer 以上**。

用**已經存在硬碟上的錄製檔**產生 Golden Run，補現場擷取搆不到的兩種製程：

- **緩啟動**：前幾秒功率還在爬升，穩定段從哪裡開始只有曲線看得出來，站在機台前按下 Capture 是猜的。
- **短製程**：一次 run 比擷取視窗還短，單獨一次湊不出足夠的幀，得把好幾次合起來。

**不適用：多步驟製程。** 一個 Golden Run 只描述**一個**穩定操作點。要監測多個 step，就每個 step 各錄一份基準、換 step 時人工切換作用中的基準。原因與代價寫在 `docs/adr/0001`。

#### 操作步驟

1. 選日期範圍 → **Refresh**，列出資料夾裡的全光譜錄製（壓縮進 `DD.zip` 的也會列出來）。
2. 勾要用的錄製 → **Scan ticked**。這一步會用**現在**的 Ratio Setup 與波長修正把每一幀重新萃取一次，所以改過那些設定之後要重掃。這是整個流程唯一花時間的一步。
3. 點清單裡的一筆看它的曲線。
4. **在圖上按住左鍵拖曳**選出穩定段；也可以按 **Suggest** 讓它填入「最平的一段」，或直接在上方兩個框裡打數字。
   - Suggest 只找得出「這一段很平」，**找不出「這一段沒有漏」**——它的工作是把游標放到對的地方附近，判斷仍然是你的。
5. 每個檔各自選一段（**一個檔只能一段**，理由見下）。
6. 下方填 Golden Run 名稱 → **Build** → 看結果面板 → **Save as active baseline**。

#### 圖怎麼看

每條比值都除以它自己在整段錄製的中位數，所以量級差很多的線可以共用一個縱軸；軸上直接寫 `× own median`。這**不是** Leak Monitor 的「% of baseline」——這個分頁的前提就是基準還不存在。

#### 結果面板的四件事

| 區塊 | 意思 |
|---|---|
| 接受的 baseline | 每個比值的 `mean ± σ`、`mean/σ`、採用幀數 |
| 沒拿到基準的比值 | 原因和現場擷取用的是同一批句子，可對照 §9.5 |
| 被擱置的錄製 | 某個檔的水準和其他檔差太多會**預設排除**，該列變橘底。勾 `Keep anyway` 可以覆寫 |
| **視窗穩定度** | 每個檔在**自己視窗以內**的 `σ/mean` 與漂移（取該檔最差的那條比值） |
| 回套檢查 | 每個檔在**自己視窗以外**最遠跑到幾 σ |

**`mean/σ` 剛好過門檻要當回事**。門檻是 10；`mean/σ = 10.2` 和 `mean/σ = 97` 在 Leak Monitor 分頁上長得**一模一樣**（都只是「有基準」），但前者的警報門檻寬了十倍——看起來設定完成、真的漏氣時不會叫。低於 20 時結果面板會標 `<< only just clears the floor`。通常代表視窗framed進了不該進來的東西。

**視窗穩定度怎麼讀**：一段真正的平台大約是 `σ/mean ≈ 1 %`。十倍於此，代表視窗吃進了製程正在做的事——**漂移大**說明那是一段爬升（視窗放錯位置），**只有 σ 大、漂移小**說明是雜訊（電漿本身不穩）。

**整檔框選會讓回套檢查失效**：視窗以外沒有東西可比，那道唯一會發現「這份錄製別處跑到 59 σ」的守衛就沉默了。這種情況結果面板會明講「No back-check」，而不是留一片空白讓人以為通過。這時**視窗穩定度是唯一的判準**。

**被擱置代表什麼**：這道檢查擋的是最危險的一種錯誤——把一份**當時真的在漏**的錄製混進基準。一旦混進去，那個漏就變成「正常」，之後永遠測不到它。所以預設是排除、要你明確覆寫。真要覆寫也未必成功：一份差很遠的錄製合進來會讓 σ 膨脹，`mean > 10σ` 那道門檻通常會自己把結果擋掉。

**回套檢查的數字大不代表壞**：視窗以外本來就是製程在變的地方。但如果那份錄製裡真的有一次洩漏，這個數字就是它。

#### 為什麼一個檔只能選一段

兩段若是**同一個**操作點，它們本來就該是連續的一段（中間有空隙不影響）；若是**不同**操作點，把它們平均成一個 mean 正是這整件事要避免的錯誤。允許多段等於偷偷開始做多步驟支援，而且做的是錯的版本。

#### 取像條件（`.acq.json`）

錄製的 CSV 本身**沒有**記錄積分時間與平均次數，而絕對強度會隨這些設定整個縮放。所以現在每開一個錄製檔，app 會在它旁邊寫一個同名的 `{檔名}.acq.json` 記下當時的取像條件；壓縮成 `DD.zip` 時會一起收進去。

**在這個功能之前錄的檔沒有這個伴隨檔**，用它們建出來的基準只帶得了波長軸（軸可以從 CSV 標頭還原），`LeakMonitorAcquisitionMismatch` 也就只比得了軸。這是刻意的：猜一個積分時間填進去，會讓那道檢查在該擋的時候通過。

### 6.8 Replay（重播驗證）

> 權限：**Engineer 以上**。

把一份**已錄製的全光譜 CSV** 當成即時光譜餵進整條流程 —— Leak Monitor、兩張趨勢圖、以及兩個記錄器都會收到 —— 用來在**沒有硬體**的情況下驗證偵測演算法。與 §6.9 Recordings 的差別：Recordings 是把資料畫出來給人看，Replay 是把資料**重新跑一遍給程式判斷**。

**控制項**

| 控制 | 說明 |
|---|---|
| **Choose CSV…** | 選一份全光譜錄檔（記錄器寫出的寬格式）。載入不等於開始播 |
| **Clear** | 放掉錄檔，測試模式回到內建合成光譜 |
| **Play** | 開始播放，或從暫停繼續。在 `READY` / `FINISHED` 狀態按會**從第一幀重來** |
| **Pause** | 凍結。暫停期間不送出任何幀，續播時幀時間戳**不會出現斷點** |
| **Restart** | 倒回第一幀重播（等於重新做一次同樣的驗證） |
| **Stop** | 結束重播，串流交還內建合成光譜 |
| **Speed** | `1×` / `5×` / `20×` 快轉倍率 |
| **Raise leak alarms during replay** | 讓測試模式的幀也產生警報轉態並寫進系統日誌 |
| 狀態徽章 | `NO FILE` / `READY` / `PLAYING` / `PAUSED` / `FINISHED` |
| 進度列與 `mm:ss / mm:ss`、`frame N / M` | 播放進度 |
| 下方圖 | 目前正在送出的那一幀，畫在**錄檔自己的波長軸**上 |

**必須知道的六件事**

1. **要先讓 OES 在「測試模式」下跑。** 重播是靠裝置的取樣節拍推動的，所以順序是 Monitor 分頁 **Connect → Start**（無硬體會自動進測試模式），再回來按 Play。**接著實機時 Play 會被停用**，分頁上會出現黃色說明條 —— 因為重播只會取代測試模式的幀（見第 6 點），接著實機按下去等於什麼都不會發生。要在有硬體的機台上重播，先拔掉／中斷連線，或在 Configuration 勾 **Force test mode** 後重新 Connect。
2. **用錄檔自己的波長軸。** 例如 1896 點、179.8–850.3 nm，而不是測試模式那條 1000 點、200–800 nm 的合成軸。Ar 811.5 nm 這種超出合成軸的譜線才不會被丟掉，比值、σ、SNR、洩漏率才會和真機一致。
3. **幀間隔照錄檔。** 播放用虛擬時鐘：起點是按下 Play 的時刻，之後每一幀推進錄檔原本的間隔。倍速只縮短**實際等待時間**，演算法看到的時間軸等比例縮放，判斷結果不變 —— 20× 只是同一份證據送得快 20 倍。
4. **只播一次。** 播到最後一幀就停在那裡（`FINISHED`），不會循環。循環會把檔尾接回檔頭，下游的基線與警報會把那個接縫當成真實的階躍變化。
5. **產出檔名帶 `SIM`。** 重播期間兩個記錄器都改寫 `SIMP_OES1_*` / `SIMP_Ratio_*`，落在**今天**的資料夾。Recordings 與 Ratio Review 照樣列得出來，但一眼就分得出不是量測資料。
6. **真實硬體的幀永遠不會被取代。** 只有測試模式的幀會被換掉。所以重播若在播放途中「接上」了實機（或裝置改以實機模式重新連線），程式會**立刻停止重播並把記錄器切回正常檔名前綴**，日誌記一筆 `ReplayAbortedByHardware`。
   > 這道保護是實測補上的：曾經在連著實機的情況下按 Play，畫面顯示 `PLAYING`、進度卻停在 0，而記錄器已經切成 `SIM` 前綴 —— 於是**實機量到的真資料被寫成標記為重播的檔案**，剛好把「重播不會被誤認為量測」反過來用。現在 Play 會被擋下，途中變成實機也會被中止。

> ⚠️ **重播的第一秒會跳一次 `LeakMonitorAcquisitionMismatch`。** 按下 Start 時裝置回報的還是合成軸（1000 點），基線若是從重播抓的（1896 點）就對不上。等重播的幀開始流動，比對對象換成錄檔的軸，警告就不再出現。只要基線與待驗證的錄檔來自同一台機、同一組曝光參數，這一次警告可以忽略。

> ⚠️ **不要拿實機抓的 Golden Run 去驗證重播。** 錄檔裡沒有當初的曝光參數，重播的幀帶的是裝置目前的設定。基線請從重播本身抓 —— 完整做法見 §8.5。

### 6.9 Recordings（光譜回放）

回放記錄器寫出的光譜 CSV。**已被壓縮的日期也會列出**（標示 `zip`），選取時直接從壓縮檔讀取，不必先解壓縮（見 §7.4）。

**工具列**

| 按鈕 | 說明 |
|---|---|
| **Refresh** | 重新掃描資料夾（含 `DD.zip` 壓縮檔內容）。啟動時與 Configuration 改過資料夾按 Apply 後都會自動掃一次，所以平常只有在**程式外部**新增／刪除檔案時才需要手動按 |
| **Open Base** | 用檔案總管開啟記錄器的根目錄 |
| **Open Folder** | 開啟選定 session 的資料夾 |
| **Open File** | 用預設程式開啟該 CSV |
| **Line** / **Heatmap** | 切換檢視模式（目前模式有綠色外框） |
| **Save PNG** / **Copy Image** | 匯出目前圖表 |
| **Clear Compare** | 移除比較用的第二個 session |

**篩選**：Search（日期／時間／檔名關鍵字）、From / To 日期。

#### 6.9.1 線圖的波長（可多條）

線圖上方有一排波長控制，**最多同時畫 6 條波長**（Heatmap 模式時會收起來）：

| 控制 | 說明 |
|---|---|
| 色塊清單 | 目前畫的波長，每條配一個顏色 —— **顏色代表波長**，與圖例一致 |
| 下拉 ＋ **Add line** | 從**譜線目錄**選（物種分組，內定線與 `u…` 自訂線都在，見 §6.5.1） |
| **or nm:** ＋ **Add** | 直接打任一波長（按 Enter 也可）。**判斷一條線有沒有反應時，通常要拿旁邊一段沒有峰的連續光當對照**，那個位置不在目錄裡，只能手打 |
| 下拉 ＋ **Remove** | 移除某一條（至少保留一條） |
| **Normalize (÷ own mean)** | 每條線除以**自己在整段錄檔的平均值**，全部落在 1.0 附近，比的是**形狀**。不同譜線的強度常差好幾個數量級，不正規化的話弱的那條會被壓成貼底的直線 |
| **Peak ±0.5 nm** | 改取 ±0.5 nm 內的**最大值**（與 Monitor 分頁的即時趨勢一致，可吸收軸漂移）。**預設關閉** |

> **開啟時預設就是記錄器的 trigger wavelength 那一條**，和以前一樣；清單會被記住，下次開啟沿用。
>
> ⚠️ **`Normalize` 不是 Leak Monitor 的「% of baseline」。** 這裡的分母是**該條線自己的全段平均**，那裡的分母是 **Golden Run 基線**。圖上 Y 軸會寫 `Intensity (× own mean)` 以示區別。若某條線的平均值 ≤ 0（例如扣過背景的雜訊），該條會維持原始 counts 並在下方狀態列註明。
>
> ⚠️ **`Peak ±0.5 nm` 預設關閉是刻意的。** 取窗內最大值會對**弱線**造成系統性向上偏差，同時抬高它的平均與散度 —— 而 §1.1 的判準正是「變化是雜訊的幾倍」。回顧分析要的是那個位置**實際量到**的值；真的碰到軸漂移，請用 §6.5.2 的漂移修正對症處理。

**比較模式**：選兩個 session 時，**線型代表 session**（主 session 實線、比較 session 虛線），顏色仍代表波長 —— 所以 3 條波長 × 2 個 session = 6 條線，圖例寫成 `337.1 nm · primary` / `337.1 nm · compare`。

**版面**
- 左側：session 清單（Date / Time / Rot / Size）。**可以多選兩個 session 做疊圖比較。**
- 右上：波長控制列 ＋ 主圖（線圖或熱圖）。
- 右下左：單幀光譜 —— 在主圖上點一下就會顯示該時間點的完整光譜。
- 右下右：**Notes** —— 打字後按 **Save Notes**，會存成 CSV 旁邊的 `.notes.txt` 伴隨檔。

### 6.10 Ratio Review（比值回放）

回放記錄器寫出的比值 CSV（`{prefix}_Ratio_*.csv`）。**已被壓縮的日期一併列出**（標示 `zip`），直接從壓縮檔讀取。

**三種檢視模式**（同樣以綠框標示目前模式）：

| 模式 | 內容 |
|---|---|
| **% of baseline** | 各比值相對基準線的百分比，附 100 / 120 / 150 % 參考線 |
| **Raw ratio** | 未正規化的原始比值 |
| **Leak rate** | 校正後的 `Q̂`（mbar·L/s），附半透明 ±1σ 帶 |

圖表背景會用半透明色帶標出當時的 Warning / Alarm 狀態。

> 📝 **Leak rate** 模式只有在該 CSV 含有 `LeakRate` / `LeakRateSigma` 欄位時才有東西可畫。校正功能上線前錄的舊檔沒有這兩欄，仍然可以正常開啟與檢視前兩種模式。

其餘按鈕（Refresh / Open Base / Open Folder / Open File / Zoom All / Save PNG / Copy Image / Search）用法同 Recordings。

### 6.11 Logs（系統日誌）

顯示系統稽核日誌，記錄：

- 裝置連線／中斷、擷取啟停
- 記錄器開檔／收檔／錯誤
- 登入／登出／自動鎖定／使用者管理
- **警報狀態轉換**
- **Acknowledge**（清除鎖存的人、時間、清掉哪幾條）
- **Golden Run 擷取**（含被拒絕的比值與原因）
- **洩漏率校正的啟用／暫停／清除**
- Ratio CSV 被略過的原因

日誌檔位置：`%APPDATA%\OES_Leak_Monitor\Logs\yyMMddHH.csv`（每小時一個檔）。欄位：

```
Time,Status,Condition,Description,RelatedParameters,Value,Timestamp,LogLevel
```

| 欄位 | 內容 |
|---|---|
| `Time` | 距離程式啟動的秒數（方便對照同一次執行內的先後） |
| `Condition` | 事件代號，例如 `Device_RuntimeError`、`GoldenRunRatioDropped` |
| `Description` | **人看的說明**：發生什麼事、該怎麼處理 |
| `RelatedParameters` / `Value` | 相關參數與數值 |
| `Timestamp` | 絕對時間 |

> ⚠️ **`Description` 欄是在 `Aqst.OesApp.Core` 0.1.7 才寫進檔案的。** 在那之前，這一欄的內容只存在於執行中的記憶體（Logs 分頁看得到），關掉程式就消失 —— 檔案裡只留下「發生了一個叫 `Device_RuntimeError` 的事件」，完全沒有錯誤內容。**0.1.7 之前的舊日誌檔沒有這一欄，也救不回來。**
>
> 若同一小時內先後跑過新舊版本，新版會另開 `yyMMddHH_1.csv`，避免同一個檔案裡混著兩種欄位數。

> 追查「為什麼那時候跳警報」或「為什麼這條比值沒有基準線」，這裡是第一個要看的地方 —— 現在 `Description` 欄會直接寫出原因。

## 7. 檔案與資料夾

### 7.1 位置

```
%APPDATA%\OES_Leak_Monitor\
├── settings.json          ← 所有設定（裝置參數、記錄器、比值、Golden Run、校正、波長修正）
├── Data\                  ← 記錄的 CSV（可在 Configuration 改成別的路徑）
│   └── 202608\
│       └── 04\
│           ├── P_OES1_0804153012.csv        ← 強度／全光譜
│           ├── P_OES1_0804153012_1.csv      ← 超過記憶體上限時的續檔
│           ├── P_Ratio_0804153012.csv       ← 對應的比值檔
│           └── P_0804153012.notes.txt       ← Recordings 分頁存的筆記（檔名不含 tag）
└── Logs\
    └── 26080415.csv       ← 系統稽核日誌（每小時一檔）
```

`%APPDATA%` 通常是 `C:\Users\<你的帳號>\AppData\Roaming`。

### 7.2 檔名規則

```
{prefix}_{tag}_{MMddHHmmss}[_N].csv
```

- `prefix` — Configuration 裡設的 File Prefix
- `tag` — `OES1`（強度檔）或 `Ratio`（比值檔）
- `MMddHHmmss` — session 起始時間（**年份由上層資料夾還原**）
- `_N` — 續檔序號。兩種情況會產生：**(a)** 單檔超過記憶體預算；**(b)** 存檔途中**光譜波長軸改變**（重新套用擷取參數、裝置重連），此時舊檔關閉、以新的波長軸開新檔，Logs 分頁會留下一筆 `SpectrumAxisChanged` 警告

> ⚠️ 看到 `SpectrumAxisChanged` 就代表這一爐的資料被切成**兩段不同波長軸**的檔案。若它是因為你改了曝光相關參數而產生，**請重錄 Golden Run** —— 舊基準線是在舊曝光條件下錄的。

### 7.3 比值 CSV 格式

```
Timestamp,NO 237 / Ar 750.4 [R_7c40d2f9],NO 237 / Ar 750.4 [R_7c40d2f9]_pctBaseline,…,OverallState,LeakRate,LeakRateSigma
```

每個比值兩欄（原始值 + % 基準），最後三欄是整體狀態與洩漏率估計。欄位是**依標題名稱**尋址的，所以舊版沒有 `LeakRate` 欄位的檔案仍可正常解析。

**欄名同時帶著名字與代號**：`{顯示名稱} [{key}]`。

- **名字**是你在 Ratio Setup 取的顯示名稱，讓檔案自己說明它記的是哪條譜線 —— 用 Excel 打開就看得懂，不必回去對 `settings.json`。
- **`key`**（例如 `R_7c40d2f9`）是這條比值建立時產生的隨機識別碼，**永遠不會變**。改名字、換門檻、換抽取模式它都不動，Golden Run 基準線與洩漏率校正才不會因為你改了個名字就失效。程式一律認這個碼。

> 📝 **舊檔（欄名只有 `R_xxxxxxxx`）照樣讀得開**，只是 Ratio Review 的圖例會顯示代號而不是名字 —— 那些檔案裡沒有名字可用。

> 第二欄的名稱會說明它裝的是什麼：一般是 `…_pctBaseline`（% 基準）；若該比值採 `AbsoluteIntensity` + `RawMean`，就會是 **`…_sigmaScore`**（σ 分數）。兩者都畫在同一組 100/120/150 標尺上，但**不是同一個量**，所以 Ratio Review 會在圖例標上 `(σ-score)`。

> ⚠️ 顯示名稱裡的逗號會被寫成分號、中括號會被寫成小括號 —— 否則會把 CSV 的欄位切壞。取名字時盡量只用物種、波長與斜線，例如 `N2 337.1 / Ar 750.4`、`N2 337.1 (abs)`。

**比值檔與強度檔是各自獨立的記錄器**，只共用同一個輸出資料夾與檔名前綴：

| | 強度 CSV（`_OES1_`） | 比值 CSV（`_Ratio_`） |
|---|---|---|
| 什麼時候寫 | 只在強度**高於觸發門檻**時 | **只要 OES 在擷取就一直寫** |
| 需要武裝嗎 | 要（Recorder 狀態列須非 `OFF`） | 不用 —— 記錄器 `OFF` 也照樣產生 |
| 每列大小 | 全譜約 22 KB（5 Hz ≈ 400 MB/小時） | 約 200 B（5 Hz ≈ 4 MB/小時） |
| 何時關檔 | 低於門檻並滿足停止確認 | 停止擷取、Reset Run、或**跨過午夜**（自動換日換檔） |

> 💡 這是刻意的設計：比值資料是洩漏監控的核心記錄，體積只有全譜的百分之一，不應該因為「原始光譜錄影沒開」就跟著消失。
> 也因此比值檔的時間戳**不再與強度檔相同** —— 兩者各自開檔，不要用檔名時間去配對它們。

### 7.4 磁碟空間與舊資料壓縮

全譜記錄的資料量很可觀（5 Hz、2048 點約 **400 MB／小時**），而程式**不會刪除任何量測資料**。Configuration 分頁底部有一排「Data folder」設定來處理這件事：

| 控制項 | 預設 | 說明 |
|---|---|---|
| **Compress old data** | **關閉** | 勾選後才會自動壓縮。**預設關閉是刻意的** —— 升級既有機台時不該有人沒同意就動到幾個月的資料 |
| **after ___ days** | 30 | 超過這個天數的日資料夾會被壓成同層的 `DD.zip` |
| **cap ___ GB** | 20 | 整個資料夾超過此上限時，會由舊到新繼續壓，直到符合 |
| **Compress now** | — | 立刻在背景跑一次 |

**壓縮不是刪除。** `202605\08\` 會變成 `202605\08.zip`，裡面是原封不動的 CSV，用任何解壓縮軟體（含 Windows 內建的「解壓縮全部」）都能取回。要不要真的刪除，由貴廠的保存規範決定，程式不替你決定。

安全規則：

- **最新 2 天永遠不壓**，正在寫入的檔案也不壓。
- 資料夾裡只要有**任何一個檔案被開著**（包含你用 Excel 開啟的），整個資料夾這次就跳過。
- 先建立壓縮檔並**逐一核對內容清單無誤**，才刪除原始檔。中途任何失敗都保持原狀。
- 每一個動作都寫進 **Logs** 分頁（`DataArchived` / `DataArchiveSkipped` / `DataArchiveFailed`）。

> ✅ **已壓縮的資料照樣可以回放。** Recordings 與 Ratio Review 會一併列出 `DD.zip` 裡的檔案，選取時直接從壓縮檔讀取，**不需要先解壓縮**。清單上會標示 `zip`，狀態列也會註明來源檔（例如 `(from 23.zip)`）。
>
> 唯一的差別是讀取時要即時解壓縮，比未壓縮的檔案略慢（實測 30 MB 全譜檔約 0.35 秒），而 Recordings 的日期範圍預設只看最近 7 天 —— 要看更早的資料記得把 **From** 日期往前調。

**磁碟警告**（不論壓縮功能是否開啟都會發出）：程式**開啟時與關閉時**各檢查一次，**只有在真的有磁碟問題時才會跳視窗** —— 餘量低於 **10%**，或資料夾超過容量上限；低於 **5%** 視為嚴重。單純「沒開啟自動壓縮」不會跳提示（否則每次開關程式都要按一次確定，久了就沒人看了），該狀態在 Configuration 分頁本來就看得到。

### 7.5 備份建議

要保存一台機台的完整組態，備份 **`settings.json`** 一個檔就夠了 —— 裡面包含所有裝置參數、記錄器設定、比值定義、**自訂譜線**、Golden Run 基準線、洩漏率校正、波長修正與資料保存設定。

## 8. 日常操作 SOP

### 8.1 每天開機

1. 啟動程式 → **Sign In**。
2. **Monitor** → **Connect** → 確認 `Test Mode = False`。
3. 按 **Start**。
4. 切到 **Leak Monitor**，確認：
   - **Baseline** 下拉選的是今天配方對應的基準線。
   - 狀態橫幅在電漿點著後轉為綠色 `OK — within baseline`。
   - 沒有 `LOW SIGNAL` 警示。
5. 回 **Monitor**，確認 **Recorder 狀態列**不是紅色 `OFF`（見 §6.1.2）。
   - 顯示 `ARMED` / `SAVING` → 正常，不必做任何事。
   - 顯示 `OFF` → 記錄器沒武裝，**通知工程師**（武裝在 Engineer 權限的 Configuration 分頁，操作員進不去）。這是一次性設定，正常情況下不需要每天按。
   - 出現橘色「not saved」小字 → 同樣通知工程師補按一次 Save，否則下次開機會失效。

### 8.2 換配方

1. **Leak Monitor** → **Baseline** 下拉切到新配方的基準線。
   - 洩漏率校正會**自動跟著切換**。
   - 若新配方還沒有基準線 → 跑一段良品製程後 **Capture Golden Run**。
2. 按 **Reset Run** 開新的記錄檔並清空趨勢。

### 8.3 警報發生時

1. 記下狀態橫幅的時間與 **Leak rate** 讀值。
2. 看**哪幾條比值**進了 ALARM：
   - O / OH / NO 一起上升 → 典型的**空氣洩漏**。
   - 只有單一條上升 → 可能是該譜線受干擾，或有其他製程變化。
3. 到 **Ratio Review** 回放這段時間，確認是**持續上升**還是短暫尖峰。
4. 實體檢查（O-ring、法蘭、視窗、閥件）。
5. 排除後 → **Acknowledge Alarm** 清除鎖存（這一按會記進日誌，含操作者帳號）。

### 8.4 定期維護

| 週期 | 動作 |
|---|---|
| 每次清潔觀察窗／換光纖後 | **重錄 Golden Run** |
| 每次更動積分時間等曝光參數後 | **重錄 Golden Run** |
| 定期（依機台穩定度） | 檢查波長是否漂移，必要時用 Wavelength Calibration 修正 |
| 定期 | 用標準漏孔重驗洩漏率校正是否仍準確 |
| 定期 | 檢視 `Data\` 資料夾用量（見 §7.4）。程式**不會刪除**量測資料 —— 需要時開啟自動壓縮，或自行轉存到伺服器 |

### 8.5 演算法驗證：抓基線 → 重播 → 比對轉態時間

> 權限：**Engineer 以上**。不需要硬體，也不會動到正在生產的機台。

**什麼時候做**：改過比值設定、抽取模式、警報門檻或波長校正之後，要回答「這組新設定拿去跑當初那一次真實洩漏，抓不抓得到、以及慢多久」。這是唯一能在不製造洩漏的情況下量化偵測靈敏度與延遲的方法。

#### 準備：兩段來自同一次製程的錄檔

| 段別 | 要求 |
|---|---|
| **基線段** | 全程 `Normal`、確定沒有洩漏的一段。通常就是當初在機台上錄 Golden Run 的那一段 |
| **事件段** | 已知有洩漏、實機當時真的跳過警報的一段 |

兩段必須是**同一次連續電漿、同一組曝光參數**，否則基線對事件段不成立。確認方式：

- Logs 分頁看兩段之間有沒有 `Acquisition_Stop` 之外的中斷；換過積分時間或平均次數就不算同一次。
- Ratio Review 把兩段接起來看，接縫處的比值應該是連續的（差幾個 % 以內）。
- 注意錄檔會**輪替**：一次採集可能被切成 `_0807211351` / `_0807212620` / `_0807213124` 好幾個檔，它們共用同一份 `P_Ratio_*` 比值檔。用 Logs 裡的 `IntensityLogger_FilesChanged` 對出每個檔涵蓋的時間。

#### 步驟 1 — 用基線段抓 Golden Run

1. **Replay** 分頁 → **Choose CSV…** → 選**基線段**。
2. **Monitor** 分頁 → **Connect** → **Start**（無硬體會進測試模式）。
3. 回 **Replay** → **Play**（這一步用 `1×`，讓平滑與 SNR 有正常的時間行為）。
4. 等 Leak Monitor 的各比值 SNR 與讀值平穩後，按 **Capture Golden Run**，取一個看得出來源的名字，例如 `Replay 0807-2109`。
5. 捕捉完成後檢查日誌：出現 `GoldenRunCaptured` 才算成功。若出現 `GoldenRunRatioUnstableBaseline`、`GoldenRunRatioLowSnr` 或 `GoldenRunRatioDropped`（畫面也會跳警告視窗），代表那條比值的基線被拒絕，先處理再往下（見 §9.5）。若跳的是錯誤視窗／日誌記 `GoldenRunEmpty`，這次擷取沒有存下任何東西 —— 重播的基線要重抓，**而且不要拿實機的舊基準線頂替**（§8.5 開頭的提醒）。
6. 按 **Save**。

> ⚠️ **絕對不要拿事件段抓基線。** 基線若落在洩漏已經發生的區間，同一份資料之後就會顯得正常，警報延後甚至完全不跳。實測過一次：把基線抓在告警期間，同一份事件檔的 **Warning 延後 181 秒、Alarm 延後 212 秒**，而原始比值一模一樣 —— 純粹是基線的位置造成的。

#### 步驟 2 — 重播事件段

1. **Replay** → **Stop**（若還在播）→ **Choose CSV…** → 選**事件段**。
2. 勾 **Raise leak alarms during replay**。**沒勾就不會有 `LeakMonitorState` 進日誌**，只有畫面看得到。
3. 確認 Leak Monitor 用的是步驟 1 存的那個 Golden Run。
4. **Play**。趕時間可以用 `5×` / `20×`，時間軸等比例縮放，判斷結果不變。
5. 讓它播到底（狀態變 `FINISHED`）。中途按 Stop 的話日誌會寫 `stopped by the operator`，那一輪的資料不完整、不能拿來比。

#### 步驟 3 — 比對轉態時間

資料有兩個來源，兩個都看：

- 系統日誌的 `LeakMonitorState`（`From=Normal,To=Warning` 這種）。
- 這一輪寫出的 `SIMP_Ratio_*.csv` 的 `OverallState` 欄位（Ratio Review 也可以直接開）。

**換算方式**：重播的幀時間戳 = 按下 Play 的時刻 + 錄檔中該幀的相對時間。所以只要換算成「**距離播放開始幾秒**」，就能直接和實機當年「距離該錄檔第一幀幾秒」對齊 —— 不必管日期。

| 比對項目 | 期望結果 |
|---|---|
| `SIMP_Ratio_*.csv` 列數 | 等於錄檔幀數（日誌 `ReplayStarted` 的 `Frames=` 值） |
| 首次 `Warning` 的相對秒數 | 與實機同一段相同（差幾幀之內） |
| 首次 `Alarm` 的相對秒數 | 同上 |
| `Idle`（電漿瞬斷）出現的位置 | 落在**同一幀** —— 這是資料驅動的事件，可以當成對齊是否正確的檢查點 |
| 未改動的比值原始值 | 與實機逐幀相同（CSV 只有六位有效數字，差 0.001 % 以內屬正常） |

把每次驗證的結果記下來（設定版本、基線名稱、Warning / Alarm 的相對秒數），下次改設定就有得比。可以寫在 Recordings 分頁的 **Notes**（會存成 CSV 旁的 `.notes.txt`）。

#### 差異怎麼解讀

| 現象 | 通常原因 |
|---|---|
| **原始比值本身就不一樣** | 比值定義被改過。抽取模式在 `PeakHeight` ↔ `RawMean` 之間切換會讓數值差 2–4 倍（`RawMean` 含連續光背景）；或波長校正 overlay 動過 |
| 原始比值相同、**% of baseline 不同** | 基線不同 —— 換了 Golden Run，或基線抓的位置不同 |
| **轉態整體延後** | 基線偏高（多半是抓在洩漏已經開始的區間），或 warn / alarm 門檻被調高 |
| **完全不跳警報** | 先確認有勾 Raise leak alarms during replay；再看主力比值是不是被 SNR gate 擋成 `LowSignal` |
| 日誌沒有任何 `LeakMonitorState` | 沒勾 Raise leak alarms during replay（狀態其實有變，只是沒寫進日誌） |
| 欄名從 `_pctBaseline` 變成 `_sigmaScore` | 該比值改成了絕對強度 + `RawMean`，監控的量已經換成 σ 分數，不能和舊檔的百分比直接比 |

> 💡 比對兩份比值 CSV 時，**認欄名中括號裡的 `key`**（例如 `[R_7c40d2f9]`），不要認名字 —— 名字可以被改，key 不會（見 §7.3）。

## 9. 疑難排解

### 9.1 按 Connect 後掉進測試模式（明明接了硬體）

**這是本程式最需要警覺的故障**：畫面顯示「已連線」、光譜在動、CSV 也照寫，但那些數字全是合成的，檔名前綴跟真實量測一模一樣（只有 Replay 產生的檔才會標 `SIM`）。

**先確認確實掉進測試模式**：Monitor 分頁的 `Serial` 顯示 `TEST_MODE_SIMULATOR`、**Test Mode** 為紅色 `True`，或系統日誌出現警告 `Device_TestModeFallback`（Description 就是原因）。

#### 一鍵診斷

程式資料夾裡附了 `check-oes-connect.cmd` 與 `check-oes-connect.ps1`。**兩個檔要放在 `OES_Leak_Monitor.exe` 同一層**，用平常開程式的那個帳號**點兩下 `.cmd`**（不要用「以系統管理員身分執行」）。它會照著程式連線的順序重跑一次，把程式吞掉的錯誤印出來，並存成同資料夾的 `oes-diagnostic.txt`：

| 診斷輸出 | 意思 | 處理 |
|---|---|---|
| 第 2 節 `vcruntime140.dll NOT FOUND`、第 4 節 `FAILED … (Win32 126)` | 這台沒有 VC++ 執行階段，DLL 根本載不起來 | 把 `vcruntime140.dll`、`vcruntime140_1.dll`、`msvcp140.dll` 補到 `.exe` 旁（見 §2.1），或安裝 [VC++ 2015–2022 x64 Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe) |
| 第 4 節 `FAILED …（Win32 5）` | 檔案被防毒或權限擋住 | 檔案右鍵 → 內容 → 勾「解除封鎖」；請 IT 把資料夾加入防毒白名單 |
| 第 4 節 `FAILED …（Win32 193）` | 32/64 位元不符 | 拿到的不是 x64 版，重新取得正確的發布資料夾 |
| 第 1 節有 `MISSING` | 交付資料夾不完整 | 整包重新複製，不要只拷貝 `.exe` |
| 第 5 節 `devices=0` | 驅動沒裝或線沒接 | 裝驅動（交付 USB 的 `Driver\install_drvier.bat`）、換線、裝置管理員確認看得到裝置 |
| 第 5 節 `open #0: FAILED` | 裝置被別的程式佔用 | 關掉原廠軟體（SpectraSmart 等）與其他一份本程式，再試 |

#### 其他要檢查的

- Configuration 分頁的 **Force Test Mode** 是不是被勾起來了（日誌 `Device_TestModeFallback` 的 Related 欄會寫 `ForceTestMode=True`）。**注意**：按下 Configuration 分頁的 **Load Defaults** 不會再把它打開，但舊版本會 —— 若這台曾經按過並存檔，請取消勾選後 **Apply → Save**。
- 乙太網路機種：0.4.6 已修正預設 device type（改為 Z5，並會自動改試另一種），若仍連不上請確認 IP 設定。

> **實例（2026-08-17）**：某台機台的交付資料夾檔案齊全、位元正確、驅動正常、原廠軟體也連得到，卻每次都掉進測試模式。原因是那台從未安裝過 VC++ Redistributable，`libsodium.dll` 載入失敗（Win32 126），連裝置列舉都還沒跑到。之後的版本已把 VC++ 執行階段一起打包，就是為了根除這個情況。

### 9.2 光譜幀出現斷裂／撕裂

Configuration → **Acquire Mode** 改成 `Oneshot` → **Apply**。常見於 Z5／乙太網路機種在長積分時間下。

> 同一個設定也是**整幀全暗**（掉幀）的第一個處理方向 —— 那種狀況日誌會記 `SpectrumFrameDropout`，見 §9.6。

### 9.3 峰形變寬、峰位偏移

Configuration → **Average Mode** 改成 `Software` → **Apply**。某些機種的硬體平均器在多次讀取時會錯位。代價是速度變慢約 N 倍（N = Average Count）。

### 9.4 一直顯示 Low Signal

代表訊號或參考譜線太靠近雜訊底。依序嘗試：

1. **拉長積分時間**（Configuration → Integration Time → Apply）。
2. **提高 Average Count**（配合 `Software` 平均模式）。
3. 檢查**光纖對位**與**觀察窗是否髒污**。
4. 該譜線在你的機台上本來就很弱 → 到 Ratio Setup 把它的 **Monitoring method** 改成 `AbsoluteIntensity`。
   > ⚠️ 但在**真實電漿**上要謹慎：實測顯示洩漏會讓整個光譜一起變亮，而且**洩漏排除之後電漿仍維持較亮**，所以絕對強度會回不到基準線、持續假警報（同一時刻 Ar 正規化的比值已經回到 +1%，絕對強度還高著 +7.6%）。`AbsoluteIntensity` 適合光源穩定的場合；電漿量測請優先用 `Ratio` 模式，先換一條真的會動的譜線（§1.1）再考慮改模式。
5. 先到 Recordings 看一眼**那個波長到底有沒有峰**。若只是一段平滑的連續光，再怎麼調 SNR 都沒有用 —— 把 **Extraction** 改成 `RawMean`（見 §6.4.2），或換一條真的存在的譜線。
6. 最後手段：調低該比值的 **Min SNR**。**不建議**設為 0 —— 那等於關掉假警報保護。

### 9.5 Golden Run 錄完後某條比值沒有基準線

擷取一結束就會**跳出警告視窗**列出被拒絕的比值與原因，同樣的句子也會寫進系統日誌；下面是各種原因的處理方式。

系統日誌會有 `GoldenRunRatioLowSnr` 記錄。原因是該比值可評估的幀當中，通過 SNR 下限的**不到一半**，基準線被主動拒絕了。

若日誌寫的是 **`GoldenRunRatioDropped`**，代表該比值一幀都沒被採用。訊息會直接說是哪一種：監控譜線落在光譜儀波長範圍外、電漿閘門全程關閉（檢查記錄器的觸發波長／存檔門檻，見 §10.2）、參考譜線從未出現、或該比值整段擷取都是停用的。

若日誌寫的是 **`GoldenRunRatioUnstableBaseline`**，原因不同：基準均值本身不夠遠離 0（例如 `−25 ± 95`）。這代表該波長沒有峰，扣背景後只剩雜訊 —— 把 **Extraction** 改成 `RawMean` 再錄一次。

若日誌寫的是 **`LeakMonitorBaselineMismatch`**，基準線是好的，但你之後改了某個讓它失效的設定（參考譜線、監控方式、擷取方式、或升級後積分單位改變）—— 重錄即可。

**若是「所有」比值都沒有基準線**（跳出的是錯誤視窗、日誌記 `GoldenRunEmpty`），這次擷取已被整份丟棄 —— 原本使用中的基準線與洩漏率校正都沒有被動到，機台仍在用舊基準線監控。先照上面的原因排除，再重錄一次即可，**不必**擔心要去把舊基準線救回來。最常見的原因是電漿沒開／記錄器觸發門檻設得太高，讓電漿閘門整段關著（§10.2）。

> 若原因是「電漿還沒穩定」或「製程太短，擷取視窗湊不到足夠的幀」，那不是設定問題，是現場擷取本身不適用——改用 **Baseline Builder**（§6.7）從錄製檔事後挑穩定段，短製程可以把多次 run 合起來。

### 9.6 日誌出現 `SpectrumFrameDropout`

代表**光譜儀送回了整幀全暗的資料**（正常幀最亮處約數萬 counts，全暗幀只有幾十）。這不是製程事件 —— 真正的電漿熄滅會持續超過一秒，而這種掉幀通常只有一到兩幀、約 0.3 秒。

程式的電漿閘門會把這些幀丟掉，所以**讀值不會被汙染**；記這筆日誌是因為丟得無聲無息，你需要知道儀器有沒有在出這種狀況。實測曾在 13 分鐘內出現 20 幀，其中**一幀落在 Golden Run 擷取視窗內就足以讓該比值的基準線被拒絕**（σ 變成均值的 2.4 倍）。

處理方式：

1. 到 Configuration 分頁把 **Acquire Mode** 從 `HardwareAverage` 改成 **`Oneshot`** → Apply → Save，這是 Z5 / Ethernet 模組出現分段或撕裂幀時的既有解法。
2. 跑一段一樣長的時間，比較日誌裡 `SpectrumFrameDropout` 的 `FramesThisSession` 數字有沒有下降。
3. 若沒有改善，檢查 USB／網路線材與接頭，並考慮降低積分時間。

處理方式同 §9.4 —— 先把訊號救起來，再重錄。

### 9.7 進不了 Configuration 分頁

正常行為 —— 該分頁需要 **Engineer** 以上。點進去會跳出登入視窗，取消就退回原本的分頁。請用 Engineer 或 Admin 帳號登入。

若登入後角色又掉回 Engineer 以下（例如閒置自動鎖定），畫面會自動跳回 Monitor 分頁。

> 📌 **歷史問題（已修正）**：舊版用硬編的分頁索引做這道檢查，在插入 Wavelength Calibration 分頁後指到了錯誤的分頁，導致 Configuration 一度**完全沒有權限保護**。現已改為以分頁名稱（`x:Name`）比對，插入新分頁不會再讓權限檢查失準。若你手上的版本早於此修正，請升級。

### 9.8 改了 Ratio Setup 但沒反應

Ratio Setup 與 Wavelength Calibration 的修改是**暫存**的。按完 **Save** 之後，必須到 Monitor 分頁 **Stop → Start** 重啟擷取才會生效。

（Leak Calibration 例外 —— 它存檔後立即生效。）

### 9.9 沒有產生 Ratio CSV

依序確認：

比值 CSV **不需要**記錄器武裝，也不看觸發門檻 —— 只要 OES 在擷取就該有檔案。所以依序確認：

1. OES 是不是真的在擷取（Monitor 分頁 `Status: Acquiring`）。沒擷取就不會有任何資料。
2. `settings.json` 裡 `LeakMonitor.Enabled` 與 `RatioCsvEnabled` 是否都為 `true`（預設是）。
3. 看 **Logs** 分頁有沒有 `RatioCsvSkipped`（設定被關）或 `RatioCsv_Open_Failed`（路徑寫不進去，例如磁碟滿或無權限）記錄，裡面會寫原因。
4. 檔案位置跟強度 CSV 同一個資料夾，但**檔名時間戳不同** —— 別拿強度檔的時間去找它。

### 9.10 測試模式下警報不會跳

這是預期行為（`SuppressAlarmsInTestMode` 預設為 `true`）：合成光譜會把系統日誌灌滿沒有意義的警報。要演練警報，在 **Replay** 分頁勾 **Raise leak alarms during replay** —— 那正是要檢查警報的場合。

注意這個開關管的是**警報轉態有沒有被記錄與latch**；Leak Monitor 分頁的狀態不管勾不勾都照算照顯示，`SIMP_Ratio_*.csv` 的 `OverallState` 欄也照寫。所以「日誌裡一行 `LeakMonitorState` 都沒有」不等於「沒偵測到」，先去比值 CSV 看那一欄。

### 9.11 Guest 關不掉程式

這也是刻意設計 —— 必須先 **Sign In**（任何非 Guest 角色都可以）才能關閉視窗。X 鈕、Alt+F4、系統選單都會被擋。

### 9.12 重播的結果和實機當時不一樣

先分清楚是**光譜**不同還是**判讀**不同 —— 重播送出的光譜是逐幀原樣的，所以幾乎都是後者。

1. 打開這一輪的 `SIMP_Ratio_*.csv` 和實機當時的 `P_Ratio_*.csv`，比**原始比值欄**（不是百分比欄）。若相同（差 0.001 % 以內），光譜路徑沒問題，往下看第 2 點；若不同，是比值定義或波長校正被改過。
2. 比 **% of baseline** 欄。原始值相同而百分比不同，就是基線不同 —— 檢查目前作用中的 Golden Run 是哪一個、什麼時候抓的、抓的時候在放哪一段。基線抓在洩漏區間是最常見的原因。
3. 檢查 `SIMP_Ratio_*.csv` 的列數等不等於錄檔幀數。少了就是那一輪被中途按了 Stop（日誌會寫 `stopped by the operator`），不能拿來比。
4. 確認錄檔對得起來：一次採集常被切成好幾個輪替檔，比較的兩段要涵蓋同一段時間。

完整的比對程序見 §8.5。

### 10.5 出廠預設比值

全部以 **Ar 750.4 nm（PeakHeight）** 為參考線；門檻倍數 Warn **1.05** / Alarm **1.12**，σ 3 / 6。

| Key | 名稱 | 角色 | 訊號線 | 擷取方式 | 出廠 |
|---|---|---|---|---|---|
| `R_N2Ar` | N₂ 337 / Ar 750 | 主指標（實測 33.8σ） | N₂ 337.1 nm | RawMean（半寬 1.0） | 啟用 |
| `R_NOAr` | NO 237 / Ar 750 | 次指標（18.3σ，另一個物種的獨立意見） | NO 237.0 nm | RawMean（半寬 1.5） | 啟用 |
| `R_N2357Ar` | N₂ 358 / Ar 750 | 第三條（16.2σ），讓「三取二」有餘裕 | N₂ 357.7 nm | PeakHeight（半寬 0.5） | 啟用 |
| `R_N2357Abs` | N₂ 358 absolute | 診斷用：同一條線**不除以 Ar** | N₂ 357.7 nm | RawMean（半寬 1.0）、`AbsoluteIntensity` | **不啟用** |

**為什麼是這幾條**：這是 §1.1 那次已知洩漏實測**挑出來**的結果，不是教科書假設。舊出廠組（`O 777 / N₂ 337` 等四條）依據的是「空氣洩漏會抬高 O 的發光」，而同一次實測裡 O 777.2 只有 0.7σ、OH 308.9 只有 0.1σ，真正動的是被放在分母的 N₂ 337.1（33.8σ）—— 分子與分母反了。

**第三條的用途**：`RequireTwoForAlarm` 出廠是 true（要兩條同時 Alarm）。只有兩條時，任一條掉進 LowSignal 或沒有基準線，整體就再也升不到 Alarm，而畫面上不會有任何提示。三條啟用時掉一條仍能報警。

**第四條的用途**：它和第三條讀**同一條譜線**，差別只在有沒有除以 Ar 750.4。兩條並排看，就能直接判斷「訊號上升」是化學變化還是整個光譜一起變亮（巡檢計畫診斷矩陣裡最難判的那一列）。出廠不啟用，是因為絕對強度在洩漏排除後**回不到基準線**（實測仍高 +7.6%，同一時刻 Ar 正規化的比值已回到 +1%），也會跟著觀察窗髒污漂移 —— 開著會讓機台在每次事件後長期掛著 Warning。要用時到 Ratio Setup 勾選、Save、重啟擷取。

> ⚠️ **這仍然是「一台機器」的答案，不是通用建議值。** 壓力、功率、氣體組成一變，會動的物種就可能換人。**上線前請依 §1.1 用一次已知洩漏重做一次挑線**。門檻倍數 1.05 / 1.12 也是配著那台機器 2% 的基準散度調的：散度 8% 的機台用 1.05 會天天假警報。（出廠的 1.2 / 1.5 則是相反的問題 —— 配上 2% 散度會讓乘法那一支永遠勝出而把 σ 門檻整個蓋掉，詳見 §6.4.2。手動**新增**比值時的起始值仍是 1.2 / 1.5，見 §10.3。）
