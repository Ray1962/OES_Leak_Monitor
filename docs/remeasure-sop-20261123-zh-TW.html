A. Baseline Builder

A1. 列出錄檔

  1. 進 Baseline Builder 分頁。
  2. From 設成 2026-11-23,To 設成 2026-11-23 → 按 Refresh。 → 狀態列:{n} recording(s) in …
  3. 在 Use 欄勾選下列 8 筆(其他不勾):

A2. 掃描

  1. 按 Scan ticked,等按鈕恢復可按。 → State 欄,每筆應為:
    • P1_Ar · 約 80 frames, 約 89 s
    • P2_NoAr · 約 40 frames, 約 43 s
    • 若出現 Unknown ·,或 class 跟上表不同:停,通知 Engineer(分類器設定有問題)。

A3. 選視窗

  1. 逐筆點選 → 在 Baseline window: 兩格輸入上表的秒數(按 Tab 離開欄位才生效)。 → 該列 Window 欄出現數字。
    • 不要用 Whole file:每段結尾都有幾秒是碳源已經關掉的過渡段。
  2. 確認 8 筆的 Window 欄都有數字。

A4. Build(只算,不存)

  1. Golden Run name 填 remeasure-20261123 → 按 Build。 → 畫面最下方的結果面板出現文字。

A5. 讀結果

  1. 看 Baselines (n): 與 No baseline for:,對照下表:

  • 第 4 組若設成 N₂ 357.7(只用右側窗):預期 mean 約 0.015,預期被拒(約 5.9)。
  • 「預期被拒」是正常結果:4 次 run 的含氮指標一路在降,合併後的 σ 被拉大。
  • 被拒的比值,看 How far the recordings disagree with each other 那一段 → 應顯示 run 間差距是檔內散度的數倍。
  1. 看 How steady each chosen window is: → 每筆 σ/mean 應在 10 % 以內。超過 → 視窗可能沒對準,回 A3 重設。

A6. 單筆再量一次(只量比值 1、2)

  1. 取消勾選其他錄檔,只留 P_OES1_1123155536(最後一次長段) → Build。 → 預期比值 1 的 mean/σ 約 14,比值 2 約 26,兩者都通過。
    • 若比值 1、2 顯示幀數不足(少於 60 幀):把視窗起點改成 5.0 s 再 Build。
    • 單筆短段只有約 25 幀,不夠 60 幀,比值 6–9 會被拒:正常。

B. Replay(Engineer,選用)

⚠️ 只在機台不跑製程、光譜儀已斷線時做。有接光譜儀時 Play 按不下去。

  1. 斷開光譜儀,App 進入測試模式。
  2. 進 Replay 分頁 → Choose CSV… → 選 C:\DualOES\202611\23\P_OES1_1123155536.csv。
  3. 速度選 20× → Play,等到狀態變成 Finished。
  4. 依序再播 P_OES1_1123155443.csv(短段)。 → 今天的日資料夾會多出 SIMP_OES1_*.csv、SIMP_Ratio_*.csv。
  5. 用 Ratio Review 開 SIMP_Ratio_*.csv。 → 各比值的原始值應接近 A5 表的「預期 mean」;沒有 Golden Run 的比值不會有 % 值。
  6. 收尾:
    • 刪除今天日資料夾裡的 SIMP_* 檔。
    • C:\DualOES\_batches.csv 會多出 Replay 的批次列,把它們刪掉。
    • 重新連上光譜儀,確認 Monitor 分頁回到即時量測。

C. 紀錄

  1. A5、A6 每次 Build 完,把結果面板全文複製出來,存成: C:\DualOES\202611\23\_remeasure_20261123_{今天 yyyyMMdd}.txt (檔名要用底線開頭,才不會被列進錄檔清單)
  2. 在同一個檔案最後補上:
    • 做的人、日期
    • A2 每筆的 class
    • 與 A5 表不同的地方
  3. 交給 Engineer。
