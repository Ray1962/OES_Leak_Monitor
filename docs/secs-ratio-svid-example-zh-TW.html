Species Ratio 槽位 SVID 範例說明

本文以設備出廠比值組為例，說明 Ratio Setup 中每一組 Species Ratio 對應的 SVID 怎麼算、讀到的值代表什麼。 依據：docs/Satellite_SECS_Specification_v2.md §1.4(b)～(d)、§6.2。

實作狀態： 比值槽位 VID 101～400（位移 01～25）與 CEID 507 已由設備端實作（規格 v2.4），可用 S1F3 查詢、S2F23 追蹤。 第 3、5 節的身分類數值是出廠比值組實際會送出的值；第 4 節的即時量是虛構的範例值。 舊機台的 profile 若是 2026-10-23（加入槽位 VID）之前寫的，要先在 SECS 分頁按「Add missing rows」並重啟介面，才查得到這些 SVID。

1. 編碼規則

SVID 為 10 位數 1ccssaavvv。OES Leak Monitor 的 ss 固定為 27，aa 固定為 00（OES 不經 slit valve），cc 為腔體代號。比值槽位的 vvv 由下式決定：

SVID = 1 + cc + 27 + 00 + vvv
vvv  = 100 + (N − 1) × 30 + 位移        （N = Ratio Setup 的第 N 列，1～10）

每個槽位佔 30 個號碼，號碼範圍為 [100+(N−1)×30+1, 100+N×30]：

槽位起算值（位移 0）VID 區段槽位起算值（位移 0）VID 區段
Ratio 1100101～130Ratio 6250251～280
Ratio 2130131～160Ratio 7280281～310
Ratio 3160161～190Ratio 8310311～340
Ratio 4190191～220Ratio 9340341～370
Ratio 5220221～250Ratio 10370371～400

算一次： Ch_2 的 Ratio 2「基準百分比／σ 分數」（位移 03） = 100 + (2 − 1) × 30 + 03 = VID 133 → SVID = 1 + 02 + 27 + 00 + 133 = 1022700133

本文以下範例一律假設設備裝在 Ch_2（cc = 02）。

3. 身分類 SVID（位移 16～25）

這一組 SVID 描述「這個槽位在監測什麼」，只在比值設定重新載入（設備重新開始採集）時可能改變；改變時設備送 CEID 10227507。Host 讀這一組就能知道每個槽位對應哪條譜線，不需要取得設備的設定檔。設備剛啟動、還沒有任何光譜時就讀得到。

  • 自訂譜線的物種一律以 u 開頭（如 uN2），由此可分辨現場自訂譜線與內建譜線。

6. Host 端建議的讀法

  1. 建立對照表： 連線後，或收到 CEID 10227507（槽位身分改變）時，讀每個槽位的位移 16～25，記下「槽位 → Key／訊號線／參考線／單位」。507 只在身分真的變了才送（調整順序、增刪比值、改譜線／監測方式／擷取方式／啟用／名稱／波長修正）；只改門檻不送。
  2. 以位移 25 的 Key 追蹤比值，不要以槽位號。 工程師在 Ratio Setup 調整順序（▲／▼）或刪除、新增比值後，同一個槽位號可能換成另一組比值；用 Key 對應，才不會把 A 比值的歷史接到 B 比值上。位移 22 只拿來顯示。
  3. 追趨勢： 平常用 S2F23 Trace 追各槽位的位移 03（1022700103、1022700133、1022700163…），不要用事件報告逐幀推送。
  4. 先看單位再判讀： 每次讀位移 03／04 之前先看位移 18。0 是基準百分比、1 是 σ 分數；兩者共用 100／120／150 的刻度（基準／警告／警報），但物理意義不同，不可混算。
  5. 停判不等於正常： 位移 05 為 3～8 的槽位都不納入複合警報，Host 不應把它們當成 Normal。
  6. 洩漏率要看校正狀態： 位移 14 只有在 VID 006（Calibration status）= 1 時才有意義。

7. 規格與程式碼不一致之處（v2.2／v2.4 處理情形）

以下三點是比對規格 v2.1 與設備端程式時發現的。前兩點已在規格 v2.2 修正，第三點在 v2.4 決定。

  1. 位移 18 的判定條件——已修正。 v2.1 §1.4(d) 寫「原始平均 + 絕對強度模式」才改用 σ 分數；程式碼的判定是 RatioDefinition.ValueHasPedestal——分子是 RawMean 就算，比值模式也算，因為除以參考線只會等比縮放連續光基座，不會消掉它。照 v2.1 字面，出廠的 Ratio 1、2 會被標成「百分比」，Host 會讀錯。v2.2 改為只看位移 19。
  2. 位移 05 的狀態碼——已修正。 v2.1 只列 0～6；程式碼另外還有 Observing（7，TrendOnly／Guard 角色）與 NotApplicable（8，不屬於目前的製程類別）。v2.2 已增列，附加在尾端，0～6 不變。
  3. 位移 22 填哪個名稱——已決定（v2.4）。 規格 v2.1 範例填 R_N2Ar，那是 Key。程式碼中 Key 一旦設定就永不改變（改名後基準與校正才不會失效），新增比值時 Key 是隨機 GUID 片段；畫面上顯示的是 DisplayName（如 N₂ 337 / Ar 750）。v2.4 的決定：位移 22 = DisplayName，原保留的位移 25 = Key，兩者都送。
