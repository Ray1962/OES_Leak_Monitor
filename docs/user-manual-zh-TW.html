1. 這個軟體在做什麼

OES Leak Monitor 用光學發射光譜（OES）即時偵測製程腔體的空氣／氧氣洩漏。

核心方法是 actinometry（比值法）：

  • 空氣漏進電漿後，會改變某些物種的發光強度 —— 哪些物種，取決於你的電漿（見下方警告）。
  • 但譜線的絕對強度也會隨電漿功率、壓力、氣流、窗口髒污而漂移 —— 直接看絕對強度會誤判。
  • 所以把「訊號譜線」除以一條參考譜線。電漿條件漂移會同時放大／縮小兩者，相除後被抵消，剩下的變化就主要來自洩漏。

⚠️ 哪些譜線會對洩漏起反應，是你機台的實驗結果，不是常識。

教科書上的 actinometry 多半拿 O 777.2 / Ar 當空氣洩漏指標，本軟體的出廠預設比值（§10.5）也是照這個假設配的。但在一台 Ar 80 sccm、0.95 torr、RF 50 W 的實機上實測：O 777.2 對 100 單位的空氣洩漏只有 0.7σ 的反應（等於沒有），而 N₂ 337.1 有 33.8σ —— 分子與分母的角色完全反了過來。

壓力、功率、氣體組成一變，會動的物種就可能換人。上線前一定要用一次已知洩漏實測，確認哪條線真的會動（見 §1.1）。跳過這一步，監控器會看起來一切正常而完全抓不到洩漏。

1.1 上線前必做：用一次已知洩漏挑譜線

  1. 讓製程在正常條件下穩定，錄一次 Golden Run。
  2. 用針閥或標準漏孔，分幾個階段引入空氣，每階維持至少 60 秒。階數越多越好 —— 三階只能看出有沒有反應，九階才能看出線性與偵測下限。
  3. 事後用 Recordings 分頁比對「基準期」與「最大洩漏期」的平均光譜。
  4. 挑出變化最大的譜線 —— 但一定要先除以一條惰性參考線（Ar 750.4 或 811.5）。洩漏常會讓整個光譜一起亮 5–10%，那是電漿阻抗改變，不是化學變化；不除掉它，每條線看起來都有反應。
  5. 用挑出來的線設定比值（§6.4），重錄 Golden Run，再跑一次洩漏測試，確認警告／警報會在你要的劑量觸發。

判斷標準不是「變化幾 %」，而是「變化是雜訊的幾倍」。 一條變化 +50% 但基準散度 8% 的線（6σ），不如一條變化 +17% 但散度 2% 的線（8.5σ）。Golden Run 會把每個比值的 σ 記下來，用它來比。

前述那台機器的實測結果，可以當作這個程序的範例（100 單位空氣洩漏，全部已除以 Ar 750.4）：

軟體會：

  1. 在無洩漏的良品製程中錄下基準線（Golden Run） —— 每個比值的平均值與標準差 σ。
  2. 即時計算比值，做 EMA 平滑，與基準線比較。
  3. 超過警告／警報門檻並持續一段時間後才升級狀態（避免瞬間雜訊誤報）。
  4. 若做過洩漏率校正（Leak Calibration），還會把比值上升量換算成定量洩漏率 Q̂（mbar·L/s）。

同時它也是一台資料記錄器：當指定波長的強度超過門檻時，自動開檔記錄光譜 CSV 與比值 CSV，事後可在 Recordings / Ratio Review 分頁回放。

2. 安裝與啟動

2.1 標準安裝（免安裝 .NET）

發布產物是一個資料夾，內含單一 .exe 與數個原生 DLL：

OES_Leak_Monitor.exe          ← 主程式（已內含 .NET 8 執行環境）
UserApplication.dll           ← OES 硬體 SDK
SiUSBXp.dll                   ← USB 驅動介面
libsodium.dll                 ← SDK 相依
wpfgfx_cor3.dll               ← 以下為 WPF 原生元件
PresentationNative_cor3.dll
D3DCompiler_47_cor3.dll
PenImc_cor3.dll
vcruntime140_cor3.dll

⚠️ 整個資料夾要一起複製，不能只拷貝 .exe。 那幾個 DLL 是刻意放在 .exe 旁邊的 —— SDK 的 DllResolver 只會在程式所在目錄找它們。少了 UserApplication.dll / SiUSBXp.dll，程式仍會啟動，但連線會無聲地掉進測試模式（畫面看得到假光譜，卻連不到硬體）。

需求：64 位元 Windows。目標電腦不需要安裝 .NET。

2.2 啟動

雙擊 OES_Leak_Monitor.exe。首次啟動會在 %APPDATA%\OES_Leak_Monitor\ 建立設定與資料夾。

2.3 測試模式（無硬體）

沒接到光譜儀時，按 Connect 會自動退回測試模式，產生合成光譜（正弦波＋雜訊，約 200–800 nm、1000 點）。整個 UI 都能操作，適合教育訓練與功能驗證。

在測試模式下：

  • Leak Monitor 分頁會顯示 "test mode" 註記，並註明目前的光譜來源是合成波形還是重播的錄檔、警報是否生效。
  • 警報預設被抑制（SuppressAlarmsInTestMode），比值照算照畫，但不會真的跳 ALARM。要演練警報，在 Replay 分頁勾 Raise leak alarms during replay。
  • 可以在 Replay 分頁選一個已錄製的全光譜 CSV 來取代合成波形，用真實電漿資料驗證偵測演算法（見 §6.7 與 §8.5）。

5. 快速上手：從零到監控

第一次在一台新機台上導入，依序做完這六步：

步驟 1 — 連線並確認有光譜

  1. 到 Monitor 分頁。
  2. 按 Connect。下方狀態列的 Test Mode 應顯示 False，Serial 應顯示實際序號。
    • 若顯示 True 但硬體確實接著 → 見 §9.1。
  3. 按 Start。全光譜圖應開始更新，Last 時間持續跳動。

步驟 2 — 調整硬體參數

  1. 到 Configuration 分頁（需 Engineer）。
  2. 設定 Integration Time（積分時間）：讓最強的譜線約落在滿刻度的 50–80%，不要飽和。
  3. 需要降雜訊時調 Average Count；若發現峰位被硬體平均扭曲，把 Average Mode 改成 Software（見 §6.2.1）。
  4. 按 Apply 推送到硬體，再按 Save 寫入 settings.json。

步驟 3 — 設定要監控的比值

  1. 到 Ratio Setup 分頁。
  2. 出廠預設已有四組比值：O 777 / N₂ 337、OH 309 / N₂ 337、NO 237 / N₂ 337、Ar 750 / N₂ 337。
  3. 檢查你的光譜儀波段是否涵蓋這些波長 —— 涵蓋不到的請取消勾選或改選別的譜線。
  4. 若某條訊號線太弱（接近雜訊底），把該比值的 Monitoring method 改成 AbsoluteIntensity（見 §6.3.2）。
  5. 按 Save。
  6. ⚠️ 回 Monitor 分頁按 Stop → 再按 Start。Ratio Setup 的修改是「暫存」的，只有在擷取重啟後才生效。

步驟 4 — 錄基準線（Golden Run）

  1. 讓機台跑一段確定沒有洩漏的良品製程，電漿條件穩定。
  2. 到 Leak Monitor 分頁 → 按 Capture Golden Run。
  3. 輸入配方／基準線名稱（例如 Recipe-A-20260804）。
  4. 勾選「I confirm the process is currently running leak-free.」→ 按 Start Capture。
  5. 預設平均 60 秒。進度條跑完後，基準線立刻寫入 settings.json。
  6. 上方 Baseline 下拉會自動選到這條新基準線。
  7. 若跳出視窗，先看完再繼續：警告視窗代表有比值沒拿到基準線（那幾條不會參與警報）；錯誤視窗代表一條都沒拿到，這次擷取已被丟棄、舊基準線原封不動 —— 依視窗上的原因排除後重錄（見 §6.3.5 與 §9.5）。

此時洩漏偵測就已經在運作了 —— 狀態列會顯示 OK — within baseline。

步驟 5（選用）— 洩漏率定量校正

只有需要把「比值上升」讀成 mbar·L/s 時才要做。見 §6.5。

步驟 6 — 開啟資料記錄

  1. Configuration → 下半部 Data Logger。
  2. 設定 Trigger Wavelength（判斷「電漿開了」的波長，例如 337.1）與 Save Threshold Intensity。
  3. 按 Apply → Save。
  4. 按 Start Save 武裝觸發器。當強度持續超過門檻達 Start Confirm Time 後，自動開檔。

6. 分頁詳解

6.1 Monitor（即時監看）

6.1.1 頂部：Reset Run

Reset Run（Operator+）用在「調完參數，想從乾淨的狀態重新開始這一爐」：

  • 關閉目前的 Intensity CSV 與 Ratio CSV。兩者開新檔的時機不同：Intensity CSV 要等下一次超過門檻，Ratio CSV 下一幀就開新檔。
  • 清空 Monitor 強度趨勢圖與 Leak Monitor 的 % 趨勢圖。
  • 重置各比值的即時平滑。

保留不動：Golden Run 基準線、洩漏率校正、已鎖存的警報（必須由人按 Acknowledge 才清除）、擷取本身持續進行。

鎖存的警報也會跨越「停止 → 啟動擷取」。 重啟擷取會套用 Ratio Setup 的暫存修改（重建所有比值），以前那個重建會把鎖存的警報一起清掉 —— 等於不用 Acknowledge 就能讓一個已確認的洩漏消失。現在只有「該比值被刪除、停用，或被改成量別的東西」時鎖存才會放掉，而且會在日誌記一筆 LeakMonitorAlarmLatchDropped。只調門檻或平滑參數不算改變量測對象，鎖存會保留。

若你剛改過積分時間或其他會影響絕對強度的設定，Reset Run 不夠 —— 請重新錄一次 Golden Run，因為舊基準線是在不同曝光條件下錄的。

6.1.2 Recorder 狀態列（唯讀）

Reset Run 底下的細長狀態列（標示 Spectrum recorder），顯示全光譜記錄器現在到底有沒有在錄。純顯示，這裡按不到任何東西 —— 記錄器的開關與所有設定都在 Configuration 分頁（需 Engineer），但看狀態不需要權限，Guest 也看得到。

這條狀態列只講強度（全光譜）CSV。比值 CSV 是另一個獨立的記錄器，只要 OES 在擷取就一直寫，即使這裡顯示 OFF 也照常產生（見 §7.3）。

徽章顏色意義
OFF紅記錄器沒有武裝 —— 不會產生強度 CSV（比值 CSV 不受影響，見 §7.3）
ARMED藍已武裝，等待強度跨過觸發門檻。右側會寫出目前的門檻條件
STARTING橘已高於門檻，正在等 Start confirm 時間
SAVING綠正在寫強度 CSV，右側顯示目前檔名
STOPPING橘已低於門檻，正在等 Stop confirm 時間

滑鼠停在狀態列上會顯示完整檔案路徑（沒有開檔時則顯示開檔條件）。

若右側出現橘色小字 「armed but not saved — reverts to OFF on restart」，表示有人在 Configuration 分頁按了 Start Save 卻沒有按 Save —— 目前確實在錄，但這個狀態沒有寫進 settings.json，下次重開程式就會變回 OFF。回 Configuration 按一次 Save 即可消除。反向的「disarmed but not saved」同理。

💡 每日巡檢的第一眼就看這條 —— 它是「以為在錄、其實沒錄」這個失效模式唯一的可見警示。

6.3.5 Golden Run 擷取流程

  1. 確保製程正在跑，而且確定沒有洩漏。
  2. 按 Capture Golden Run。
  3. 填入配方／基準線名稱。
  4. 勾選確認框（不勾就不能按 Start Capture）。
  5. 按 Start Capture，預設平均 60 秒。
  6. 只要至少有一條比值取得基準線，這次擷取就會立即寫入 settings.json 並自動設為使用中的基準線。

擷取結果會當場告訴你：

結果畫面發生什麼事
全部比值都拿到基準線狀態列顯示「captured — N ratio baseline(s)」存檔並啟用
部分比值被拒絕跳出警告視窗，列出沒拿到基準線的比值與原因仍然存檔並啟用；被拒的比值顯示 No Baseline，不參與洩漏警報
沒有任何比值拿到基準線跳出錯誤視窗這次擷取整份丟棄：不存檔、不啟用、也不會蓋掉同名的舊基準線。原本使用中的基準線與洩漏率校正完全不受影響

為什麼要丟棄：一次什麼都沒量到的擷取，若照樣存檔並啟用，會讓每一條比值瞬間失去基準線（面板全變 No Baseline、洩漏警報整個停擺），還會連帶把綁定的洩漏率校正一起解除配對 —— 而這一切的依據是一段根本沒量到東西的資料。日誌記 GoldenRunEmpty，訊息會寫明目前使用中的基準線沒有變動。

擷取期間的品質把關：

  • 只有通過 SNR 下限的幀才會被納入該比值的基準線（跟即時判定用同一道關卡）。
  • 若某條比值可評估的幀當中，通過率不到 50%，這條比值的基準線會被直接拒絕，並記進系統日誌。 → 避免弱訊號譜線用「剛好往上跳的那幾筆雜訊」湊出一條假基準線。
  • 同時會記錄 PlasmaPresentFloor（＝參考譜線基準均值的 20%），之後用來判斷「電漿有沒有開」（僅 Ratio 模式使用）。
  • 基準均值必須明顯離開 0：若均值 ≤ 0，或均值不到自身 σ 的 10 倍，該比值的基準線會被拒絕並寫進日誌。門檻、% 顯示、洩漏率全都要除以這個均值，一個「−25 ± 95」的基準線會讓三者都變成擲硬幣。日誌訊息會建議改用 RawMean 擷取（該波長若本來就沒有峰）。
  • 同時記錄擷取當時的取得參數（積分時間、平均次數、boxcar、acquire / average mode、背景移除等開關、波長軸長度與範圍）。之後只要現況與基準線不符，Leak Monitor 上方會出現警示條，系統日誌也會記一筆 LeakMonitorAcquisitionMismatch。

⚠️ 什麼時候必須重錄 Golden Run：改了積分時間或其他影響絕對強度的設定、換了參考譜線（Ratio 模式）、改了監控方式或擷取方式、清理過觀察窗、換過光纖、製程配方改變。前三項程式會自動偵測並停用舊基準線；其餘的只有你知道。

6.4.2 右側：選定比值的細節

基本

  • Display name — 顯示名稱。
  • Enabled — 是否納入監控。

Monitoring method（監控方式） — 這是關鍵選擇：

模式監控的量適用情境
Ratio訊號 ÷ 參考預設。 標準 actinometry，能抵消電漿條件漂移
AbsoluteIntensity訊號線的絕對強度（扣背景後）<br>完全不使用參考線訊號線很弱、接近雜訊底時。兩個小數字相除會劇烈擺盪，拿掉除法就少一個雜訊來源

AbsoluteIntensity 的代價：不再抵消電漿條件漂移（功率／壓力／流量變化會直接反映在讀值上）。因此使用它時必須維持穩定的操作點，並更頻繁地重錄基準線。

「電漿存在」判定來自記錄器的儲存觸發（Configuration 分頁的 trigger 波長與 save-start 門檻，建議值見 §10.2）。AbsoluteIntensity 模式完全只看它 —— 選了這個模式，右側就不會出現 Reference line 欄位；Ratio 模式則是兩個條件都要成立：儲存觸發過門檻，而且參考譜線本身可用。

這樣改的原因：絕對強度模式本來就不對參考線做除法，所以那條線根本不必存在；而一條不存在的譜線扣完背景後只剩在 0 附近正負跳動的雜訊，於是「參考線 > 0」變成一枚硬幣，決定這一幀要不要計算。更糟的是，若參考線落在彎曲的連續光上（兩側基準視窗拉出的直線會高於凸型連續光），扣出來會系統性為負，該比值就一幀也不會被評估 —— CSV 欄位整片空白，畫面永遠停在 No Plasma。同理，參考線的 SNR 也不再影響 Low Signal 判定，只看被監控的那條線。

% 趨勢的單位由「擷取方式」決定，不是由監控方式決定：只有 AbsoluteIntensity + RawMean（讀值帶連續光基座）才改用 σ 正規化分數（基準線 = 100、高一個 warn-σ = 120，斜率以 σ/min 計）。AbsoluteIntensity 搭配 PeakHeight / Integral 時，讀值已經扣掉背景，基準均值本身就是訊號，所以照常用 值 ÷ 基準均值 × 100（斜率 %/min）。

Signal line（訊號譜線）／ Reference line（參考譜線）（Reference line 只在 Ratio 模式出現）

  • Emission line — 從依元素分組的譜線 catalog 中挑選。若該譜線套用了波長修正，這裡會顯示例如 +0.20 nm → 777.4 nm。
  • Extraction（擷取方式）：
擷取方式量什麼什麼時候用
PeakHeight視窗內扣背景後的最大值窄的原子譜線
Integral視窗內扣背景後的積分，單位 counts·nm分子帶頭（OH、NO、N₂）
RawMean原始強度（不扣背景、不找峰）該波長根本沒有峰的時候

前兩種都會把「兩側基準視窗拉出的一條直線」當作連續光扣掉。在有峰的地方這是小修正；在沒有峰的地方，那條直線就是讀值的全部 —— 連續光通常是凸的，直線會高於中間，扣出來系統性為負；而 peak search 在單調斜坡上等於「往上坡走到底」，每一幀都把視窗釘在搜尋範圍的邊緣。實測（440.7 nm）：Integral 讀值 −11.7、63% 的幀為負；RawMean 讀值 3745 ± 19、0% 為負，而且雜訊還更低（不必付出估計背景本身的雜訊）。

RawMean 的代價是讀值帶著連續光基座，所以它也會跟著窗口髒污、雜散光、曝光時間變化 —— 這時改由 Golden Run 均值扮演背景：一個在可信時刻量到的基準，而不是每幀猜出來的。HalfWidthNm 在這個模式下是平均寬度，設 0 表示「在中心波長做線性內插取值」。

> ⚠️ RawMean 搭配 AbsoluteIntensity 使用時（建議的組合），三件事會自動改變： > 1. Warn / Alarm factor 被忽略，只用 σ 門檻 —— 基座的 1.2 倍是好幾十個 σ，那種警報永遠不會響，而且看起來像是有在戒備。 > 2. % 趨勢改為 σ 分數（基準線 = 100，高一個 warn-σ = 120），CSV 欄位也會改叫 _sigmaScore。 > 3. Min SNR 不適用 —— 原始強度除以連續光雜訊會得到幾百的「SNR」，那是基座不是譜線，所以乾脆不給 SNR（顯示 —）。

⚠️ 換了參考譜線，原本的 Golden Run 基準線就失效（Ratio 模式的基準線綁定當初的參考譜線）。換完必須重錄。絕對強度模式的基準線不綁參考線，但改變監控方式（Ratio ↔ AbsoluteIntensity）一定會讓舊基準線失效 —— 兩種模式量的根本不是同一個東西。

6.5 Wavelength Calibration（波長校正）

Engineer+ 才能存檔，同樣是暫存 → Stop/Start 才生效。

用途：補償光譜儀的波長軸漂移。每一列把 catalog 中的一條 (元素, 波長) 譜線加上一個位移量（nm）。

關鍵特性：因為 key 是 catalog 的 (元素, 波長)，所以修正一次就會同時套用到所有用到這條譜線的比值（不論它當訊號線還是參考線），不必逐一去改。

欄位說明
Element元素／物種
Wavelength (nm)catalog 中的原始波長

Add / Remove 增刪，底部 Save / Revert。存檔時會檢查位移範圍，並拒絕重複的 (元素, 波長) 組合。

這裡的修正只影響量測，不會寫回 settings.json 裡的原始 catalog 波長。

6.6 Leak Calibration（洩漏率校正）

Engineer+ 才能存檔。 目的：把「比值上升了多少」換算成「漏了多少 mbar·L/s」。

⚠️⚠️ 標準漏孔必須是空氣（或就是你要偵測的那種洩漏）。用惰性氣體（如 He）的標準漏孔完全無效 —— 它不會抬升 O / OH / NO 的訊號。

6.6.1 原理

對每個比值擬合一條過原點的加權最小平方直線：

x ≈ s · Q
  • x = 相對基準線的上升量。單位由讀值有沒有帶連續光基座決定：AbsoluteIntensity + RawMean 用絕對上升 Δ = 值 − 基準均值（相對上升會被基座壓縮到零點幾個百分點）；其餘一律用相對上升 值/基準均值 − 1（它對純比例縮放免疫，條件較好）
  • Q = 已知漏率（mbar·L/s）
  • s = 該比值的靈敏度

即時運算時反過來求 Qᵢ = xᵢ / sᵢ，再把所有比值用逆變異數加權融合成一個 Q̂ ± σ_Q，並給出跨比值一致性的信心度。

「無洩漏」狀態就是原點（Q = 0, x = 0），不需要另外量一個點。

6.6.2 操作步驟

  1. 選 Baseline (Golden Run) — 這份校正會綁定到這條基準線。
  2. 填 Calibration name — 例如 Recipe-A-cal-20260804。
  3. 掛上第一顆已知漏率的標準漏孔，打開它，等電漿穩定。
  4. 按 Capture Point…
    • 填 Known leak rate (mbar·L/s)，支援科學記號（1.2e-4）。
    • 填 Leak element / label（選填，建議填標準漏孔編號）。
    • 勾選確認框 → Start Capture。預設平均 30 秒。
  5. 換下一顆不同漏率的標準漏孔，重複步驟 3–4。至少兩點，建議三點以上並涵蓋你關心的漏率範圍。
  6. 檢查中間的資料表（漏率、標籤、比值數、各比值的 x ± σ）。
    • 要刪除某一點：選取後按 Remove Selected。
    • 全部重來：Clear Points。
  7. 按 Save Calibration。Fitted sensitivities 區塊會顯示各比值擬合出的靈敏度。

存檔後立即生效（不像 Ratio Setup 需要重啟擷取），Leak Monitor 分頁的讀值馬上會出現。

6.6.3 有效性把關

校正只在對應的 Golden Run 是使用中基準線時才會套用：

狀態行為
NotCalibrated沒有使用中的校正，只做定性警報
Active正常估算
BaselineMismatch基準線換成別條了 → 暫停估算（而不是給出被錯誤縮放的數字）

切換或重新擷取 Golden Run 時，系統會自動配對綁定該基準線的最新校正，所以換配方不會留下過期的 BaselineMismatch。狀態轉換都會寫進系統日誌。

若某個比值的 x 單位在校正之後被改過（改了監控方式或擷取方式，使讀值從「帶基座」變成「不帶基座」或反之），該比值的擬合會被拒用 —— 兩種單位的斜率不能互相套用。這也代表升級到本版之後，絕對強度比值的舊校正一律要重做。

完整的數學模型與設計文件見 docs/leak-rate-calibration.md。

6.7 Replay（重播驗證）

權限：Engineer 以上。

把一份已錄製的全光譜 CSV 當成即時光譜餵進整條流程 —— Leak Monitor、兩張趨勢圖、以及兩個記錄器都會收到 —— 用來在沒有硬體的情況下驗證偵測演算法。與 §6.8 Recordings 的差別：Recordings 是把資料畫出來給人看，Replay 是把資料重新跑一遍給程式判斷。

必須知道的六件事

  2. 用錄檔自己的波長軸。 例如 1896 點、179.8–850.3 nm，而不是測試模式那條 1000 點、200–800 nm 的合成軸。Ar 811.5 nm 這種超出合成軸的譜線才不會被丟掉，比值、σ、SNR、洩漏率才會和真機一致。
  3. 幀間隔照錄檔。 播放用虛擬時鐘：起點是按下 Play 的時刻，之後每一幀推進錄檔原本的間隔。倍速只縮短實際等待時間，演算法看到的時間軸等比例縮放，判斷結果不變 —— 20× 只是同一份證據送得快 20 倍。
  4. 只播一次。 播到最後一幀就停在那裡（FINISHED），不會循環。循環會把檔尾接回檔頭，下游的基線與警報會把那個接縫當成真實的階躍變化。
  5. 產出檔名帶 SIM。 重播期間兩個記錄器都改寫 SIMP_OES1_* / SIMP_Ratio_*，落在今天的資料夾。Recordings 與 Ratio Review 照樣列得出來，但一眼就分得出不是量測資料。

⚠️ 重播的第一秒會跳一次 LeakMonitorAcquisitionMismatch。 按下 Start 時裝置回報的還是合成軸（1000 點），基線若是從重播抓的（1896 點）就對不上。等重播的幀開始流動，比對對象換成錄檔的軸，警告就不再出現。只要基線與待驗證的錄檔來自同一台機、同一組曝光參數，這一次警告可以忽略。

⚠️ 不要拿實機抓的 Golden Run 去驗證重播。 錄檔裡沒有當初的曝光參數，重播的幀帶的是裝置目前的設定。基線請從重播本身抓 —— 完整做法見 §8.5。

7.2 檔名規則

{prefix}_{tag}_{MMddHHmmss}[_N].csv
  • prefix — Configuration 裡設的 File Prefix
  • tag — OES1（強度檔）或 Ratio（比值檔）
  • MMddHHmmss — session 起始時間（年份由上層資料夾還原）
  • _N — 續檔序號。兩種情況會產生：(a) 單檔超過記憶體預算；(b) 存檔途中光譜波長軸改變（重新套用擷取參數、裝置重連），此時舊檔關閉、以新的波長軸開新檔，Logs 分頁會留下一筆 SpectrumAxisChanged 警告

⚠️ 看到 SpectrumAxisChanged 就代表這一爐的資料被切成兩段不同波長軸的檔案。若它是因為你改了曝光相關參數而產生，請重錄 Golden Run —— 舊基準線是在舊曝光條件下錄的。

7.3 比值 CSV 格式

Timestamp,NO 237 / Ar 750.4 [R_7c40d2f9],NO 237 / Ar 750.4 [R_7c40d2f9]_pctBaseline,…,OverallState,LeakRate,LeakRateSigma

每個比值兩欄（原始值 + % 基準），最後三欄是整體狀態與洩漏率估計。欄位是依標題名稱尋址的，所以舊版沒有 LeakRate 欄位的檔案仍可正常解析。

欄名同時帶著名字與代號：{顯示名稱} [{key}]。

  • 名字是你在 Ratio Setup 取的顯示名稱，讓檔案自己說明它記的是哪條譜線 —— 用 Excel 打開就看得懂，不必回去對 settings.json。
  • key（例如 R_7c40d2f9）是這條比值建立時產生的隨機識別碼，永遠不會變。改名字、換門檻、換抽取模式它都不動，Golden Run 基準線與洩漏率校正才不會因為你改了個名字就失效。程式一律認這個碼。

📝 舊檔（欄名只有 R_xxxxxxxx）照樣讀得開，只是 Ratio Review 的圖例會顯示代號而不是名字 —— 那些檔案裡沒有名字可用。

第二欄的名稱會說明它裝的是什麼：一般是 …_pctBaseline（% 基準）；若該比值採 AbsoluteIntensity + RawMean，就會是 …_sigmaScore（σ 分數）。兩者都畫在同一組 100/120/150 標尺上，但不是同一個量，所以 Ratio Review 會在圖例標上 (σ-score)。

⚠️ 顯示名稱裡的逗號會被寫成分號、中括號會被寫成小括號 —— 否則會把 CSV 的欄位切壞。取名字時盡量只用物種、波長與斜線，例如 N2 337.1 / Ar 750.4、N2 337.1 (abs)。

比值檔與強度檔是各自獨立的記錄器，只共用同一個輸出資料夾與檔名前綴：

強度 CSV（_OES1_）比值 CSV（_Ratio_）
什麼時候寫只在強度高於觸發門檻時只要 OES 在擷取就一直寫
需要武裝嗎要（Recorder 狀態列須非 OFF）不用 —— 記錄器 OFF 也照樣產生
每列大小全譜約 22 KB（5 Hz ≈ 400 MB/小時）約 200 B（5 Hz ≈ 4 MB/小時）
何時關檔低於門檻並滿足停止確認停止擷取、Reset Run、或跨過午夜（自動換日換檔）

💡 這是刻意的設計：比值資料是洩漏監控的核心記錄，體積只有全譜的百分之一，不應該因為「原始光譜錄影沒開」就跟著消失。 也因此比值檔的時間戳不再與強度檔相同 —— 兩者各自開檔，不要用檔名時間去配對它們。

壓縮不是刪除。 202605\08\ 會變成 202605\08.zip，裡面是原封不動的 CSV，用任何解壓縮軟體（含 Windows 內建的「解壓縮全部」）都能取回。要不要真的刪除，由貴廠的保存規範決定，程式不替你決定。

安全規則：

  • 最新 2 天永遠不壓，正在寫入的檔案也不壓。
  • 資料夾裡只要有任何一個檔案被開著（包含你用 Excel 開啟的），整個資料夾這次就跳過。
  • 先建立壓縮檔並逐一核對內容清單無誤，才刪除原始檔。中途任何失敗都保持原狀。
  • 每一個動作都寫進 Logs 分頁（DataArchived / DataArchiveSkipped / DataArchiveFailed）。

✅ 已壓縮的資料照樣可以回放。 Recordings 與 Ratio Review 會一併列出 DD.zip 裡的檔案，選取時直接從壓縮檔讀取，不需要先解壓縮。清單上會標示 zip，狀態列也會註明來源檔（例如 (from 23.zip)）。

唯一的差別是讀取時要即時解壓縮，比未壓縮的檔案略慢（實測 30 MB 全譜檔約 0.35 秒），而 Recordings 的日期範圍預設只看最近 7 天 —— 要看更早的資料記得把 From 日期往前調。

磁碟警告（不論壓縮功能是否開啟都會發出）：程式開啟時與關閉時各檢查一次，只有在真的有磁碟問題時才會跳視窗 —— 餘量低於 10%，或資料夾超過容量上限；低於 5% 視為嚴重。單純「沒開啟自動壓縮」不會跳提示（否則每次開關程式都要按一次確定，久了就沒人看了），該狀態在 Configuration 分頁本來就看得到。

8. 日常操作 SOP

8.1 每天開機

  1. 啟動程式 → Sign In。
  2. Monitor → Connect → 確認 Test Mode = False。
  3. 按 Start。
  4. 切到 Leak Monitor，確認：
    • Baseline 下拉選的是今天配方對應的基準線。
    • 狀態橫幅在電漿點著後轉為綠色 OK — within baseline。
    • 沒有 LOW SIGNAL 警示。
  5. 回 Monitor，確認 Recorder 狀態列不是紅色 OFF（見 §6.1.2）。
    • 顯示 ARMED / SAVING → 正常，不必做任何事。
    • 顯示 OFF → 記錄器沒武裝，通知工程師（武裝在 Engineer 權限的 Configuration 分頁，操作員進不去）。這是一次性設定，正常情況下不需要每天按。
    • 出現橘色「not saved」小字 → 同樣通知工程師補按一次 Save，否則下次開機會失效。

8.2 換配方

  1. Leak Monitor → Baseline 下拉切到新配方的基準線。
    • 洩漏率校正會自動跟著切換。
    • 若新配方還沒有基準線 → 跑一段良品製程後 Capture Golden Run。
  2. 按 Reset Run 開新的記錄檔並清空趨勢。

8.3 警報發生時

  1. 記下狀態橫幅的時間與 Leak rate 讀值。
  2. 看哪幾條比值進了 ALARM：
    • O / OH / NO 一起上升 → 典型的空氣洩漏。
    • 只有單一條上升 → 可能是該譜線受干擾，或有其他製程變化。
  3. 到 Ratio Review 回放這段時間，確認是持續上升還是短暫尖峰。
  4. 實體檢查（O-ring、法蘭、視窗、閥件）。
  5. 排除後 → Acknowledge Alarm 清除鎖存。

8.5 演算法驗證：抓基線 → 重播 → 比對轉態時間

權限：Engineer 以上。不需要硬體，也不會動到正在生產的機台。

什麼時候做：改過比值設定、抽取模式、警報門檻或波長校正之後，要回答「這組新設定拿去跑當初那一次真實洩漏，抓不抓得到、以及慢多久」。這是唯一能在不製造洩漏的情況下量化偵測靈敏度與延遲的方法。

準備：兩段來自同一次製程的錄檔

段別要求
基線段全程 Normal、確定沒有洩漏的一段。通常就是當初在機台上錄 Golden Run 的那一段
事件段已知有洩漏、實機當時真的跳過警報的一段

兩段必須是同一次連續電漿、同一組曝光參數，否則基線對事件段不成立。確認方式：

  • Logs 分頁看兩段之間有沒有 Acquisition_Stop 之外的中斷；換過積分時間或平均次數就不算同一次。
  • Ratio Review 把兩段接起來看，接縫處的比值應該是連續的（差幾個 % 以內）。
  • 注意錄檔會輪替：一次採集可能被切成 _0807211351 / _0807212620 / _0807213124 好幾個檔，它們共用同一份 P_Ratio_* 比值檔。用 Logs 裡的 IntensityLogger_FilesChanged 對出每個檔涵蓋的時間。

步驟 1 — 用基線段抓 Golden Run

  1. Replay 分頁 → Choose CSV… → 選基線段。
  2. Monitor 分頁 → Connect → Start（無硬體會進測試模式）。
  3. 回 Replay → Play（這一步用 1×，讓平滑與 SNR 有正常的時間行為）。
  4. 等 Leak Monitor 的各比值 SNR 與讀值平穩後，按 Capture Golden Run，取一個看得出來源的名字，例如 Replay 0807-2109。
  5. 捕捉完成後檢查日誌：出現 GoldenRunCaptured 才算成功。若出現 GoldenRunRatioUnstableBaseline、GoldenRunRatioLowSnr 或 GoldenRunRatioDropped（畫面也會跳警告視窗），代表那條比值的基線被拒絕，先處理再往下（見 §9.5）。若跳的是錯誤視窗／日誌記 GoldenRunEmpty，這次擷取沒有存下任何東西 —— 重播的基線要重抓，而且不要拿實機的舊基準線頂替（§8.5 開頭的提醒）。
  6. 按 Save。

⚠️ 絕對不要拿事件段抓基線。 基線若落在洩漏已經發生的區間，同一份資料之後就會顯得正常，警報延後甚至完全不跳。實測過一次：把基線抓在告警期間，同一份事件檔的 Warning 延後 181 秒、Alarm 延後 212 秒，而原始比值一模一樣 —— 純粹是基線的位置造成的。

步驟 2 — 重播事件段

  1. Replay → Stop（若還在播）→ Choose CSV… → 選事件段。
  2. 勾 Raise leak alarms during replay。沒勾就不會有 LeakMonitorState 進日誌，只有畫面看得到。
  3. 確認 Leak Monitor 用的是步驟 1 存的那個 Golden Run。
  4. Play。趕時間可以用 5× / 20×，時間軸等比例縮放，判斷結果不變。
  5. 讓它播到底（狀態變 FINISHED）。中途按 Stop 的話日誌會寫 stopped by the operator，那一輪的資料不完整、不能拿來比。

步驟 3 — 比對轉態時間

資料有兩個來源，兩個都看：

  • 系統日誌的 LeakMonitorState（From=Normal,To=Warning 這種）。
  • 這一輪寫出的 SIMP_Ratio_*.csv 的 OverallState 欄位（Ratio Review 也可以直接開）。

換算方式：重播的幀時間戳 = 按下 Play 的時刻 + 錄檔中該幀的相對時間。所以只要換算成「距離播放開始幾秒」，就能直接和實機當年「距離該錄檔第一幀幾秒」對齊 —— 不必管日期。

比對項目期望結果
SIMP_Ratio_*.csv 列數等於錄檔幀數（日誌 ReplayStarted 的 Frames= 值）
首次 Warning 的相對秒數與實機同一段相同（差幾幀之內）
首次 Alarm 的相對秒數同上
Idle（電漿瞬斷）出現的位置落在同一幀 —— 這是資料驅動的事件，可以當成對齊是否正確的檢查點
未改動的比值原始值與實機逐幀相同（CSV 只有六位有效數字，差 0.001 % 以內屬正常）

把每次驗證的結果記下來（設定版本、基線名稱、Warning / Alarm 的相對秒數），下次改設定就有得比。可以寫在 Recordings 分頁的 Notes（會存成 CSV 旁的 .notes.txt）。

9. 疑難排解

9.1 按 Connect 後掉進測試模式（明明接了硬體）

最常見原因：原生 DLL 不在 .exe 旁邊。

檢查程式資料夾裡有沒有 UserApplication.dll、SiUSBXp.dll、libsodium.dll。SDK 的 DLL 解析器只會在程式所在目錄找，放到子資料夾沒有用。

其他要檢查的：

  • Configuration 分頁的 Force Test Mode 是不是被勾起來了。
  • USB 線／驅動、裝置管理員裡有沒有看到裝置。
  • 乙太網路機種：0.4.6 已修正預設 device type（改為 Z5，並會自動改試另一種），若仍連不上請確認 IP 設定。

9.2 光譜幀出現斷裂／撕裂

Configuration → Acquire Mode 改成 Oneshot → Apply。常見於 Z5／乙太網路機種在長積分時間下。

同一個設定也是整幀全暗（掉幀）的第一個處理方向 —— 那種狀況日誌會記 SpectrumFrameDropout，見 §9.6。

9.3 峰形變寬、峰位偏移

Configuration → Average Mode 改成 Software → Apply。某些機種的硬體平均器在多次讀取時會錯位。代價是速度變慢約 N 倍（N = Average Count）。

9.4 一直顯示 Low Signal

代表訊號或參考譜線太靠近雜訊底。依序嘗試：

  1. 拉長積分時間（Configuration → Integration Time → Apply）。
  2. 提高 Average Count（配合 Software 平均模式）。
  3. 檢查光纖對位與觀察窗是否髒污。
  4. 該譜線在你的機台上本來就很弱 → 到 Ratio Setup 把它的 Monitoring method 改成 AbsoluteIntensity。 > ⚠️ 但在真實電漿上要謹慎：實測顯示洩漏會讓整個光譜一起變亮，而且洩漏排除之後電漿仍維持較亮，所以絕對強度會回不到基準線、持續假警報（同一時刻 Ar 正規化的比值已經回到 +1%，絕對強度還高著 +7.6%）。AbsoluteIntensity 適合光源穩定的場合；電漿量測請優先用 Ratio 模式，先換一條真的會動的譜線（§1.1）再考慮改模式。
  5. 先到 Recordings 看一眼那個波長到底有沒有峰。若只是一段平滑的連續光，再怎麼調 SNR 都沒有用 —— 把 Extraction 改成 RawMean（見 §6.4.2），或換一條真的存在的譜線。
  6. 最後手段：調低該比值的 Min SNR。不建議設為 0 —— 那等於關掉假警報保護。

9.5 Golden Run 錄完後某條比值沒有基準線

擷取一結束就會跳出警告視窗列出被拒絕的比值與原因，同樣的句子也會寫進系統日誌；下面是各種原因的處理方式。

系統日誌會有 GoldenRunRatioLowSnr 記錄。原因是該比值可評估的幀當中，通過 SNR 下限的不到一半，基準線被主動拒絕了。

若日誌寫的是 GoldenRunRatioDropped，代表該比值一幀都沒被採用。訊息會直接說是哪一種：監控譜線落在光譜儀波長範圍外、電漿閘門全程關閉（檢查記錄器的觸發波長／存檔門檻，見 §10.2）、參考譜線從未出現、或該比值整段擷取都是停用的。

若日誌寫的是 GoldenRunRatioUnstableBaseline，原因不同：基準均值本身不夠遠離 0（例如 −25 ± 95）。這代表該波長沒有峰，扣背景後只剩雜訊 —— 把 Extraction 改成 RawMean 再錄一次。

若日誌寫的是 LeakMonitorBaselineMismatch，基準線是好的，但你之後改了某個讓它失效的設定（參考譜線、監控方式、擷取方式、或升級後積分單位改變）—— 重錄即可。

若是「所有」比值都沒有基準線（跳出的是錯誤視窗、日誌記 GoldenRunEmpty），這次擷取已被整份丟棄 —— 原本使用中的基準線與洩漏率校正都沒有被動到，機台仍在用舊基準線監控。先照上面的原因排除，再重錄一次即可，不必擔心要去把舊基準線救回來。最常見的原因是電漿沒開／記錄器觸發門檻設得太高，讓電漿閘門整段關著（§10.2）。

9.6 日誌出現 SpectrumFrameDropout

代表光譜儀送回了整幀全暗的資料（正常幀最亮處約數萬 counts，全暗幀只有幾十）。這不是製程事件 —— 真正的電漿熄滅會持續超過一秒，而這種掉幀通常只有一到兩幀、約 0.3 秒。

程式的電漿閘門會把這些幀丟掉，所以讀值不會被汙染；記這筆日誌是因為丟得無聲無息，你需要知道儀器有沒有在出這種狀況。實測曾在 13 分鐘內出現 20 幀，其中一幀落在 Golden Run 擷取視窗內就足以讓該比值的基準線被拒絕（σ 變成均值的 2.4 倍）。

處理方式：

  1. 到 Configuration 分頁把 Acquire Mode 從 HardwareAverage 改成 Oneshot → Apply → Save，這是 Z5 / Ethernet 模組出現分段或撕裂幀時的既有解法。
  2. 跑一段一樣長的時間，比較日誌裡 SpectrumFrameDropout 的 FramesThisSession 數字有沒有下降。
  3. 若沒有改善，檢查 USB／網路線材與接頭，並考慮降低積分時間。

處理方式同 §9.4 —— 先把訊號救起來，再重錄。

9.7 進不了 Configuration 分頁

正常行為 —— 該分頁需要 Engineer 以上。點進去會跳出登入視窗，取消就退回原本的分頁。請用 Engineer 或 Admin 帳號登入。

若登入後角色又掉回 Engineer 以下（例如閒置自動鎖定），畫面會自動跳回 Monitor 分頁。

📌 歷史問題（已修正）：舊版用硬編的分頁索引做這道檢查，在插入 Wavelength Calibration 分頁後指到了錯誤的分頁，導致 Configuration 一度完全沒有權限保護。現已改為以分頁名稱（x:Name）比對，插入新分頁不會再讓權限檢查失準。若你手上的版本早於此修正，請升級。

9.8 改了 Ratio Setup 但沒反應

Ratio Setup 與 Wavelength Calibration 的修改是暫存的。按完 Save 之後，必須到 Monitor 分頁 Stop → Start 重啟擷取才會生效。

（Leak Calibration 例外 —— 它存檔後立即生效。）

9.9 沒有產生 Ratio CSV

依序確認：

比值 CSV 不需要記錄器武裝，也不看觸發門檻 —— 只要 OES 在擷取就該有檔案。所以依序確認：

  1. OES 是不是真的在擷取（Monitor 分頁 Status: Acquiring）。沒擷取就不會有任何資料。
  2. settings.json 裡 LeakMonitor.Enabled 與 RatioCsvEnabled 是否都為 true（預設是）。
  3. 看 Logs 分頁有沒有 RatioCsvSkipped（設定被關）或 RatioCsv_Open_Failed（路徑寫不進去，例如磁碟滿或無權限）記錄，裡面會寫原因。
  4. 檔案位置跟強度 CSV 同一個資料夾，但檔名時間戳不同 —— 別拿強度檔的時間去找它。

9.10 測試模式下警報不會跳

這是預期行為（SuppressAlarmsInTestMode 預設為 true）：合成光譜會把系統日誌灌滿沒有意義的警報。要演練警報，在 Replay 分頁勾 Raise leak alarms during replay —— 那正是要檢查警報的場合。

注意這個開關管的是警報轉態有沒有被記錄與latch；Leak Monitor 分頁的狀態不管勾不勾都照算照顯示，SIMP_Ratio_*.csv 的 OverallState 欄也照寫。所以「日誌裡一行 LeakMonitorState 都沒有」不等於「沒偵測到」，先去比值 CSV 看那一欄。

9.11 Guest 關不掉程式

這也是刻意設計 —— 必須先 Sign In（任何非 Guest 角色都可以）才能關閉視窗。X 鈕、Alt+F4、系統選單都會被擋。

9.12 重播的結果和實機當時不一樣

先分清楚是光譜不同還是判讀不同 —— 重播送出的光譜是逐幀原樣的，所以幾乎都是後者。

  1. 打開這一輪的 SIMP_Ratio_*.csv 和實機當時的 P_Ratio_*.csv，比原始比值欄（不是百分比欄）。若相同（差 0.001 % 以內），光譜路徑沒問題，往下看第 2 點；若不同，是比值定義或波長校正被改過。
  2. 比 % of baseline 欄。原始值相同而百分比不同，就是基線不同 —— 檢查目前作用中的 Golden Run 是哪一個、什麼時候抓的、抓的時候在放哪一段。基線抓在洩漏區間是最常見的原因。
  3. 檢查 SIMP_Ratio_*.csv 的列數等不等於錄檔幀數。少了就是那一輪被中途按了 Stop（日誌會寫 stopped by the operator），不能拿來比。
  4. 確認錄檔對得起來：一次採集常被切成好幾個輪替檔，比較的兩段要涵蓋同一段時間。

完整的比對程序見 §8.5。
