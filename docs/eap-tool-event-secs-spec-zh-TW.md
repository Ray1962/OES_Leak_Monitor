# OES Leak Monitor × EAP 製程事件介面規格（SECS，方案 2b）

> **對象：** 廠內 EAP 平台廠商（開發與維運）。
> **目的：** 定義 OES Leak Monitor 怎麼向 EAP 取得主機台 **PM3** 的製程事件：EAP 以 SECS **equipment** 身分提供製程視窗的狀態變數，並以 S6F11 轉發主機台事件；OES 以 **host** 身分連入讀取。
> **狀態：** 2026-10-28（第二版）。OES 端已依本規格實作。**本規格取代 2026-10-26 的 TCP 文字行規格（`eap-tool-event-tcp-spec-zh-TW`）**，拿到舊版的請改依本規格。
>
> **本版與 2026-10-27 版的差異**（EAP 端原本的實作不需要修改；以下都是放寬或新增的建議）：
>
> 1. **S4 與連線狀態 CEID 改為選填**（§4、§4.1、§4.2、Q5）。平台無法得知自己與主機台的連線狀態時，這兩項不必提供，OES 照樣連線；代價寫在 §4.2。
> 2. **只連線測試**（§4、§10 第 0 項）。識別碼還沒指定時，OES 只填 EAP 的位址、port、Device ID 就能先連線，只送 S1F13、S1F17、S1F1，用來先驗證網路與防火牆。
> 3. **約定名稱**（新增 §4.3、Q7、Q8、§9、§10 第 0a 項）。建議平台支援 S1F11／S1F23，並把 SVNAME／CENAME 設成 §4.3 的名稱，OES 就能自動帶出 9 個識別碼、核對有沒有填錯。不支援時照原本方式提供編號即可。
> **一句話：** OES 主動連到 EAP（預設 `10.2.3.120:20347`），上線後啟用兩個 CEID、讀 S1～S7，之後每 30 秒再讀一次；主機台每有一筆事件，EAP 就以**一個固定的轉發 CEID** 送 S6F11，報告內容固定為「主機台 CEID、EAP 收到的時間、序號」。

## 1. 背景

OES Leak Monitor 裝在主機台 PM3 上，用電漿光譜偵測腔體漏氣。PM3 會交替執行不同製程（Chamber Process／precoat、Chamber Clean 等），每種製程的光譜完全不同。OES 必須知道**當下這一幀光譜屬於哪個製程**，才能用正確的基準判定。

主機台的製程事件已經送到 EAP。OES 原有的 SECS 連線是給 FDC 用的，一條 HSMS-SS 連線只能有一個 host，所以 EAP 不能從那條連線送事件進來。因此 OES 另開一條 SECS 連線，**以 host 身分連到 EAP**。

這條連線**只傳遞資訊**：OES 只會讀狀態、啟用事件，不會對 EAP 或主機台下任何命令。

## 2. 系統配置與角色

```
┌──────────────┐  SECS（既有）  ┌──────────────────────────┐
│   Tool PC    │──────────────▶│            EAP           │
│  (PM2／PM3)  │   EAP = host  │ equipment，監聽 20347     │
└──────────────┘               └────────────▲─────────────┘
                                            │ SECS（本規格）
                                            │ OES = host，主動連入
┌──────────────┐  SECS（既有）  ┌────────────┴─────────────┐
│     FDC      │──────────────▶│          OES PC          │
│              │   FDC = host  │       （只看 PM3）        │
└──────────────┘               └──────────────────────────┘
```

| 連線 | host | equipment | 用途 |
|---|---|---|---|
| Tool PC ↔ EAP | EAP | Tool PC | 既有，不變 |
| FDC → OES | FDC | OES | 既有，不變。FDC 讀 OES 的洩漏狀態；OES 目前依據的製程視窗也由 OES 的 VID 030～032 提供給 FDC |
| **OES → EAP** | **OES** | **EAP** | **本規格** |

**這條連線上 OES 會送的訊息：** S1F13、S1F17、S1F1、S2F37、S1F3，以及 S6F12（回覆事件）。**不會送** S2F33／S2F35（報告由平台固定）、S2F31（不改 EAP 的時鐘）、S2F41、S2F15 或任何控制訊息。

## 3. 連線參數

| 項目 | 值 | 說明 |
|---|---|---|
| 協定 | HSMS-SS | |
| 連線模式 | **EAP = Passive（監聽）、OES = Active（主動連入）** | |
| EAP 的位址 | 預設 `10.2.3.120:20347`（EAP 方提供） | 在 OES 的 **EAP 分頁**輸入，存檔即生效。EAP 切換到不同 IP 的備援機時，由設備工程師改填 |
| Device ID | 預設 0 | 同上 |
| T3／T5／T6／T7／T8 | 45／10／10／10／10 秒 | OES 端固定 |
| 時鐘 | **雙方各自接 NTP** | OES 不送 S2F31 |
| 時間格式 | `YYYYMMDDhhmmsscc`（16 位，本地時間） | 也接受 14 位 |

連上後 OES 讀 S1F2 的 MDLN／SOFTREV 並記入日誌，不做比對。

## 4. EAP 需要提供的識別碼與資料

下表的 S1～S7、兩個 CEID 共 **9 個識別碼由 EAP 方指定**，在 OES 的 EAP 分頁輸入（預設為 0，代表未設定）。其中 **S4 與連線狀態 CEID 是選填**：平台做不到時填 0，OES 照樣連線（見 Q5）。其餘 7 個都要填，而且 S1～S7 不可重複，OES 才會正式運作。**7 個必填的全部是 0 時，OES 只做連線測試**：連上、S1F17、S1F1，不送 S2F37、不讀 S1F3、不影響製程視窗，EAP 分頁顯示 EAP 回的型號與版本。這讓現場在 EAP 指定識別碼之前，就能先驗證位址、port、Device ID 與防火牆（見 §10 第 0 項）。只填了一部分則不會連線，並列出缺哪幾個。

### 4.1 SVID（供 OES 以 S1F3 讀取）

| 代號 | 名稱 | 格式 | 內容 |
|---|---|---|---|
| S1 | PM3 視窗狀態 | U1 | **0** = 不在任何視窗內、**1** = 在視窗內、**2** = 不明（EAP 不知道 PM3 目前狀態） |
| S2 | 目前視窗的 Start CEID | U4 | S1 = 1 時為開啟這個視窗的**主機台原始 CEID**；其他情況為 0 |
| S3 | 目前視窗的開始時間 | A[16] | S1 = 1 時為 EAP 收到該 Start 的時間；其他情況為空字串 |
| S4 | EAP 與主機台的通訊狀態（**選填**） | U1 | **0** = 未通訊、**1** = 通訊中。平台不提供時，OES 的 S1F3 只讀 S1～S3、S5～S7 |
| S5 | 最後一筆轉發事件的主機台 CEID | U4 | 尚無事件時為 0 |
| S6 | 最後一筆事件的時間 | A[16] | EAP 收到該事件的時間；尚無事件時為空字串 |
| S7 | 序號 | U4 | 每轉發一筆事件加 1，EAP 重啟後從 0 開始 |

**S1 一定要有「2 = 不明」。** EAP 不知道時回報 0，OES 會以為 PM3 閒置，這是錯的；回報 2，OES 就改用不依賴製程事件的判定方式。

### 4.2 CEID 與固定報告（EAP → OES，S6F11）

| 代號 | 名稱 | 觸發時機 | 報告（**由平台固定，只有一份**） |
|---|---|---|---|
| 轉發 CEID | PM3 事件轉發 | EAP 收到主機台的任何事件時 | `L{ U4 主機台原始CEID, A[16] EAP收到的時間, U4 序號 }`，也就是 S5、S6、S7 |
| 連線狀態 CEID（**選填**） | 主機台通訊狀態改變 | S4 改變時 | `L{ U1 S4 }`。平台不提供時，OES 的 S2F37 只啟用轉發 CEID |

- **只用一個轉發 CEID 送所有主機台事件**，原始 CEID 放在報告第一個值。主機台新增事件時，只要改 OES 的 CEID 對照表，EAP 不用改。
- 報告內容**依位置讀取**，順序與格式必須和上表完全一致。OES 收到不符的報告（數量、順序或型別不對）會記錄並捨棄該筆事件，靠下一次 S1F3 補回視窗。報告格式之後若要變更，請事先通知。
- 時間值是 **EAP 收到事件的時間**：主機台的事件報告不帶時間戳（2026-10-26 確認）。請一律填上，不要留空。
- **S4 與連線狀態 CEID 不提供時**，OES 就看不到 EAP 與主機台之間的連線本身，只能從 **S1 = 2** 得知 EAP 不知道 PM3 的狀態（所以 E4、E5 的「S1 改為 2」更重要），或等 OES 端的視窗上限（600 秒）到期。只缺 S4 時，連線狀態改變只靠事件得知，漏掉的事件不會被 30 秒一次的 S1F3 補回；只缺連線狀態 CEID 時，改變要到下一次 S1F3 才會被發現。OES 會在系統日誌記一筆 `EapToolLinkNotMonitored`，EAP 分頁也會以橘字標示。

### 4.3 約定名稱（建議，供 OES 自動帶出識別碼）

平台若支援 S1F11（Status Variable Namelist）與 S1F23（Collection Event Namelist），請把 SVNAME／CENAME 設成下表。OES 連上後會查詢這兩份清單，依名稱帶出 9 個識別碼供工程師確認，不必手抄編號，也能核對已輸入的編號有沒有填反（S1 與 S4 都是 U1、值都是 0／1，只看格式分不出來）。

| 識別碼 | SVNAME／CENAME |
|---|---|
| S1 | `PM3_WINDOW_STATE` |
| S2 | `PM3_WINDOW_CEID` |
| S3 | `PM3_WINDOW_START` |
| S4 | `PM3_TOOL_LINK` |
| S5 | `PM3_LAST_CEID` |
| S6 | `PM3_LAST_TIME` |
| S7 | `PM3_EVENT_SEQ` |
| 轉發 CEID | `PM3_EVENT_FORWARD` |
| 連線狀態 CEID | `PM3_TOOL_LINK_CHANGED` |

- OES 依名稱**完全比對**（去掉前後空白、不分大小寫），不做模糊比對。找不到或有兩個以上同名的，該項不帶出並說明原因；S4、連線狀態 CEID 找不到時視為「不提供」。
- 帶出的編號只填進 OES EAP 分頁的欄位，**仍要工程師按 Save 才生效**，OES 不會自動存檔。
- 這一節是建議，不是連線的前提（見 Q7、Q8）。平台不支援或名稱不同時，照原本的方式由 EAP 方提供編號、在 OES 輸入即可。

本規格所說的「PM3 製程事件」至少包括：

| 主機台 CEID（Start／End） | 事件 |
|---|---|
| 3100439529／3100439530 | PM3 ProcessStart／End（Chamber Process／precoat） |
| 3099591660／3099591661 | PM3 ProcessStart／End（Chamber Clean） |
| 3100167145／3100167146 | PM3 ProcessStart／End（Auto Leak check） |

## 5. 訊息流程

### 5.1 連線後的初始化（每次連上都完整執行，包括斷線重連）

| 步驟 | 方向 | 訊息 | 目的 |
|---|---|---|---|
| 1 | OES ↔ EAP | S1F13 → S1F14 | 建立通訊。雙方都可以先送 |
| 2 | OES → EAP | S1F17 → S1F18 | 要求 ON-LINE。ONLACK 0 或 2 都可以 |
| 3 | OES → EAP | S1F1 → S1F2 | 確認對方身分（只記日誌） |
| 4 | OES → EAP | S2F37 → S2F38 | 啟用轉發 CEID 與連線狀態 CEID。**ERACK 必須為 0** |
| 5 | OES → EAP | S1F3 → S1F4 | 讀 S1～S7，取得目前視窗，**補上斷線期間錯過的狀態** |

步驟 4 先於步驟 5：先啟用事件再讀狀態，兩者之間發生的事件才不會漏掉。

### 5.2 平常運作

| 方向 | 訊息 | 時機 |
|---|---|---|
| EAP → OES | S6F11 → S6F12 | 主機台的每一筆事件；主機台通訊狀態改變時 |
| OES → EAP | S1F3 → S1F4 | **每 30 秒**讀一次 S1～S7。連線狀態事件的值是 1（恢復）時，OES 會立刻再讀一次 |

### 5.3 訊息範例

OES 讀取目前視窗（以 S1～S7 = 6001～6007 為例）：

```
S1F3 W
<L[7] <U4 6001> <U4 6002> <U4 6003> <U4 6004> <U4 6005> <U4 6006> <U4 6007>>

S1F4
<L[7]
  <U1 1>                        S1 在視窗內
  <U4 3100439529>               S2 Chamber Process Start
  <A[16] "2026102714014000">    S3
  <U1 1>                        S4 主機台通訊中
  <U4 3100439529>               S5
  <A[16] "2026102714014000">    S6
  <U4 128>                      S7
>
```

EAP 轉發 PM3 ProcessEnd（轉發 CEID 以 6100、RPTID 以 6200 為例）：

```
S6F11 W
<L[3]
  <U4 DATAID>
  <U4 6100>
  <L[1]
    <L[2]
      <U4 6200>
      <L[3] <U4 3100439530> <A[16] "2026102714024300"> <U4 129>>
    >
  >
>
```

## 6. EAP 端的行為要求

| # | 要求 | 原因 |
|---|---|---|
| E1 | **主機台事件發生後 1 秒內送出 S6F11** | OES 每一幀光譜（約每 0.6～2 秒一幀）都要依視窗判定製程，短的製程步驟只有約 60 秒 |
| E2 | **事件依發生順序送出** | Start 和 End 的順序錯了，視窗就是錯的 |
| E3 | **先更新 S1～S7，再送 S6F11** | 報告的值在送出當下讀取；OES 也用之後的 S1F3 修正視窗，兩者必須一致 |
| E4 | **EAP 不知道 PM3 狀態時，S1 填 2**：EAP 剛啟動、尚未收到任何 PM3 製程事件，或與主機台斷線、恢復後尚未收到新的製程事件時 | 不知道時填 0，OES 會以為 PM3 閒置 |
| E5 | 與主機台斷線時，S4 改為 0、S1 改為 2，並立即送連線狀態 CEID | 讓 OES 立刻改用不依賴製程事件的判定方式 |
| E6 | 重送同一筆事件時使用相同的序號 | OES 用序號判斷重送，避免同一筆處理兩次 |
| E7 | 時間值填 **EAP 收到主機台事件的時間** | 主機台的報告不帶時間戳 |
| E8 | 不需要支援 S2F33／S2F35（報告由平台固定） | OES 不會送 |
| E9 | **不需要 spooling**：OES 斷線期間的事件可以丟棄 | OES 重連後會用 S1F3 重新同步 |
| E10 | 同時只接受**一個** OES host 連線；同一台 OES 重連時，以新連線取代舊連線 | HSMS-SS 本來就只有一個 host；舊連線可能還沒釋放 |

**可以這樣做：** 主機台的事件**可以不篩選、全部轉發**（PM2 的也可以），OES 不認得的 CEID 只記錄、不處理。Start 之後又收到 Start，或收到沒有對應 Start 的 End，照實轉發即可，由 OES 處理並記錄警告。

## 7. OES 端的行為（供參考）

EAP 方不需要實作本節，但了解它有助於判讀雙方的日誌。

- **CEID 怎麼變成製程：** OES 用自己的對照表把主機台 CEID 換算成製程類別（例如 3100439529 → 製程 A），Start 到 End 之間的光譜都依該製程的基準判定。
- **S1F3 讀到的視窗和 OES 自己記的不同時，以讀到的為準**，並記一筆警告（這就是「EAP 漏送事件」的紀錄）。S1 = 1 時，S2 依 OES 對照表解讀：

| S2 在 OES 對照表裡是 | OES 的視窗 |
|---|---|
| 有製程類別的 Start | 該製程的視窗 |
| 只記錄、不分類的 Start，或對照表沒有的 CEID | 不在任何視窗內 |
| End 事件 | 內容矛盾：記警告，視窗不變 |

- **資料不可信時，OES 不會停止偵測：** S1 = 2、S4 = 0、收到值為 0 的連線狀態事件，或 **75 秒內沒有任何一次成功的 S1F3、也沒收到事件** 時，OES 把製程視窗改為「不明」，改用光譜本身判斷，等狀態恢復再切回來。
- **連線斷掉本身不改變視窗**。OES 會自動重連，連上後依 5.1 重新讀取；只要 75 秒內恢復，視窗一直維持正確。
- **序號：** 同一序號只處理一次；跳號會記錄「有事件沒送到」；序號變小代表 EAP 重啟。OES 重啟後第一次讀到的 S7 不會讓接著重送的那筆被當成重複。
- **OES 不會因為這條連線斷掉而發出漏氣警報。** 連線狀態顯示在 OES 的 EAP 分頁上，收發的每一則訊息記在 OES 的 `eap_YYYYMMDD.log`。

| Q7 | 平台是否支援 S1F11／S1F12（狀態變數名稱清單）與 S1F23／S1F24（事件名稱清單）？ | **建議，待廠商確認；不是連線的前提。** 不支援時，OES 分頁寫明「EAP does not support name queries」，改由人工輸入編號 |

## 9. 自測工具

**`Test_SECS`**（OES 方提供的 SECS 測試程式，Windows，不需安裝 OES）內建兩個設定檔：

- **OES (2b host)**：角色選 **Host (active)**，連到 EAP 平台後依序按「1. Establish and go online」「2. Enable the EAP events」「3. Read S1–S7」，就是 OES 上線時的同一套步驟；「4. Read SV names」「5. Read event names」送 S1F11／S1F23，逐一寫出 4.3 的約定名稱落在哪個編號（找不到、重複或與目前編號不同時會標出）。日誌的 `[OES]` 行寫出 S1～S7 的值與意思；收到的每筆 S6F11 依 4.2 的格式解讀，寫在 `[EAP]` 行，格式不符會寫 `REJECTED` 並說明原因。
- **EAP (PM3 event forwarder)**：角色選 **Equipment simulator (passive)**，假扮 EAP，提供本規格的 S1～S7 與兩個 CEID，可以按鈕送各種事件。供 OES 方測試，也可以給 EAP 廠商當參考實作。

兩個設定檔的預設編號是 S1～S7 = 6001～6007、轉發 CEID = 6100、連線狀態 CEID = 6101、RPTID = 6200／6201。平台的編號不同時，在 `Test_SECS.exe` 旁放一份 `eap-ids.json`（欄位見 `Test_SECS` 的整合指南），沒寫的欄位維持預設。

## 10. 驗收方式

| # | 操作 | 預期結果 |
|---|---|---|
| 0 | 只連線（識別碼尚未指定）：OES 只填 EAP 的位址、port、Device ID，識別碼全部留 0 | OES 連上、送 S1F17 與 S1F1；EAP 分頁顯示橘色 `connected to … — <EAP 的型號 版本> … link test only`；EAP 日誌沒有 S2F37、S1F3 |
| 0a | 依名稱帶出識別碼（平台支援 Q7、Q8 時）：接續第 0 項 | OES 自動送 S1F11、S1F23，EAP 分頁表格 9 項都是 ✓；按「Use these ids」填入、Save & apply 後進入第 1 項。EAP 日誌沒有 S2F37 |
| 1 | OES 啟用連線 | 5.1 的步驟全部成功；OES EAP 分頁顯示綠色 `connected` |
| 2 | PM3 閒置時觀察 | OES 每 30 秒讀一次 S1～S7：S1 = 0、S4 = 1（不提供 S4 時，OES 讀 S1～S3、S5～S7，EAP 分頁顯示 `tool link not monitored`） |
| 3 | 主機台跑一次 PM3 Chamber Process | Start／End 各一筆 S6F11，1 秒內送出，報告為主機台 CEID、時間、序號；期間 S1 = 1、S2 = 3100439529；OES 顯示製程 A 視窗 |
| 4 | 主機台跑一次 PM3 Chamber Clean | 同上，S2 = 3099591660，OES 顯示製程 B 視窗 |
| 5 | 轉發一筆不在 OES 對照表內的 CEID（例如 slit door） | OES 記錄、不處理；視窗不變 |
| 6 | PM3 製程進行中，重啟 OES | OES 重新連上，讀 S1～S7 後立刻恢復到正確的製程視窗，不必等下一筆事件 |
| 7 | PM3 製程進行中，拔掉 OES 的網路線 90 秒後接回 | OES 在 75 秒時改為「不明」；接回後自動重連並恢復正確視窗 |
| 8 | 中斷 EAP 與主機台的連線 | EAP 送連線狀態 CEID（值 0），S1 = 2、S4 = 0；OES 改為「不明」。不提供 S4／連線狀態 CEID 時，只驗 S1 = 2，OES 在下一次 S1F3 改為「不明」 |
| 9 | 恢復 EAP 與主機台的連線 | 連線狀態 CEID（值 1，有提供時）；S1 在下一筆 PM3 製程事件後恢復正確值 |
| 10 | 重啟 EAP | OES 自動重連；S7 = 0、S1 = 2，第一筆事件的序號為 1，OES 正常接受 |
| 11 | 檢查 EAP 日誌 | OES 沒有送過 S2F33、S2F35、S2F31、S2F41、S2F15 |
