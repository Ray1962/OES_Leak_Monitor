  • DV=400 時 OH 讀值掉到飽和線以下，比值因此下降。這可能是漏氣改變了電漿，但在飽和的條件下無法確定。

    • 5 Torr 造成的電漿條件改變；
    • 腔體內原本就有大量 N/O，例如背景漏氣或污染。

單憑這批資料分辨不出是哪一種，需要在現場確認。

Golden Run 的名稱沿用「Recipe 3 NO-OH」，所以直接覆蓋了 11/19 用 Baseline Builder 從 DV=0 錄檔建立、並用 Replay 驗證過的那份。

新的這份有三個問題：

  • 在 DV=200 的錄檔中擷取；
  • 擷取時分子是飽和的；
  • 積分時間是 40 ms。

所以不能拿來當正常基準。

6. App 版本

今天的 config snapshot 裡沒有 goldenRunJudging、stepJudging 等欄位，表示實驗機執行的是 step judging（PR #98）之前的舊版。滾動基準判定、Line preview 和像素數警告都沒有在運作。

7. 下次測試建議

  1. 先排除飽和。 用新版 App 的 Line preview 確認 NO 236 和 OH 309 的峰頂明顯低於約 60,000 counts，再開始測試。必要時降低積分時間，或改回 21 Torr 的條件。
  2. 測試中不要改積分時間。 要改就停止再重新開始，並重新建立基準。
  3. Golden Run 要在 DV=0、條件穩定之後擷取，或用 Baseline Builder 從 DV=0 的錄檔建立。另外取一個新名稱，避免覆寫 11/19 的版本。
  4. 改用今天發布的新版 App，並依 11/19 的建議開啟 step judging：
    • NO/Ar：+10% / +15%；
    • OH/Ar：+2% / +3%；
    • 關閉 Golden Run 判定，並開啟 RequireTwoForAlarm。
  5. 確認 NO/OH 為什麼異常地亮。 先在 DV=0 下比較 5 Torr 和 21 Torr 的光譜，排除背景漏氣或污染。
