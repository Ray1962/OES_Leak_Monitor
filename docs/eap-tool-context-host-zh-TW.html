OES Leak Monitor 向 EAP 取得 PM3 製程視窗：介面需求（方案 2b）

對象： 廠內 EAP 平台廠商（開發與維運）。 目的： 說明 OES Leak Monitor 需要 EAP 提供哪些資料、用什麼 SECS 訊息取得，請廠商評估平台能否支援，並回覆第 9 節的問題。 狀態： 草案（2026-10-26）。Q1～Q3 已確認（平台能以 equipment 身分讓 OES 連入；能提供由平台程式維護的自訂 SVID；事件報告內容固定，由平台定義），Q4～Q9 待回覆。OES 端尚未實作本方案，文中 SVID／CEID 編號由 EAP 方指定後回填。 一句話： EAP 以 equipment（被動端） 身分讓 OES 連入；OES 以 host 身分讀取 PM3 目前的製程視窗、訂閱 PM3 的 Start／End 事件。全程唯讀，OES 不對 EAP 或主機台下任何命令。

1. 背景

OES Leak Monitor 裝在主機台 PM3 上，以電漿光譜偵測腔體漏氣。PM3 會交替執行不同製程，例如 Chamber Process／precoat（製程 A）與 Chamber Clean（製程 B）。各製程的光譜完全不同，OES 必須知道當下這一幀光譜屬於哪個製程，才能用正確的基準判定。

主機台本身最清楚目前在跑哪個製程，而它的製程事件已經送到 EAP 了。所以 OES 要向 EAP 取得這些事件。

為什麼不是 EAP 直接把事件送進 OES 既有的 SECS 連線： OES 現有的 SECS 連線（HSMS-SS，單一 session）的 host 是 FDC，FDC 用它讀取 OES 的狀態。一條 HSMS-SS 連線同時只能有一個 host，EAP 沒有辦法再連進來。因此 OES 另外開一條連線，連到 EAP。

4. EAP 需要提供的資料

以下編號欄的 S1～S7、D1～D4、E1～E2 是本文件內的代號，實際 SVID／DVID／CEID 由 EAP 方指定後回填。

4.1 SVID（供 OES 以 S1F3 讀取）

代號實際 SVID名稱格式內容
S1（待填）PM3 視窗狀態U10 = 不在任何視窗內、1 = 在視窗內、2 = 不明（EAP 不知道 PM3 目前狀態，例如 EAP 剛重啟、與主機台斷線）
S2（待填）目前視窗的 Start CEIDU4S1 = 1 時，為開啟這個視窗的主機台原始 CEID（例如 3100439529）；其他情況為 0
S3（待填）目前視窗的開始時間A[16]S1 = 1 時，為主機台送出該 Start 的時間；其他情況為空字串
S4（待填）EAP 與主機台的通訊狀態U10 = 未通訊、1 = 通訊中（S1F13 已完成）
S5（待填）最後一筆 PM3 事件的 CEIDU4主機台原始 CEID；尚無事件時為 0
S6（待填）最後一筆 PM3 事件的時間A[16]尚無事件時為空字串
S7（待填）事件序號U4每轉發一筆 PM3 事件加 1，EAP 重啟後從 0 開始。OES 用它判斷有沒有漏收事件

S1 一定要有「2 = 不明」這個值。 EAP 不知道的時候，回報「0 = 不在視窗內」會讓 OES 以為 PM3 閒置，這是錯的；回報「2」，OES 就會改用不依賴製程事件的方式判定（見第 7 節）。

至少需要以下 PM3 事件（來源：EAP ceid-events.md）：

可以不篩選、整台主機台的事件全部轉發。 OES 不認得的 CEID 會記錄後忽略，EAP 不需要另外維護過濾清單。

不另設 DVID 也可以： 報告可以直接放 SVID。EAP 只要在送出 S6F11 之前先更新 S4～S7，報告就改成 E1 → S5、S6、S7，E2 → S4，內容和 D1～D4 相同。

報告由平台固定定義（Q3）。 請平台依上表的內容定義 E1、E2 的報告，並把以下資訊交給 OES 方，填入 OES 的設定：

  • 每個 CEID 對應的 RPTID。
  • 報告內每個項目的順序與 SECS 格式（例如「第 1 項 U4 主機台 CEID、第 2 項 A[16] 時間、第 3 項 U4 序號」）。OES 依位置讀取報告，不靠 VID 名稱。
  • 報告的順序或格式之後若要變更，請事先通知 OES 方。OES 讀到與設定不符的報告時會記錄警告並捨棄該筆事件，然後靠 5.2 的定期 S1F3 補回視窗狀態，但在下一次 S1F3 之前，視窗可能是錯的。

5. 訊息流程

5.1 連線後的初始化（每次連上都完整執行，包括斷線重連）

步驟方向訊息目的
1OES → EAPS1F13 → S1F14建立通訊。雙方都可以先送 S1F13
2OES → EAPS1F1 → S1F2確認對方身分（MDLN／SOFTREV 由 EAP 方決定，請在 Q7 告知）
3OES → EAPS1F17 → S1F18要求 ON-LINE。ONLACK 0（接受）或 2（已在線上）都可以
4OES → EAPS2F37 → S2F38啟用 E1 的各 CEID 與 E2（報告由平台固定定義，見 4.3 節）
5OES → EAPS1F3 → S1F4讀 S1～S7，取得目前視窗，補上斷線期間錯過的狀態

步驟 4 先於步驟 5：先啟用事件再讀狀態，兩者之間發生的事件才不會漏掉。如果平台的事件一律啟用、不支援 S2F37，請在 Q3a 告知，OES 會略過步驟 4。

6. 行為要求

#要求原因
R1S6F11 要在 EAP 收到主機台事件後 1 秒內送出OES 每一幀光譜（約每 0.6～2 秒一幀）都要依視窗判定製程。一個製程步驟短的只有約 60 秒，延遲越久，被判錯的幀越多
R2D2／S3／S6 的時間以主機台的事件時間為準EAP 轉發時有延遲，OES 的紀錄才能對到主機台實際發生的時刻
R3EAP 與主機台斷線時： S4 改為 0、送 E2，並把 S1 改為 2（不明）斷線期間 EAP 的視窗資料已經過時，不能再當真
R4EAP 重啟後： S1 = 2，直到收到 PM3 的第一筆 Start 或 End，或 EAP 能向主機台查詢到 PM3 目前狀態（Q6）重啟前的狀態不可信
R5Start 之後又收到 Start（中間沒有 End）時，照實轉發，S1～S3 改為新的 Start由 OES 判斷如何處理，並記錄警告
R6收到 End 但目前沒有對應的 Start 時，照實轉發，S1 改為 0同上
R7不需要 spooling。 OES 斷線期間的事件可以丟棄OES 重連後會用 S1F3 重新同步（5.1 步驟 5），不會要求 S2F43
R8同時只接受一個 OES host 連線一條 HSMS-SS 連線本來就只能有一個 host
R9S7／D3 的序號要單調遞增，只有 EAP 重啟時歸零（此時 S1 = 2）OES 用序號跳號判斷是否漏收事件

7. OES 端的行為（供參考）

EAP 方不需要實作本節，但了解它有助於判讀雙方的日誌。

  • OES 怎麼用這些資料： OES 用自己的對照表把主機台 CEID 換算成製程類別（例如 3100439529 → 製程 A），在 Start 到 End 之間的光譜都依該製程的基準判定。對照表只存在 OES，EAP 只要轉發原始 CEID。
  • 資料不可信時，OES 退回「不依賴製程事件」的判定方式（fail-open）： 與 EAP 斷線、S1 = 2、S4 = 0 時，OES 不會停止偵測漏氣，而是改用光譜本身判斷，等狀態恢復再切回來。
  • OES 不會因為這條連線斷掉而發出漏氣警報。 連線狀態會顯示在 OES 畫面上，並寫入 OES 的系統日誌。
  • OES 對 FDC 的介面不變。 FDC 照舊讀 OES 的洩漏狀態；OES 目前依據的製程視窗也照舊由 VID 030～032 提供給 FDC（Satellite_SECS_Specification_v2.md）。

8. 驗收方式

#操作預期結果
1OES 連入 EAP5.1 的步驟 1～5 全部成功；OES 畫面顯示「已連線」
2PM3 閒置時，OES 讀 S1～S7S1 = 0、S2 = 0、S3 = 空字串、S4 = 1
3主機台跑一次 PM3 Chamber ProcessStart 與 End 各收到一筆 S6F11，延遲 ≤ 1 秒；製程進行中讀 S1 = 1、S2 = 3100439529；結束後 S1 = 0；S7 每筆加 1
4主機台跑一次 PM3 Chamber Clean同上，S2 = 3099591660
5PM3 製程進行中，中斷 OES 與 EAP 的連線，30 秒後恢復OES 重連後以 S1F3 補回目前視窗（S1 = 1），不需要等到下一個 Start
6PM3 製程進行中，中斷 EAP 與主機台的連線收到 E2（D4 = 0）；之後讀 S1 = 2、S4 = 0
7恢復 EAP 與主機台的連線收到 E2（D4 = 1）；S1 在下一筆 PM3 事件後（或依 Q6 的方式）恢復正確值
8重啟 EAPOES 自動重連；S1 = 2、S7 = 0，直到第一筆 PM3 事件
9檢查 EAP 日誌OES 沒有送過 S2F41、S2F31、S2F15 或任何控制訊息

10. 若平台無法扮演 equipment

如果 Q1 的答案是否定的，替代做法是角色反過來：OES 另開第二個 port 當 equipment，EAP 以 host 身分連入，把 PM3 事件用 S2F41 TOOL_EVENT 推送給 OES。訊息格式已經定義在 Satellite_SECS_Specification_v2.md §7，OES 端也已實作接收邏輯，只需要再加開第二個 port。

兩種方案的差別：

本方案（2b）替代方案（2a）

OES 重啟後補回目前視窗OES 自己用 S1F3 讀取EAP 要另外實作「重送目前視窗的 Start」
OES 能否得知 EAP 與主機台斷線能（S4、E2）不能
EAP 端的工作提供 SVID、DVID、CEID 與報告轉發 S2F41
