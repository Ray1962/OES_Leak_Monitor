# OES Leak Monitor 名詞定義（中譯）

以比值法（actinometry）偵測單一電漿腔體漏氣的工具：它看腔體自身發光中的譜線，拿來和一份無洩漏時錄下的
Golden Run 比對，再把結果報給操作員和廠務主機。

> **這份是 repo 根目錄 `CONTEXT.md` 的中譯，供現場工程師閱讀。**
> 定義以 `CONTEXT.md` 為準；兩邊有出入時，是這份翻譯過期了。
> 詞條本身一律保留英文，因為那就是畫面、日誌與 CSV 欄位上出現的字。
> 給操作員的中英對照（OES、SNR、積分時間等一般名詞）在操作手冊末尾的「名詞對照」，那份不重複收錄於此。

這裡只收「望文生義會弄錯」的詞——不是這個專案把它用得比一般更窄，就是這個 repo 裡有兩個東西共用同一個字。

## 洩漏偵測

**Ratio（比值項）**：
被監看的清單裡的一筆設定——一條 signal line、它的萃取方式、它的門檻，以及（只有在真的做除法時）一條
reference line。這個名字講的是常見情況而不是保證：設成絕對強度的項目不做任何除法，它的 reference line
完全不參與判讀。

**Monitored value（受監看值）**：
一筆 ratio 從每一幀算出來的那一個數字，也是所有判斷真正拿來比的東西。它的意義取決於該項的模式，所以凡是
談單位、談 pedestal、談「這兩個數能不能比」，講的都是它。

**Signal line / Reference line（訊號譜線／參考譜線）**：
一筆 ratio 裡面，被問的那條譜線，和拿來除它的那條。reference line 的作用是抵銷電漿條件的漂移；不做除法的
項目沒有這條線。

**Golden Run（基準錄製）**：
一份具名、已存檔的紀錄，記下無洩漏時每一筆 ratio 各讀到多少，錄製一段時間窗，並連同當時的條件一起保存。
今天的讀數是相對於它才有意義的——這個工具本身沒有絕對刻度。它描述的是**一個**穩定操作點，而且同時只有一份
生效；一個有多個操作點的配方需要多份，並且要人工切換。見 `docs/adr/0001`。

**Recipe / run / step（配方／執行／製程步）**：
配方是具名的製程程式；一次 run 是它執行一次；一個 step 是 run 裡設定值固定的一段。Golden Run 以配方命名，
但它描述的只是其中一個 step。

**Steady segment（穩定段）**：
一個 step 裡操作點真的穩住的那部分——**唯一能拿來當基準的東西**。緩啟動的前幾秒屬於那個 step，但不屬於它的
穩定段；這就是為什麼這一段有時必須事後從錄下來的曲線上挑，而不是站在機台前等一分鐘。

**Baseline build（離線建基準）**：
用已經存在硬碟上的錄製檔產生 Golden Run，而不是用現場的即時訊框。它的存在是為了現場擷取搆不到的那些
run：先爬升才穩定的，以及單獨一次不夠長、要好幾次合起來才湊得出一份基準的。

**Golden Run baseline（基準值）**：
某一筆 ratio 在一份 Golden Run 裡分到的那份——它的平均值與散佈。有可能其他項都有、就這一項沒有，這時該項
是「無法判讀」，而不是「正常」。它同時被當成兩個東西用：讀數要拿來比對的**參考點**，以及所有百分比、門檻
倍率、洩漏率擬合要拿來除的**除數**。只有後者需要平均值明顯離零——所以一條行為完全正確的譜線，也可能被拒
絕給基準值。

**Absent-line baseline（零基線）**：
一種 Golden Run baseline：它在無洩漏時的值就是雜訊水準，因為被監看的元素在沒有漏氣時根本不在腔體裡。這是
這個工具的**正常狀態**，不是擷取失敗——要偵測的是那條譜線的「出現」，而不是它的「變化」。這種量不能用
「佔自身平均值的百分之幾」來判讀，它屬於 σ 單位。

**Reactant-gas regime（反應氣體態）**：
製程刻意通入被監看元素的配方。這時譜線在沒有漏氣的情況下也會存在，所以它的存在不構成漏氣的證據；漏氣只會
表現成一個大訊號上的小增量。

**Plasma gate（電漿閘）**：
判斷這一幀值不值得拿來判讀的測試，講法是「記錄器現在會不會存這一幀」。它刻意用和記錄器觸發完全相同的量測
方式，所以閘門和記錄器不可能對「電漿有沒有亮」給出不同答案。

**Pedestal（連續背景基座）**：
一個讀數裡屬於連續背景、而不屬於譜線的那一部分——只有在受監看量什麼都不減時才會存在。帶著 pedestal 的量
不能用「佔基準值的百分之幾」來判斷，這就是為什麼它是唯一那個開關：一旦成立，門檻、顯示、斜率、洩漏率校正
全部改用 σ 為單位。

**Low signal（訊號過弱）**：
某一筆受監看項目的譜線太貼近雜訊、不值得相信的狀態。它會被排除在複合判定之外，而不是被當成正常回報——
讀不出來不等於通過。

**Latched（鎖存）**：
形容警報：引發它的條件已經消失，它仍然維持成立。只有人為的 acknowledge 能清掉，而且那次清除一定記得到
是哪個使用者做的。

**Sustained confirmation（持續確認）**：
狀態改變之前，門檻必須連續被突破達指定秒數的要求。這是把「漏氣」和「一根突波」分開的東西。

**Composite level（複合等級）**：
整台機器唯一那個 Normal／Warning／Alarm 判定，由各項目各自的狀態合成。讀不出來的項目不參與合成。

**Acknowledge（人工確認）**：
由具名人員結束一個鎖存警報的動作。它是唯一能清掉鎖存的東西，所以一個警報結束時若沒有這筆紀錄，代表它是
自己消失的——那是關於這台儀器的事實，不是關於腔體的。

**Dropout（掉幀）**：
plasma gate 短暫關閉、但前後兩側都是好幀：這是儀器故障，而且會被當成故障計數。電漿真的熄掉持續時間更長，
不算 dropout。

**Factory ratio set（出廠比值組）**：
工具內建的那組 ratio。這裡的「出廠」指的是**某一台機器用一次已知洩漏實測挑出來的結果**，不是教科書會建議
的組合——那些看起來理所當然的選擇有好幾個在那台機器上試過，根本不動。

**Acquisition fingerprint（取像指紋）**：
一次量測是在哪一組硬體設定下取得的。指紋不同的兩個讀數不能互相比較，不管數字看起來多接近。

## 洩漏率定量

**Leak rate（洩漏率）**：
估計出來的漏氣量，單位 mbar·L/s。只有在這台工具被餵過一個已知大小的洩漏之後才存在；沒有校正過的話，
它對「方向」有意見，對「大小」沒有。

**Calibrated leak（標準漏孔）**：
已知漏率的實體漏件，刻意接上去讓工具學會「它看到的變化」和「實際漏多少」之間的關係。氣體種類必須和要偵測
的洩漏一致。

**Calibration point（校正點）**：
一次觀測，把一個已知漏率、和各受監看項目在該漏率下的上升幅度配成一對。

**Sensitivity（靈敏度）**：
每一項各自的「每單位洩漏會讓我動多少」。把它倒過來算，就是把一次觀測還原成一個洩漏率。

## 譜線

**Continuum（連續背景）**：
譜線底下那片寬廣的背景，用譜線兩側各放一個視窗、內插估出來。三種萃取模式裡有兩種會把它減掉，第三種刻意
不減。
*避免使用*：單獨講「baseline／基準」——它同時指這個和 Golden Run baseline。一定要加限定詞：
continuum baseline（連續背景基線）或 Golden Run baseline（基準值）。

**SNR（訊噪比）**：
譜線高度相對於當地連續背景雜訊的比值，這裡是拿來當**閘門**用的，不是拿來當品質分數。完全不減連續背景的
讀數**沒有** SNR——是「未知」，而不是「很高」。

**Extraction mode（萃取模式）**：
在某個波長上要怎麼從光譜裡取出一個數字：峰高、積分面積，或什麼都不減的原始平均。不同模式取出的兩個讀數
單位不同，不能互比。

**Correction（波長修正）**：
加在圖庫譜線波長上的位移量，用來跟上波長軸漂移。它是**譜線的**屬性，所以修一次，用到這條線的每個地方
全部一起對正。

**User line（自訂譜線）**：
廠端自己的譜線，疊在固定的內建圖庫之上。它的物種名一定帶著標記前綴，所以任何標籤只要引用到它，一眼就看得
出不是內建的。

## 錄下來的資料

**Recording（錄檔）**：
一個已寫出的 CSV，被讀回來。它是**一個檔案**，不是一段過程：長時間存檔會產生好幾個 recording，讀回其中
一個不代表讀到了整段過程。

**Save session（存檔期間）**：
過程本身——記錄器從開檔到關檔的那一段，中間可能因為檔案輪替而跨越好幾個 recording。
*避免使用*：單獨講「run」。看誰在講，它可能指 Golden Run、指一次電漿製程、或指程式跑一次。請講明是哪一個。

**Archive（封存）**：
把某一天的 recording 就地壓成單一檔案。老資料只封存、**永不刪除**——保留多久是資料擁有者的決定，不是這個
工具的決定，而且封存過的日子仍然完整可讀。

**Trigger threshold（觸發門檻）**：
記錄器認定「有事情正在發生」而開始寫檔的強度門檻。同一個數字也決定 plasma gate 開不開，所以它從來不只是
一個記錄設定。

## 在量測，與不在量測

**Test mode（測試模式）**：
光譜是合成出來的、而不是量測到的狀態。沒有硬體時會刻意進入，硬體載入失敗時也會退化進入——正因為如此，
它是明講在畫面和日誌上的，不是靠推測的。

**Test-mode fallback（測試模式退化）**：
一次「成功」的連線，回報一切健康，但送出來的是合成光譜。這是這個工具最危險的狀態，因為它下游的一切看起來
都很正常。

**Replay（重播）**：
把先前錄下的光譜檔重新灌回即時流程，用來檢驗**偵測本身**而不是腔體。test mode 是這個字語意的一部分，
不是外掛上去的前提：實際量測到的幀永遠不會被取代，而重播寫出來的任何東西都會被標記，這樣它永遠不可能被
當成量測資料讀回。
*避免使用*：simulation。那是一個已移除的前身的名字（它會把錄檔重採樣到合成波長軸上），現在只以一個
設定鍵名的形式殘存，而該鍵指向的其實是重播檔。

## 和廠務主機對話

**Chamber code（腔體代碼）**：
標示這個執行個體代表哪一座腔體的兩位數字，會被蓋進主機看得到的每一個 id。未蓋章的那個值**不是**一座
腔體——它是「這份設定檔還沒被設定過」的標記。

**Stamping（蓋章）**：
啟動時把腔體代碼改寫進廠端設定檔的每個 id；若結果會佔用到另一種感測器類型的 id，則拒絕啟動。

**Effective profile（生效設定檔）**：
真正拿來回答主機的那份蓋章副本，和廠端可編輯的原始檔分開存放，這樣人在編輯的檔案永遠不會是主機被回答時
所依據的檔案。

## 改動何時生效

**Staged（暫存待生效）**：
形容設定：現在就改、現在就存，但要等下一次重新開始取像才生效。此刻正在跑的量測，是由它開始時的那組值
定義的。

**Hot-applied（即時生效）**：
形容設定：下一幀就生效。用在「若採暫存待生效，系統兩個部分會在這一整趟量測期間互相矛盾」的地方。
