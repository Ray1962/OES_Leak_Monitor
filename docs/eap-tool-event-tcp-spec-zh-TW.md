# OES Leak Monitor × EAP 製程事件通訊規格（TCP 文字行）

> **對象：** 廠內 EAP 平台廠商（開發與維運）。
> **目的：** 定義 EAP 把主機台 **PM3** 的製程事件轉送給 OES Leak Monitor 的通訊方式：連線、訊息格式、回應碼、心跳、斷線處理與驗收方式。
> **狀態：** 2026-10-26 修訂。OES 端已依本規格實作；第 10 節各項都已確認（C1、C2 的位址由現場輸入，C3、C4 已回覆）。有疑問或無法照做的地方請提出。
> **一句話：** OES 主動以 TCP 連到 EAP 的 `10.2.3.120:20347`，EAP 一行送一筆訊息：PM3 事件發生時送 `EVT`，另外每 30 秒送一筆 `HB` 心跳回報 PM3 目前狀態；OES 每收一行回一行。

## 1. 背景

OES Leak Monitor 裝在主機台 PM3 上，用電漿光譜偵測腔體漏氣。PM3 會交替執行不同製程（Chamber Process／precoat、Chamber Clean 等），每種製程的光譜完全不同。OES 必須知道**當下這一幀光譜屬於哪個製程**，才能用正確的基準判定。

主機台的製程事件已經送到 EAP，所以由 EAP 轉送給 OES。OES 原有的 SECS 連線是給 FDC 使用的，因此另外開一條專用的 TCP 連線：**由 OES 連到 EAP**，只用來接收 EAP 轉送的事件。

這條連線**只傳遞資訊，不做任何控制**：OES 不會透過它對 EAP 或主機台下任何命令。

## 2. 系統配置

```
┌──────────────┐  SECS（既有）  ┌──────────────────────┐
│   Tool PC    │──────────────▶│         EAP          │
│  (PM2／PM3)  │   EAP = host  │ 監聽 10.2.3.120:20347 │
└──────────────┘               └──────────▲───────────┘
                                          │ TCP 文字行（本規格）
                                          │ OES 主動連入
┌──────────────┐  SECS（既有）  ┌──────────┴───────────┐
│     FDC      │──────────────▶│        OES PC        │
│              │   FDC = host  │     （只看 PM3）      │
└──────────────┘               └──────────────────────┘
```

- FDC 與 OES 之間的 SECS 連線不受本規格影響。
- OES 目前依據的製程視窗會照舊由 OES 的 VID 030～032 提供給 FDC。

## 3. 連線

| 項目 | 規定 |
|---|---|
| 協定 | TCP |
| 連線方向 | **OES 主動連入，EAP 監聽** |
| EAP 的監聽位址 | 預設 **`10.2.3.120:20347`**（EAP 方提供）。**在 OES 的 SECS 分頁輸入**（`EAP address`／`Port`），存檔即生效，不必重開 App。EAP 位址變更（包括切換到備援機）時，由設備工程師在 OES 改，見第 10 節 |
| OES 的來源位址 | OES PC 的 IP，由現場決定，**輸入到 EAP 端的防火牆設定**（見第 10 節）；來源 port 由作業系統分配，**每次連線可能不同** |
| 同時連線數 | **1 條**。EAP 若在舊連線還在時又收到同一台 OES 的新連線（例如 OES 重啟、網路瞬斷後舊連線尚未釋放），請**以新連線取代舊連線** |
| 斷線重連 | **OES 每 10 秒**重試一次，直到連上為止 |
| 防火牆 | EAP 端允許 OES PC 的 IP 連入 20347（建議只允許這個 IP）。OES PC 只需要允許連出，通常不需另外設定 |

**為什麼新連線取代舊連線：** OES 重啟或網路中斷時，EAP 這端可能還留著一條看起來仍然連著、但實際已經斷掉的舊連線。如果 EAP 拒絕新連線，OES 會一直連不上。

## 4. 訊息格式

### 4.1 通則

| 項目 | 規定 |
|---|---|
| 編碼 | ASCII |
| 一行一筆 | 每筆訊息以換行結尾。OES 接受 `\n`（LF）與 `\r\n`（CRLF）；OES 送出的一律是 `\r\n` |
| 欄位分隔 | 半形逗號 `,`。欄位內不得出現逗號；欄位前後不得有空白 |
| 長度上限 | 每行最多 **256 字元**（不含換行） |
| 大小寫 | 訊息類型（`EVT`、`HB`）必須大寫 |
| 空白行 | 忽略，不回應 |

### 4.2 EAP → OES

**事件 `EVT`：PM3 的事件發生時送出**

```
EVT,<CEID>,<TIME>,<SEQ>
```

**心跳 `HB`：每 30 秒送出，以及每次接受 OES 連線後立即送一筆**

```
HB,<STATE>,<WINCEID>,<WINTIME>,<TOOLLINK>,<SEQ>
```

### 4.3 OES → EAP

**回應 `EVT`：**

```
ACK,<SEQ>,<CODE>
```

`<SEQ>` 與收到的 `EVT` 相同，`<CODE>` 見第 6 節。

**回應 `HB`：**

```
HBACK,<CODE>
```

**格式錯誤、無法讀出序號時：**

```
ERR,<CODE>
```

OES 對每一行非空白的訊息都會**剛好回一行**，而且依收到的順序回覆。OES 不會主動送出其他訊息。

## 5. 欄位定義

| 欄位 | 用在 | 格式 | 內容 |
|---|---|---|---|
| `CEID` | `EVT` | 十進位數字，1～10 位，範圍 0～4294967295 | 主機台的**原始 CEID**（例如 `3100439529`），不需轉換 |
| `TIME` | `EVT` | `YYYYMMDDhhmmsscc`（16 位）或 `YYYYMMDDhhmmss`（14 位），本地時間；**可以留空** | **EAP 收到**該主機台事件的時間（主機台的事件報告不帶時間戳，見 C3）。請一律填上、不要留空：留空時 OES 只能用自己收到的時間，會多算進轉送延遲 |
| `SEQ` | `EVT`、`HB` | 十進位數字，0～4294967295 | 事件序號。見 5.1 |
| `STATE` | `HB` | `0`、`1` 或 `2` | PM3 目前的視窗狀態：**0** = 不在任何製程視窗內、**1** = 在製程視窗內、**2** = 不明 |
| `WINCEID` | `HB` | 同 `CEID`；`STATE` 不是 1 時留空 | 開啟目前視窗的那筆 **Start 事件**的主機台 CEID |
| `WINTIME` | `HB` | 同 `TIME`；`STATE` 不是 1 時留空 | 目前視窗開始的時間（那筆 Start 事件的時間） |
| `TOOLLINK` | `HB` | `0` 或 `1` | EAP 與主機台的 SECS 通訊狀態：**0** = 未通訊、**1** = 通訊中 |

### 5.1 序號 `SEQ`

- EAP 每送出一筆**新的** `EVT`，序號加 1。EAP 啟動後的第一筆 `EVT` 為 `1`。
- **重送同一筆事件時使用相同的序號**（見 7.4）。
- `HB` 的 `SEQ` 填**最後一筆已送出的 `EVT` 序號**；啟動後還沒有送過任何 `EVT` 時填 `0`。OES 用它判斷有沒有漏收事件。
- 序號只在 EAP 重啟時歸零。重啟後的第一筆 `HB` 應為 `STATE = 2`（見 8.1 的 E4）。
- 超過 4294967295 時從 1 重新開始（實務上不會發生）。

### 5.2 `STATE` 的判斷

EAP 依自己收到的主機台事件維護 PM3 的狀態：

| 最近一筆 PM3 製程事件 | `STATE` | `WINCEID`／`WINTIME` |
|---|---|---|
| Start（尚未收到對應的 End） | `1` | 該 Start 的 CEID／時間 |
| End | `0` | 留空 |
| EAP 啟動後還沒收到任何 PM3 製程事件 | `2` | 留空 |
| EAP 與主機台斷線中（`TOOLLINK = 0`） | `2` | 留空 |
| 與主機台恢復通訊後，還沒收到新的 PM3 製程事件 | `2` | 留空。斷線期間可能錯過了 Start 或 End，斷線前的狀態已不可信 |

本規格所說的「PM3 製程事件」至少包括下表各組：

| 主機台 CEID（Start／End） | 事件 |
|---|---|
| 3100439529／3100439530 | PM3 ProcessStart／End（Chamber Process／precoat） |
| 3099591660／3099591661 | PM3 ProcessStart／End（Chamber Clean） |
| 3100167145／3100167146 | PM3 ProcessStart／End（Auto Leak check） |

## 6. 回應碼

| `CODE` | 意義 | 用在 | EAP 的處理 |
|---|---|---|---|
| `0` | 收下。包括 CEID 不在 OES 對照表內（OES 記錄後不處理）與重複的事件（見 7.4） | `ACK`、`HBACK` | 正常，繼續 |
| `1` | 不認得的訊息類型 | `ERR` | 檢查程式，不要重送 |
| `2` | OES 目前未啟用製程事件功能 | `ACK`、`HBACK` | 照常持續傳送，無害；請通知 OES 設備工程師 |
| `3` | 格式錯誤：欄位數量不對、欄位內容無法解讀、超過長度上限；或 `HB` 的 `WINCEID` 是一筆 End 事件 | `ACK`、`HBACK`、`ERR` | 修正格式或內容。**不要重送同一行**，OES 不會採用該行 |

OES 回 `ERR` 或代碼 `3` 時**不會**關閉連線。

## 7. 運作流程

### 7.1 連線建立後

1. OES 連入 EAP 的 `10.2.3.120:20347`。
2. EAP 接受連線後，**立即送一筆 `HB`**，回報 PM3 目前狀態。OES 用它補上連線中斷期間錯過的狀態。
3. 有尚未收到 `ACK` 的 `EVT` 時，接著重送（見 7.4）。
4. 之後進入 7.2 的平常運作。

### 7.2 平常運作

- 主機台每發生一筆事件，EAP **在 1 秒內**送出對應的 `EVT`。
- 每 **30 秒**送一筆 `HB`。
- **一次只能有一筆在等回應：** 送出一行後，等收到 OES 的回應，再送下一行。PM3 事件間隔以分鐘計，不會因此塞車。
- 沒有 OES 連線時，EAP 不需要保存心跳；尚未送出的 `EVT` 請依 7.4 保留到 OES 連上後重送（只需保留最後一筆未確認的）。

### 7.3 逾時

| 情況 | 處理 |
|---|---|
| EAP 送出一行後 **10 秒**內沒有收到回應 | EAP 關閉這條連線，等 OES 重新連入後重送那一筆 |
| OES **75 秒**內沒有收到任何一行（約等於連續漏掉 2 筆 `HB`） | OES 關閉連線、把製程視窗改為「不明」，並依第 3 節重連 |

### 7.4 重送與重複

- EAP 送出 `EVT` 後，沒收到 `ACK` 就斷線時，**OES 重連後以相同的 `SEQ` 重送**。
- OES 依序號判斷：

| 收到的 `SEQ` 與 OES 最後收下的序號相比 | OES 的判斷 | 處理 |
|---|---|---|
| 相同 | 重送 | 回 `ACK,<SEQ>,0`，**不重複處理** |
| 大 1 | 正常 | 處理 |
| 大 2 以上 | 中間有事件沒收到 | 處理，並記錄警告；之後的 `HB` 會補正視窗狀態 |
| 較小 | EAP 已重啟、序號重新開始 | 處理，並記錄 |

### 7.5 對話範例

OES 在 PM3 閒置時連上，接著跑一次 Chamber Process：

```
（OES 連入 10.2.3.120:20347）
EAP → OES   HB,0,,,1,127
OES → EAP   HBACK,0
                                             （14:01:40 PM3 ProcessStart）
EAP → OES   EVT,3100439529,2026102614014000,128
OES → EAP   ACK,128,0
EAP → OES   HB,1,3100439529,2026102614014000,1,128
OES → EAP   HBACK,0
                                             （14:02:43 PM3 ProcessEnd）
EAP → OES   EVT,3100439530,2026102614024300,129
OES → EAP   ACK,129,0
EAP → OES   HB,0,,,1,129
OES → EAP   HBACK,0
```

不在 OES 對照表內的事件（例如 slit door），照樣送、照樣收：

```
EAP → OES   EVT,2697019492,2026102614030512,130
OES → EAP   ACK,130,0
```

EAP 與主機台斷線：

```
EAP → OES   HB,2,,,0,130
OES → EAP   HBACK,0
```

格式錯誤：

```
EAP → OES   EVT,31004395X9,2026102614014000,131
OES → EAP   ACK,131,3
EAP → OES   HELLO
OES → EAP   ERR,1
```

## 8. EAP 端的行為要求

### 8.1 必須遵守

| # | 要求 | 原因 |
|---|---|---|
| E1 | **主機台事件發生後 1 秒內送出 `EVT`** | OES 每一幀光譜（約每 0.6～2 秒一幀）都要依視窗判定製程，短的製程步驟只有約 60 秒 |
| E2 | **事件依發生順序送出** | Start 和 End 順序錯了，視窗就是錯的 |
| E3 | **`HB` 的內容要反映已送出的 `EVT`**：送出 Start 的 `EVT` 之後，下一筆 `HB` 的 `STATE` 必須是 1 | OES 以 `HB` 修正自己的狀態，兩者矛盾時 OES 會被來回修改 |
| E4 | **EAP 不知道 PM3 狀態時，`STATE` 填 2**：EAP 剛啟動、尚未收到任何 PM3 製程事件，或與主機台斷線、恢復後尚未收到新事件時 | 不知道時填 0，OES 會以為 PM3 閒置，這是錯的 |
| E5 | 與主機台斷線時，**下一筆 `HB` 立即送出**（不必等 30 秒），`TOOLLINK = 0`、`STATE = 2` | 讓 OES 盡快改用不依賴製程事件的判定方式 |
| E6 | 重送時使用相同的 `SEQ` | 見 7.4 |
| E7 | `TIME`、`WINTIME` 填 **EAP 收到主機台事件的時間**，不是送給 OES 的時間（主機台不帶時間戳，見 C3） | EAP 轉送或重送有延遲時，OES 的紀錄仍能對到 EAP 實際收到事件的時刻，與主機台只差 SECS 的傳遞時間 |
| E8 | EAP 與 OES PC 都要接 NTP 對時 | 雙方的時間戳要能直接比對 |
| E9 | **接受 OES 連線後立即送一筆 `HB`** | OES 重啟或重連後，靠這一筆立即恢復正確的製程視窗 |

### 8.2 可以這樣做

- **主機台的事件可以不篩選、全部轉送。** OES 不認得的 CEID 會記錄後忽略，EAP 不需要另外維護過濾清單。
- PM2 的事件也可以一起送，OES 一樣會忽略。
- Start 之後又收到 Start（中間沒有 End），或收到沒有對應 Start 的 End：照實轉送即可，由 OES 處理並記錄警告。

## 9. OES 端的行為（供參考）

EAP 方不需要實作本節，但了解它有助於判讀雙方的日誌。

- **CEID 怎麼變成製程：** OES 用自己的對照表把主機台 CEID 換算成製程類別（例如 3100439529 → 製程 A），Start 到 End 之間的光譜都依該製程的基準判定。對照表只存在 OES，EAP 只要轉送原始 CEID。
- **心跳和 OES 的狀態不一致時，以心跳為準**，每次修正都記錄一筆警告（這就是「EAP 漏送事件」的紀錄）。`STATE = 1` 時，OES 依 `WINCEID` 在對照表裡的意義決定視窗：

| `WINCEID` 在 OES 對照表裡是 | OES 的視窗 |
|---|---|
| 有製程類別的 Start（例如 3100439529 → 製程 A） | 該製程的視窗 |
| 只記錄、不分類的 Start（例如 Auto Leak check） | 不在任何視窗內 |
| 對照表沒有這個 CEID | 不在任何視窗內 |
| End 事件 | 內容矛盾：回 `HBACK,3`，視窗不變 |

- **資料不可信時，OES 不會停止偵測：** 以下情況 OES 把製程視窗改為「不明」，改用光譜本身判斷，等狀態恢復再切回來：
  - `HB` 回報 `STATE = 2` 或 `TOOLLINK = 0`；
  - **75 秒內沒有收到任何一行**。
- **連線斷掉本身不改變視窗。** OES 每 10 秒重連，連上後 EAP 立即送 `HB`（E9）；只要 75 秒內恢復，視窗就一直維持正確。
- **OES 不會因為這條連線斷掉而發出漏氣警報。** 連線狀態顯示在 OES 的畫面上，並寫入 OES 的系統日誌。
- **紀錄：** 這條連線收發的每一行，OES 都會記錄在通訊日誌中，包含時間與方向；連線、斷線、重連失敗也會記錄。

## 11. 驗收方式

OES 方會提供一支測試程式 `eap-link-sim.ps1`（Windows PowerShell，不需安裝）。以 `-Mode Oes` 執行時，它**假扮 OES** 連到 EAP，對每一行回正確的 `ACK`／`HBACK` 並印出收到的內容，供 EAP 在正式連線前自行測試。正式驗收依下表進行：

| # | 操作 | 預期結果 |
|---|---|---|
| 1 | OES 啟用連線 | OES 連上 `10.2.3.120:20347`；EAP 立即送 `HB`，收到 `HBACK,0`；OES 畫面顯示「已連線」 |
| 2 | EAP 停止監聽 30 秒後恢復 | OES 每 10 秒重試；EAP 恢復後 OES 自動連上，EAP 立即送 `HB` |
| 3 | PM3 閒置時觀察 `HB` | 每 30 秒一筆，`STATE = 0`、`TOOLLINK = 1` |
| 4 | 主機台跑一次 PM3 Chamber Process | Start／End 各一筆 `EVT`，發生後 1 秒內送出，各收到 `ACK,<SEQ>,0`；期間 `HB` 的 `STATE = 1`、`WINCEID = 3100439529`；OES 畫面顯示製程 A 視窗 |
| 5 | 主機台跑一次 PM3 Chamber Clean | 同上，`WINCEID = 3099591660`，OES 顯示製程 B 視窗 |
| 6 | 轉送一筆不在 OES 對照表內的 CEID（例如 slit door） | `ACK,<SEQ>,0`；OES 視窗不變 |
| 7 | 送一筆格式錯誤的 `EVT` | `ACK,<SEQ>,3`；連線不斷 |
| 8 | PM3 製程進行中，重啟 OES | OES 重新連上，EAP 立即送 `HB`；OES 不必等下一筆事件，就恢復到正確的製程視窗 |
| 9 | PM3 製程進行中，拔掉 OES 的網路線 90 秒後接回 | OES 在 75 秒時改為「不明」；接回後 OES 重連、EAP 送 `HB`，OES 恢復正確視窗 |
| 10 | 在 EAP 送出 `EVT` 後、收到 `ACK` 前中斷連線（可用測試程式模擬） | OES 重連後 EAP 以相同 `SEQ` 重送；OES 只處理一次 |
| 11 | 中斷 EAP 與主機台的連線 | EAP 立即送 `HB,2,,,0,<SEQ>`；OES 改為「不明」 |
| 12 | 恢復 EAP 與主機台的連線 | `TOOLLINK = 1`；`STATE` 在下一筆 PM3 製程事件後恢復正確值 |
| 13 | 重啟 EAP | OES 在 10 秒內重新連上；第一筆 `HB` 為 `STATE = 2`、`SEQ = 0`；第一筆 `EVT` 的 `SEQ = 1`，OES 正常接受 |
